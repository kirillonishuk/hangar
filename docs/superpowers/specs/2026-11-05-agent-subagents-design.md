# Субагенты агента — спека

Статус: задача владельца от 2026-11-05 (по мотивам сайдбара Orca: субагенты сессии Claude — вложенные строки со статусом); решение #133. Видно, что делает агент-оркестратор — его субагенты Claude (инструмент Agent/Task), — и можно заглянуть в любой, без расхода энергии, пока не смотришь.

## 1. Что это
Под строкой чата в сайдбаре — свёрнутая строка «3 субагента · 1 работает»; развёрнутая — по строке на субагента: точка статуса, его задача («Implement Task 2.2»), время. Клик по субагенту открывает лист только для чтения: задание оркестратора, ход работы (сообщения и вызовы инструментов, обновляются вживую), итог.

Слова: «субагент» / "subagent" (как в статусе чата «работает · 2 субагента»); в коде `Subagent`, `SubagentList`.

## 2. Источники (только документированные, #14)
Хуки Claude Code (https://code.claude.com/docs/en/hooks, прочитано 2026-11-05, Claude Code 2.1.318):
- `PreToolUse` с matcher `Task|Agent` (уже был, `subagent-start`): `tool_use_id`, `tool_input.description`, `subagent_type`, `prompt` → строка рождается.
- `SubagentStart` (**новый**, `hangar event subagent-run`): `agent_id`, `agent_type` — у строки появляется id субагента, а значит и его журнал. Описания и промпта в нём нет.
- `PostToolUse` `*` (уже был, `tool`): для инструмента Agent/Task — `tool_use_id`, `tool_response.agentId`, `tool_response.status` (`completed` — закончил; `async_launched` — фоновый, работает дальше).
- `SubagentStop` (уже был, `subagent-stop`): `agent_id`, `last_assistant_message`; `agent_transcript_path` не берётся — путь считается сам (§5).
- `UserPromptSubmit`, `Stop`/`StopFailure`, `SessionStart` — границы хода.

Новый хук добавляется существующим путём #95 R1 / #111: только недостающие записи Hangar, пользовательские не трогаются, резервная копия, идемпотентно; согласие уже дано включённой интеграцией. Без него (до обновления файла) всё работает, кроме журнала ещё работающего переднего субагента: id приходит только с его концом.

Поля проверяются на границе доверия дважды — в `hangar event` и при разборе строки сокета: id — `[A-Za-z0-9_-]{1,128}` (из них строится имя файла), тип ≤ 64 символов без управляющих, описание — первая строка ≤ 200, промпт и итог ≤ 2000. Поля субагентов есть только у Agent/Task: прочие `PostToolUse` идут как раньше и списков не трогают.

## 3. Состояние (`AgentStatus/Subagents.swift`, только в памяти)
`SubagentList` на лист агента; события без своих часов (время приносит событие):
- **launch** (PreToolUse) — строка `running`, ключ `tool_use_id`, тип по умолчанию `general-purpose`, название — описание или тип.
- **started** (SubagentStart) — id к первой работающей строке без id того же типа (иначе любой). *shortcut:* параллельные запуски одного типа сопоставляются по порядку прихода; ответ инструмента (`returned`) исправляет ошибку обменом id. Повторный SubagentStart того же id (resume) — снова `running`.
- **returned** (PostToolUse Agent) — id из ответа; `async_launched` → фоновый, иначе `done`.
- **stopped** (SubagentStop) — `done` + итог; id без строки запоминается (до 16): передний субагент останавливается раньше, чем отвечает инструмент; внутренние агенты Claude (подсказки, `/btw`) так и не находят строки.
- **turnEnd** (Stop/StopFailure) — работающий нефоновый не вернулся: `failed` («прерван»).
- **turnStart** (UserPromptSubmit) — уходят законченные до конца прошлого хода; законченные после (фоновый субагент разбудил Claude) остаются на этот ход. Работающие не трогаются.
- **exited** (выход агента) — работающие → `failed`; **reset** (SessionStart startup/clear/resume, перезапуск вкладки) — пусто. compact не сбрасывает.
- Не больше 30 строк: первыми уходят самые старые законченные.

Счётчик субагентов в статусе чата (`activeSubagents`, «работает · 2 субагента») остаётся как был.

## 4. Сайдбар (`SidebarSubagents.swift`)
- Под строкой чата (проект, «Чаты», подчат — на уровне его отступа + `subChatIndent`): строка 28 — треугольник 12 `text3` в колонке точки, «N субагентов · K работает» (`secondary`, `text2`). Клик сворачивает/разворачивает; по умолчанию свёрнуто; раскрытие не сохраняется (в памяти).
- Развёрнуто — строки 28: `StatusDot` (работает — `working`, готово — `done`, прерван — `failed`), название `text1` с обрезкой, в конце время `caption` `text3`: у работающего — сколько идёт, у законченного — сколько шёл; «<1 мин», «N мин», «N ч M мин». Тултип и VoiceOver — «название · тип · состояние · время».
- Время пересчитывается только при перерисовке (как «2 мин» у чатов без проекта) — таймера нет, поэтому секунд не показываем.
- В рейке ничего; фильтр «только ждущие» строки чатов не меняет. Перетаскивание учитывает высоту строк субагентов.
- Строк нет, пока у чата нет субагентов текущего прогона.

## 5. Просмотр (`SubagentViewer.swift`)
- Лист 520 (`SheetKit`), высота — до высоты окна: заголовок — название + тип; строка состояния (точка, слово, время); «Задание» — первое сообщение журнала (иначе промпт из хука); шаги: текст агента `body`, вызов — имя инструмента `mono` 600 + суть ввода (описание / команда / путь / шаблон) в одну строку, результат — `monoSmall` `text3` до 3 строк (ошибка — `failedText`); «Итог» — сообщение `SubagentHandback`, иначе `last_assistant_message` законченного. Выделение текста включено. «Закрыть» (↩ / Esc).
- Журнал: `<config>/projects/<папка cwd>/<session>/subagents/agent-<id>.jsonl` (сначала папка, которую claude называет по cwd листа, потом любая — id уникальны, как `transcriptChoice`); session — id разговора листа. Формат проверен на файлах Claude Code 2.1.314 (только чтение): строки `user`/`assistant`, `isMeta`, вложения, thinking и служебные записи пропускаются.
- **Энергия:** журнал читается при открытии, затем FSEvents (`FileWatcher`, папка журнала, задержка 0,3 с) — только события этого файла, дочитываются только дописанные полные строки (`TranscriptReader`, ≤ 8 МБ за раз, ≤ 4000 символов на шаг, ≤ 2000 шагов). Закрытие листа останавливает поток FSEvents; пока лист закрыт, не работает ничего. Строка получила id или закончилась при открытом листе → поиск журнала ещё раз (событие, не опрос).

## 6. Где работает
- Чаты проекта, чаты без проекта, подчаты — у любой вкладки claude (и в нижнем терминале).
- **Удалённые (ssh)** — строки из хуков есть (через `hangar-remote`, разбор на Mac), журнала нет: в листе задание и итог из хуков и строка «Ход работы виден только у чатов на этом Mac.» *shortcut:* `hangar-remote` версии 6 не знает `subagent-run` и отбрасывает его — строки сопоставляются по ответу инструмента; добавить при следующем изменении `hangar-remote`. Чтение журнала по ssh по запросу — не делаем, пока не попросят.
- **Codex** — пропускаем: у него нет хуков субагентов.
- CLI/MCP (`tabs subagents`) — не делаем: не просили.
