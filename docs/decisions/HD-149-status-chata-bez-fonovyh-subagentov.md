# HD-149 — 2026-11-06 — Статус чата — состояние главного агента; в сайдбаре только работающие субагенты (слово владельца по скриншоту; спека `2026-11-05-agent-subagents-design.md` §2–§5; DESIGN.md «Субагенты чата»; меняет HD-136 и HD-139 в части списка и закрытия вида)

Владелец: агент закончил ход и стоит на пустом приглашении, фоновый субагент (`run_in_background`) ещё работает, а чат показан «работает», и в развёрнутом списке рядом с работающим висит законченный «Write PLAN.md… 20 мин» — «агента нет в работе, а он висит, итерация уже новая».

**Причина статуса.** Claude Code присылает `Stop`, когда ход главного агента кончился, даже если фоновый субагент работает (поэтому у `Stop` есть `background_tasks`). Но хуки инструментов субагента (`PreToolUse`/`PostToolUse`) идут те же, с тем же `session_id`, только с полем `agent_id` (документация хуков: «When a subagent calls a tool … the input carries the `agent_id` and `agent_type`»). Hangar читал любой `PostToolUse` как «работает» — первый же инструмент фонового субагента после `Stop` переводил чат из «готово» в «работает».

**Решение.**
1. Статус чата — состояние его главного агента. `hangar event` помечает событие `inSubagent`, если в нём есть `agent_id` (кроме `SubagentStart`/`SubagentStop`, где это id самого субагента; id проверяется как прежде). `LeafStatus.inTurn` — ход главного агента идёт (от промпта или его инструмента до `Stop`/`StopFailure`, выхода, перезапуска, `SessionStart`). Инструмент или запуск субагента от субагента вне хода состояние не меняет: «готово» остаётся «готово», непросмотренным и с записью «готово» во входящих. Его запрос разрешения по-прежнему «ждёт»; после ответа (следующий его инструмент) чат снова «готово», не «работает». Внутри хода всё как было. Работающие видны своими строками.
2. В сайдбаре — только работающие субагенты: законченный (готово, ошибка, прерван) уходит из списка сразу. Свёрнутая строка — «N субагент работает / субагента работают / субагентов работают» (en "N subagent(s) running"); никто не работает — ни строки, ни счётчика. Открытый вид «Субагент» законченного не закрывается: показывает последнее состояние, пока его не закроют («×», Esc, ⌥⌘1/2/3, другой чат); список в памяти хранит законченные по прежним правилам (до хода после следующего `Stop`, сброс).
3. Время у строки — только «сколько идёт» (у законченных строк нет).

**Отвергнуто:** строка «Законченные · N» в конце списка (владелец: убирать сразу); «работает», пока жив фоновый субагент (статус чата — про то, ждёт ли агент пользователя); различать по `background_tasks` у `Stop` (инструменты субагента приходят и после, нужен признак у каждого события); закрывать вид, когда строка ушла (выдёргивает из-под пользователя).

**Дополнение (тот же день, живой баг владельца):** сайдбар держал «2 субагента работают», а Claude Code показывал один фоновый: второй прерван (его журнал кончается «[Request interrupted by user]»), `SubagentStop` не пришёл, строка «работала» 1 ч 11 мин. Строка теперь уходит не только по `SubagentStop`, но и по сверке с источниками, которым можно верить:
1. `Stop` несёт `background_tasks` (справочник хуков, «Stop input»: `id`, `type` — `subagent`/`shell`/…, `status`, `description`; у субагента `id` — его `agent_id`, сверено по журналам 2.1.318). Работающий фоновый, чьего id нет среди идущих записей, — «прерван». Нет списка или больше 99 идущих — фоновые не трогаются. Поздний `SubagentStop` такой строки делает её «готово» (хуки идут разными процессами, порядок `Stop`/`SubagentStop` не гарантирован).
2. `UserPromptSubmit` — работающий передний «прерван» (после Esc `Stop` нет; ввод во время хода Claude выполняет после хода, HD-062 — *shortcut*). Фоновые ждут следующего `Stop`. `SessionStart` startup/clear/resume и выход агента — как было (сброс / «прерван»).
3. Журнал открытого вида «Субагент» (он и так читается, HD-139) кончается «[Request interrupted by user…]» — «прерван». Нового чтения и опроса нет: закрытый вид журнал не читает.
Удалённые чаты: п. 1–2 так же (payload разбирается на Mac), п. 3 — нет (журнала нет).
**Отвергнуто:** опрашивать журналы всех субагентов (энергия); таймаут «давно молчит» (фоновый субагент легитимно работает часами).
