# Действия проекта — спека

Статус: решение владельца от 2026-11-05 (функция одобрена; в тот же день — требования владельца: полное редактирование, рабочая папка, подсказки из репозитория), запись #133. Обязательны: дизайн-система (`specs/2026-10-30-design-system.md`, #112), словарь (#113), CLI/MCP (#45, #73), порт чата `HANGAR_PORT` (#60), вкладка подготовки копии (#58, #127).

Идея взята у конкурентов (Codex Local environments — кнопки действий; Conductor — `scripts.run` и режим `nonconcurrent`, который гасит прошлый запуск; Superset — `run` в конфиге репозитория; cmux — свои команды в палитре): «запустить dev-сервер в этой копии» — самое частое действие после создания чата.

## 1. Что это
**Действие** — именованная команда проекта («Dev server» → `pnpm dev`, «Test», «Lint»), которая запускается одной кнопкой в папке текущего чата (основная папка проекта или его копия) в своей вкладке.

## 2. Где задаются
- **Настройки проекта → «Действия»** (на этом Mac), полностью редактируемые: строки «Название · Команда (mono) · Папка (mono, плейсхолдер «папка чата») · флажок «Перезапускать» · ⋯» (⋯ — «Выше», «Ниже», «Удалить действие»), внизу «+ Добавить действие». Флажок по умолчанию включён (тултип объясняет). Пустые строки отбрасываются; строка без имени или команды, повтор имени, папка вне проекта — ошибка под карточкой, ничего не сохраняется. Хранится в `state.json` у проекта: `actions` (`[{name, command, restart, folder}]`), порядок — порядок списка.
- **Рабочая папка** действия — необязательный путь относительно папки чата (`apps/cms` в монорепозитории): команда идёт в `<папка чата>/<папка>`, у копии — в её же подпапке. Абсолютный путь, `..`, `~` — отказ при сохранении. Перед каждым запуском папка проверяется в checkout этого чата (`test -d` по ssh у удалённого); нет — лист «Не удалось запустить «X»» с путём и подсказкой, у CLI/MCP — `not-found`.
- **Скрыть** действие, которое пользователь не задавал (из файла репозитория): ⋯ → «Скрыть» — строка остаётся в настройках приглушённой с подписью «скрыто» (⋯ → «Показать»), из меню, палитры, ⌘R и `actions_list` уходит; файл не меняется. Хранится в `hiddenActions` проекта (по имени). ⋯ → «Изменить как своё» копирует его в свои (своё с тем же именем перекрывает файловое).
- **Подсказки из репозитория** — только в «+ Добавить действие», никогда не добавляются сами. Клик запускает поиск (только сейчас, без фона; кнопка с индикатором), затем меню с полем поиска: «Пустое действие», группы «Корень» и пакеты («apps/cms»), пункт — «cms: dev» с командой справа; клик добавляет обычное редактируемое действие (имя «cms: dev», команда `<pm> run dev`, папка `apps/cms`). Уже добавленное (та же команда в той же папке) не предлагается. Откуда: `scripts` в `package.json` корня и пакетов workspace (`packages:` в `pnpm-workspace.yaml`, иначе `workspaces` в `package.json`, только безопасные относительные глобы), без служебных `preinstall`/`prepare` и т. п.; менеджер — поле `packageManager`, иначе lock-файл (pnpm / yarn / bun / npm); `Makefile` — цели, `justfile` — рецепты (корень). Чтение — два запуска `sh` в папке проекта (у удалённого — по ssh), каждый файл до 64 КБ, пакетов до 200. Ничего не нашлось — строка «В package.json, Makefile и justfile команд не нашлось».
- **Файл `.hangar/actions.json` в репозитории** (можно закоммитить для команды):
  ```json
  {"actions": [{"name": "Dev server", "command": "pnpm dev"}, {"name": "Test", "command": "pnpm test", "restart": false}]}
  ```
  `restart` (по умолчанию `true`) и `folder` (как выше) необязательны. Читается из папки чата (у копии — свой файл) при выборе чата, при открытии меню запуска, перед каждым запуском и из CLI/MCP; у удалённого проекта — `cat` через ssh-мастер. Файла нет — действий из репозитория нет. Битый JSON, не тот формат, запись без имени/команды, повтор имени, файл > 64 КБ — сообщение (`failedText`) под карточкой в настройках и `error` в `actions_list`; приложение не падает, годные записи работают.
- В настройках действия из файла показаны после своих, только для чтения: название, команда (`text2`), подпись «из репозитория» (`text3`; тултип — откуда и что Hangar спросит).
- Слияние: сначала свои, потом из файла; действие файла с тем же именем, что своё, скрыто (настройка этого Mac важнее).

## 3. Подтверждение команд из репозитория
Файл может прийти с `git pull` и содержать любую команду. Поэтому действие из файла перед **первым** запуском и после **изменения текста команды** показывает лист «Запустить «X» из репозитория?» с самой командой и кнопками «Отмена» / «Запустить» (не деструктивная, ⌘↩). Одобрение — SHA-256 текста команды в `approvedActions` проекта (`state.json`); переименование действия без смены команды не спрашивает. Свои действия не спрашивают. CLI/MCP команду, не одобренную в приложении, **не запускают** (ошибка «не одобрено: запустите один раз в Hangar») — агент мог сам написать файл.

## 4. Как запускаются
- **Кнопка в тулбаре** справа от кнопки ветки, только если у проекта чата есть действия (пусто — кнопки нет, §3.19): одна рамка `control.regular` `line2`, две части через `line2`: «▶ <действие>» (`secondary` `text1`, имя до 160, обрезка в конце) — запускает последнее запущенное в проекте (иначе первое), тултип «Запустить «X» — ⌘R»; шеврон 12 — меню. У каждой части своё наведение `hover`.
- **Меню** (общий `PopoverMenu`): действия (иконка ▶; справа «работает» у запущенного, «из репозитория» у файловых, ⌘R у главного; тултип — команда), затем для каждого работающего «■ Остановить «X»», затем «Настроить действия…» (лист настроек проекта).
- **Контекстное меню чата** («⋯» и правый клик): те же пункты действий первой группой (без «Настроить…»).
- **Палитра** (⇧⌘P): «Запустить: Dev server» для действий выбранного чата.
- **⌘R** (keyCode 15, свободна в Hangar и в Ghostty): главное действие выбранного чата. Нет действий — ничего.

## 5. Где выполняется
- Своя вкладка shell (`Leaf.action` = имя, `kind = shell`) в папке чата (или в рабочей папке действия под ней), с тем же окружением, что у остальных вкладок (`HANGAR_PORT`, `HANGAR_TAB_ID`, `HANGAR_LEAF_ID`, `HANGAR_SOCKET`), запуск через тот же путь, что вкладка подготовки копии: `<shell> -l -i -c '<shell> -i -c <команда>'` + OSC 133 с кодом. Удалённый проект — тот же путь удалённых вкладок (ssh + tmux на сервере, #47).
- Имя вкладки — имя действия (заголовок терминала его не перебивает; пользователь может переименовать), иконка ▶ вместо иконки shell.
- Запуск из приложения делает вкладку активной; из CLI/MCP — видимая вкладка не меняется (как `tabs_open`).
- **Повторный запуск:** «Перезапускать» вкл. — та же вкладка: если процесс работает, ⌃C (SIGINT всей задаче переднего плана через терминал); как только он завершился — новый терминал в том же месте вкладки (новый лист, тот же заголовок); не завершился за 3 с — старый терминал закрывается (SIGHUP; на сервере tmux-сессия убивается), и новый стартует. Уже завершившееся — новый терминал сразу. «Перезапускать» выкл. — каждый запуск в новой вкладке.
- **Состояние вкладки:** работает — обычная вкладка без точки (долгий dev-сервер не «работает» как агент: не держит Mac бодрым и не красит чат). Завершилось — вкладка **остаётся** (в отличие от shell-вкладок, #127) с полосой внизу: «Завершено · Enter — запустить снова», «Остановлено · …» (⌃C, SIGHUP, SIGTERM: коды 130, 129, 143, без кода), «Процесс завершён с кодом N · …» — последнее как у прочих упавших вкладок: точка `failed` на вкладке и «ошибка» у чата. Enter (или клик по полосе) — запуск снова **в этой вкладке** (через ту же проверку одобрения, команда берётся из настроек заново).
- **Остановить** (меню): ⌃C; через 3 с ещё работает — терминал закрывается, вкладка остаётся с полосой «Не запущено · Enter — запустить снова». Остановка Hangar не считается ошибкой.
- **Перезапуск приложения:** вкладки действий восстанавливаются, как обычные, но **сами не запускаются**: полоса «Не запущено · Enter — запустить снова». Удалённая вкладка подключается к своей tmux-сессии, если та жива (процесс на сервере пережил выход Hangar; это не новый запуск).

## 6. CLI и MCP
- `hangar actions list [--session S] [--json]` / MCP `actions_list` (только чтение, есть в `--read-only`): действия чата — `name`, `command`, `source` (`settings` | `repo`), `restart`, `approved`, `runningTab`; плюс `error` файла.
- `hangar actions run --name N [--session S] [--json]` / MCP `actions_run`: тот же запуск, что кнопка (перезапуск или новая вкладка); ответ — вкладка и `restarted`. Не разрушительно, `yes` не нужен.
- Сессия по умолчанию — вызывающий чат (`HANGAR_LEAF_ID`, как у `sessions_spawn`); вне терминала Hangar её надо назвать. Чат без проекта — ошибка «нет действий».
