# HD-114 — 2026-10-30 — Переключение и создание ветки — исключение из §1 «Вне рамок» (слово владельца; этап 8 дизайн-системы, спека `specs/2026-10-30-design-system.md` §3.2; дополняет HD-112).

Разрешены ровно две git-операции, меняющие рабочую папку чата: `git switch <ветка>` (удалённая `origin/x` → её локальная ветка, если есть, иначе `git switch --track`, новая локальная с upstream) и `git switch -c <имя> [<от>]` (`--no-track`, как ветки worktree). Остальное (stage, commit, push, stash, merge, reset, удаление веток вне архива) по-прежнему вне рамок. Правила безопасности (модуль `Git`, `Git+Switch.swift`; локально и по ssh через тот же `Runner`): (1) любой вывод `git status --porcelain --untracked-files=all --ignore-submodules=none` (неотслеживаемые и грязные подмодули — вопреки `status.showUntrackedFiles` и `submodule.*.ignore` репозитория) → переключение отклоняется до запуска git: «Есть незакоммиченные изменения (N файлов). Переключиться можно после коммита или stash.»; (2) исключение — новая ветка от текущего HEAD: рабочая папка не меняется, изменения уходят с ней (как в спеке §3.2); новая ветка от другой точки с изменениями — отказ, как у переключения; (3) ветка, открытая в другом worktree (`git worktree list --porcelain`), — отказ с понятным текстом: имя чата, у которого она открыта, иначе путь; (3a) игнорируемый файл на диске, который цель хранит (`ls-files --full-name -o -i --exclude-standard --directory -- :(top)` против `ls-tree -r --full-tree` цели — весь репозиторий, и для проекта в подпапке; в игнорируемой папке — только существующие файлы), git заменил бы молча (`.env` с секретом) — отказ с именами файлов; (3b) незаконченные merge / rebase / am / cherry-pick / revert / bisect (файлы состояния в git-dir, один вызов `sh`) — отказ с понятным текстом, а не сырая ошибка git; (4) имя новой ветки — `git check-ref-format --branch`, причём вывод обязан совпасть с именем (`@{-1}` git разворачивает в прошлую ветку — это не имя; так же теперь и в листе «Новый чат»); существующая — отказ; (5) аргументы — argv, ветка после `--` (имя с «-» в начале — не опция); переключение на текущую ветку — ничего не делает; ошибки git — его текст. Сохранённая ветка worktree-чата (`TaskMode.worktree.branch`) не меняется: это «своя» ветка чата для архива и восстановления (HD-057), удаляется в архиве только `branch -d`. **Текущая ветка каждого чата — живой HEAD его папки** (`Git.head()`: ветка, в том числе ещё без коммитов, или короткий хеш при detached), модель `BranchModel` + `AppState.head(of:)` / `requestHead` / `branchChoices` / `switchBranch` / `createBranch`: загрузка при первом показе, обновление без опроса — при загрузке статуса инспектора, по событиям FSEvents выбранного локального чата (поток инспектора, когда он открыт для этого чата; иначе поток только на файл `HEAD`, пока окно видно), при `done` агента, при подключении хоста и после своего переключения; возврат окна в фокус — только выбранный и видимые в сайдбаре чаты (удалённые — при подключённом хосте), не чаще раза в 5 с; один вызов git на папку (хост + путь), общий для её чатов.
