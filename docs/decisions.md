# Журнал решений

Формат: дата — решение. **Почему.** **Отвергнуто.** Решённое не переоткрывается без новой информации; новое решение — новая запись (старую пометить «заменено #N»).

1. **2026-10-18 — Только нативный Swift для macOS (AppKit + SwiftUI), macOS 14+, Apple Silicon.** Почему: энергопотребление и простота против Electron-Pane. Отвергнуто: Electron (как Pane), кроссплатформенность.
2. **2026-10-18 — Терминал — полный embed GhosttyKit (xcframework, собранный из закреплённого коммита).** Почему: рендер и поведение как в Ghostty без своей реализации. Отвергнуто: libghostty-vt + свой рендер (много работы), управление Ghostty.app снаружи (нет контроля над вкладками и статусами).
3. **2026-10-18 — Редактор — Helix (опц. Neovim) во вкладке терминала.** Почему: LSP и правка есть готовые. Отвергнуто: свой редактор (вне рамок), внешний редактор (уход из окна).
4. **2026-10-18 — Структура проект → задача → вкладки; worktree у задачи опционален.** Почему: так пользователь работает. Отвергнуто: обязательный worktree на задачу (как в Pane).
5. **2026-10-18 — Базовая ветка по умолчанию из `origin/HEAD`, пикер с поиском (remote, затем local), последний выбор запоминается; `git fetch` перед созданием worktree.** Почему: worktree от свежей удалённой ветки. Отвергнуто: от текущей локальной ветки без fetch.
6. **2026-10-18 — Git-панель только для просмотра (Files, Changes, diff).** Почему: git-действия делаются в терминале/агентом. Отвергнуто: stage/commit/push/PR в v1.
7. **2026-10-18 — CLI `hangar` и MCP-сервер (`hangar mcp`) — в v1.** Почему: агенты должны управлять приложением сразу. Отвергнуто: отложить на v2.
8. **2026-10-18 — Визуальный стиль A «Ghostty-native»; сайдбар на всю высоту, вкладки внутри области задачи; название задачи слева от вкладок.** Почему: выбор пользователя по макетам (сайдбар главный). Отвергнуто: вкладки сверху окна (`style-a-screens.html`), «только вкладки» без названия.
9. **2026-10-18 — Агент по умолчанию claude, меняется в настройках; в листе новой задачи выбора агента нет.** Почему: меньше шагов; другие агенты — через `+`. Отвергнуто: чипы выбора агента в листе.
10. **2026-10-18 — Лист новой задачи шириной ≥ 580, настройки одной карточкой, без капса и переносов подписей.** Почему: отзыв пользователя на v1–v3. Отвергнуто: узкий лист 400 с подписями сверху.
11. **2026-10-18 — Восстановление сессии: все задачи и вкладки; claude → `claude --resume <id>`, codex → `codex resume <id>` / `--last`.** Почему: требование пользователя. Отвергнуто: переживание процессов после выхода (сложно, не нужно).
12. **2026-10-18 — Лимиты Claude: `statusLine` = `hangar statusline` (читает `rate_limits` из stdin, пересылает в сокет, вызывает исходную статус-лайн пользователя) + hook `StopFailure` matcher `rate_limit`.** Почему: документированные источники. Отвергнуто: недокументированный OAuth usage endpoint.
13. **2026-10-18 — Лимиты Codex: короткоживущий `codex app-server` → `account/rateLimits/read` (по открытию поповера, ↻, концу хода, не чаще раза в минуту); запасной — `token_count` в свежем rollout.** Почему: без постоянного процесса и опроса. Отвергнуто: `/wham/usage`, постоянный опрос.
14. **2026-10-18 — Только документированные интерфейсы агентов.** Почему: недокументированное ломается без предупреждения. Отвергнуто: приватные endpoint'ы, парсинг внутренних файлов как основной путь.
15. **2026-10-18 — Изменения в `~/.claude`, `~/.codex`, конфиге Ghostty — только с согласия, с показом diff и откатом.** Почему: это файлы пользователя. Отвергнуто: молчаливая установка hooks.
16. **2026-10-18 — ponytail — только как принципы в `AGENTS.md`; плагин не ставим.** Почему: экономия токенов без lifecycle-hooks (требуют node). Отвергнуто: установка плагина/хуков.
17. **2026-10-18 — Название приложения Hangar, CLI `hangar`.**
18. **2026-10-18 — Блокировка сна только пока есть вкладки в `working` (+2 мин), `IOPMAssertion` без root; вкл/выкл в настройках и ☕ в сайдбаре.** Почему: Mac не должен спать во время работы агентов, но и не держать бодрствование «просто открытым окном». Отвергнуто: закрытая крышка через `pmset disablesleep` (root, перегрев).

Отвергнуто: молчаливая установка; работа без tmux как основной режим.

25. **2026-10-18 — Интерфейс `GhosttyBridge`:** `@MainActor final class GhosttyApp { static let shared; func start() throws }`; `@MainActor final class TerminalSurfaceView: NSView { init(spec: LaunchSpec); var onTitleChange: ((String) -> Void)?; var onBell: (() -> Void)?; var onDesktopNotification: ((String, String) -> Void)? /* title, body */; var onChildExit: ((Int32) -> Void)? /* -1 = код неизвестен */; func setVisible(_ visible: Bool) /* ghostty_surface_set_occlusion */; func sendText(_ text: String) /* bracketed paste, не выполняет команду */; func sendEnter() /* новое: ghostty_surface_key, keycode 36 */; func screenText() -> String? }`. Колбэки сразу копируют C-строки и вызываются на main. Почему: подтверждено спайком, `sendEnter` нужен для `hangar tabs send`/MCP. Отвергнуто: `sendText("...\r")` — вставка Enter не отправляет.

26. **2026-10-18 — Код выхода через обёртку OSC 133:** Ghostty на macOS запускает команду через `/usr/bin/login`, код выхода всегда 0. Команда вкладки: `<shell> -l -i -c '<inner>; c=$?; printf "\e]133;C\a\e]133;D;%d\a" $c; exit $c'`; код берётся из `GHOSTTY_ACTION_COMMAND_FINISHED`, поэтому `<inner>` без `exec`. Почему: проверено спайком (`exit 3` → `exit_code=3`). Отвергнуто: `exec claude` и `exit_code` из `SHOW_CHILD_EXITED`.

27. **2026-10-18 — PATH: `-l -i -c`:** login shell `-l -c` не видит `~/.local/bin` (добавляется в `~/.zshrc`), поэтому команды вкладок идут через `<shell> -l -i -c`. Почему: проверено с чистым env, как из Finder. Отвергнуто: только `-l`.

28. **2026-10-18 — Ресурсы Ghostty в `Hangar.app`:** `scripts/bundle.sh` копирует terminfo и `share/ghostty` из `zig-out/share` в `Contents/Resources`. Почему: иначе при запуске из Finder нет `xterm-ghostty` и shell integration (нет `PWD`, `COMMAND_FINISHED`). Отвергнуто: полагаться на env родителя.

29. **2026-10-18 — Первое сообщение агенту — аргументом CLI** (`claude "<msg>"`, `launchSpec(initialPrompt:)`), не через `sendText`. Почему: подтверждено спайком (сессия стартует с автоотправкой). Отвергнуто: отправка по первому выводу surface.

30. **2026-10-18 — OSC-уведомления Ghostty ограничены 1/сек на приложение:** статусы агентов берём из hooks, OSC — только запасной путь. Почему: при нескольких агентах лишние уведомления молча отбрасываются. Отвергнуто: OSC как основной источник статусов.

38. **2026-10-18 — Интерфейс на русском и английском, переключение в настройках без перезапуска.** `language = "system" | "ru" | "en"` в `~/.config/hangar/config.toml` (по умолчанию `system`: ru, если первый язык системы русский, иначе en). Строки — `Sources/HangarUI/Resources/{ru,en}.lproj/Localizable.strings` (исходный язык ru), доступ только через `enum L10n` (ключи `L10n.Key`, тест проверяет полноту обоих языков). String Catalog (`.xcstrings`) не используется: `swift build` (Swift 6.3) копирует его в бандл без компиляции, строки не находятся. Язык выбирается чтением `<lang>.lproj` напрямую (`String(localized:locale:)` язык не выбирает — только форматирование), выбор хранится в `@Observable`, поэтому SwiftUI перерисовывается сразу; меню пересобирается, полоски ошибок терминала перечитываются при `sync`. Бандл ресурсов SwiftPM копируется в `Contents/Resources/Hangar_HangarUI.bundle` (в корне `.app` ломает подпись), `L10n` ищет его там раньше `Bundle.module`. Окно настроек (`⌘,`, шестерёнка): язык, агент по умолчанию, редактор, `external_editor` (пусто — выкл.), фон терминала (применится после перезапуска). Запись — точечная правка одной строки ключа (комментарии и прочие строки не трогаются), атомарно; нет ключа — дописывается в конец корневой секции. Почему: решение пользователя. Клик по строке или вкладке клавиатуру у терминала не забирает (переход на другую задачу/вкладку, как и раньше, фокусирует её терминал); состояние `AppState.lastInteraction` (`.chromeClick(цель)` / `.typing`) только в памяти, без записи в модель на каждую клавишу. `Tab.focusedLeafId` следует за реальным фокусом (клик в панель → `setFocusedLeaf`), поэтому `⌘D` делит панель, в которой фокус; `⌘⇧W`; `⌘B` = `⌘0`; `⌘⌥↑/↓` — предыдущая/следующая задача (`⌘↑/↓` остаются терминалу). «Открыть в …» запускается через `<shell> -l -i -c 'exec <editor> <path>'`, а не `/usr/bin/env`: у приложения из Finder в PATH нет `/usr/local/bin` и `~/.local/bin` (как в #27); ненулевой код — `NSAlert` с последней строкой stderr. Нет папки — лист показывает «папка не найдена» без запуска, строка проекта серая. `.recoveredFromCorrupt` и `.unreadable` — `NSAlert` (строки ru/en через `L10n`); при `.unreadable` хранилище только для чтения. Выход: `applicationWillTerminate` → `saveNow`. Подтверждение ⌘Q при работающих агентах — этап 3. Ограничение: без id сессии у вкладки `--continue` / `resume --last` берут последний разговор в cwd, поэтому набор `restoring` считается один раз при старте (`resumeSet`): листья с `agentSessionId` всегда возобновляются, среди claude/codex без id в одном (вид, cwd) продолжается только первый (по порядку задач → вкладок → листьев → панели), остальные стартуют заново; настоящие id по вкладкам — с хуками этапа 3. **Запуск листа агента (обновлено 2026-10-19, финальное ревью):** `LaunchSpec` строится заново при каждом запуске (замороженный spec не переиспользуется) из одной чистой функции `launchMode(for:_:)` (`Sources/Exec/Launch.swift`) по контексту: `.created(prompt)` — новая задача/вкладка, свежий старт, первое сообщение только в этот первый запуск; `.restored(inResumeSet)` — старт из state.json и восстановление задачи из архива (в ту же сессию или позже), правило `resumeSet` как выше; для разархивированной задачи набор считается по её листьям (их surface закрыты архивом), работающие листья других задач слот не занимают; `.relaunch(previous, exitCode)` — ↩: первое сообщение никогда не отправляется повторно; если прошлый запуск был возобновлением (`--continue` / `resume --last` / `--resume <id>`) и завершился с ненулевым кодом — свежий старт (иначе бесконечное «No conversation found to continue»), иначе — возобновление (`--resume <id>`, если id известен, иначе `--continue` / `resume --last`); surface не создался (`exitCode` нет, процесс не запускался) — тот же запуск ещё раз. id сессии используется только при возобновлении: свежий старт после неудачного `--resume <id>` его игнорирует. Шелл и редактор не меняются (шелл в том же cwd, редактор с тем же файлом). Почему: приёмка этапа 1.

42. **2026-10-19 — Worktree и лист «Новая задача» (этап 2).** Модуль `Git` поверх `Exec.Runner` (struct с замыканием, не протокол; `ssh` — этап 6). Путь worktree: `<родитель проекта>/<папка проекта>.worktrees/<slug ветки>`, настраивается в настройках проекта («Папка worktree»). Slug: lowercase, транслит кириллицы по таблице (Task 3), пробел и `/` → `-`, схлопывание `-`, пусто → `task`. Новая ветка создаётся с `--no-track` (не тянет upstream базы, `git push` не уйдёт в базовую ветку). Переключатель Worktree запоминается по проекту (`Project.worktreeByDefault`); базовая ветка — `Project.lastBaseBranch`, её же правит «Ветка по умолчанию» в настройках проекта (`nil` = из `origin/HEAD`). «Обновлено N мин назад» — по mtime `FETCH_HEAD` (учитывает и fetch из терминала, ничего не хранит). Fetch — при открытии листа (фоном), по ↻ и перед созданием, если в этом открытии успешного fetch ещё не было; только remote базовой ветки (для локальной базы — `origin`, нет remote — пропуск). Архив worktree не трогает. «Удалить навсегда» — галочка «Также удалить worktree и ветку» (выкл.); грязный worktree или файлы вне git (ignored: `.env`, локальные БД; в окне до 5 имён) — второе подтверждение, `--force` только после него; ветка — `branch -d` (не слита — сообщение, ветка остаётся). «Удалить из Hangar» worktree не трогает. Не-git проект — строк worktree нет. Почему: решения контроллера плана этапа 2. Исключение из «только `-d`»: уборка после неудавшегося `worktree add` делает `branch -D` лишь для ветки, которую только что создали. Отвергнуто: протокол `GitRunner`, моки вывода git, `-D` при удалении задачи, удаление worktree при архивации, опрос fetch.

43. **2026-10-20 — Статусы агентов, уведомления, лимиты (этап 3).** Решения контроллера: модули `AgentStatus`, `Usage` и минимальный `ControlServer` — только типы `event` и `usage` (остальные — этап 5); CLI `hangar` — только `event` и `statusline`; установка интеграций — с согласием, точным diff, копией и откатом; запасные пути статусов; уведомления macOS; подтверждение ⌘Q; лимиты — пороги 80/95, одно уведомление на пересечение, без опроса. Решения плана:
  - env `HANGAR_LEAF_ID` (id листа) рядом с `HANGAR_TAB_ID`: статус хранится на лист (сплиты, панель TERMINAL, где `HANGAR_TAB_ID` = id листа); событие с tab, не владеющим leaf, игнорируется.
  - CLI лежит в `Hangar.app/Contents/Helpers/hangar`, а не в `Contents/MacOS/hangar`: APFS по умолчанию нечувствительна к регистру, `MacOS/hangar` совпал бы с `MacOS/Hangar`.
  - Hooks Claude: `SessionStart` (id сессии), `UserPromptSubmit` → working, `PostToolUse` (matcher `*`) → working (выход из waiting после разрешения), `Notification` → waiting только для `permission_prompt`/`elicitation_dialog` (`idle_prompt` иначе превращал бы каждый done в waiting), `Stop` → done, `StopFailure` matcher `rate_limit` → failed + `limitReached`; у каждого `"timeout": 5`. Прерывание (Esc) не вызывает `Stop` — статус остаётся working до следующего промпта (ограничение Claude Code).
  - Запасные пути: bell/OSC-уведомление → waiting только у листов claude/codex и только если у листа не было hook Claude; гаснет в idle при фокусе листа; код выхода > 0 → failed, иначе idle; перезапуск → idle. У Codex нет события «начал работу» — working для Codex недоступен до hooks Codex (проверить, когда codex будет установлен).
  - Исходная статус-лайна хранится в самой команде: `'<cli>' statusline --then '<исходная команда>'` (остальные ключи `statusLine` не трогаются); исходный `notify` Codex — так же: `[cli, "event", "codex-notify", "--then", …исходный argv]`. Отдельного файла состояния нет; откат восстанавливает из команды.
  - `settings.json` правится собственным JSON-кодом с сохранением порядка ключей и литералов чисел, вывод с отступом 2 (модуль `Integration`); комментарии/ошибки JSON — отказ без записи.
  - Сокет — в папке состояния (DEBUG изолируется `HANGAR_STATE_DIR`); второй экземпляр — по успешному `connect` к существующему сокету, pid собеседника (`LOCAL_PEERPID`) активируется, новый процесс выходит; мёртвый сокет удаляется.
  - Строка задачи: точка статуса всегда в жёлобке, иконка worktree — в конце строки (12 pt), в рейке точка 7 pt в углу монограммы (`icons-sidebar.html`).
  - Ключи конфига `notifications = true|false`, `limit_notifications = true|false` (по умолчанию `true`, голые bool).
  - Лимиты без таймера: прошедшее окно сбрасывается при отрисовке (а она — при сообщении, открытии поповера, активации приложения). Резервный источник Codex (rollout) и `UsageLimitExceeded` — после установки codex.
  - Отвергнуто: `MacOS/hangar`; статус на вкладку вместо листа; `JSONSerialization` (теряет порядок ключей); отдельный файл с исходной статус-лайной; таймер сброса окна; опрос `codex app-server`.
