# Дизайн-система v1 — исследование, аудит, черновик

Статус: черновик для обсуждения с владельцем (ничего в коде не меняется). Доска: `docs/superpowers/mockups/design-system-v1.html` (токены, главный экран A/B × Navy/Dark+, лист «Новый чат», переключатель ветки). Сравнение шрифтов: `docs/superpowers/mockups/design-system-fonts.html`.

Бриф владельца: инструмент разработчика — понятность и отсутствие лагов; не перегружено и не «вырвиглазно»; сейчас каждая фича делается «как попало», темы только красят базу. Нужна полная система (отступы, шрифты, скругления…), зафиксировать в скиле после обсуждения. Ориентир — WebStorm и подобные, не VS Code / Cursor. Шрифты — чтобы русский не отличался от английского. Дополнения: разделить главное и второстепенное; ясные тексты; нужна ли строка состояния; ветка проекта всегда видна и переключаема.

Принципы, которые делают их спокойными:
1. **Иерархия весом и контрастом текста**, не цветом: 2 веса, 3 уровня серого; цвет — только статус и одна акцентная роль (JetBrains: всё — Gray-ступени, акцент — один Blue6).
2. **Мало размеров**: JetBrains — база 13, «−1» и два заголовка; всё остальное — производные от базы.
3. **Одна высота строки** (24) для всех деревьев и списков, **одна высота контрола** (28).
4. **Линии вместо заливок**: группы разделяет отступ или 1 px, заливка — только у выбранного.
5. **Темы = отображение ролей на палитру**, размеры от темы не зависят.
6. **Плотность — отдельной осью** (Compact в JetBrains, `entry_spacing` в Zed), но без смены языка компонентов.

Все кандидаты рисуют кириллицу на той же x-высоте, что латиницу («х»/«x» = 1.00); у пропорциональных шрифтов русская строка в среднем на 12–18 % шире английской — это свойство языка (ж, ш, щ, ы, ю), а не шрифта. Ширина кириллицы у Inter и Golos чуть меньше, чем у SF Pro (−3…−5 %).

**Рекомендация: интерфейс — SF Pro (системный), моно — SF Mono (системный).** Ноль зависимостей, нативный хинтинг и оптические размеры, кириллица от Apple, та же пара, что у Xcode и VS Code на macOS. Терминал и Monaco — шрифт, выбранный пользователем (как сейчас); Monaco по умолчанию брать шрифт терминала Ghostty, чтобы в одном окне не было двух моно. Убрать «JetBrains Mono» из DESIGN.md. Альтернатива для владельца: Inter + JetBrains Mono в бандле (≈ 1.2 МБ, OFL, запись в `decisions.md`) — ближе к виду WebStorm, русский чуть компактнее, но шрифт перестаёт быть системным.

## 4. Лаги — куда смотреть (только указатели)

1. `AppState` — один `@Observable` (~105 хранимых свойств + 15 расширений). Проверить `Self._printChanges()` в `SidebarView`, `TabBarView`, `InspectorView`: перерисовываются ли они на каждое событие статуса агента.
2. 39 `onHover` с `withAnimation(Motion.ease(0.12))` — анимированная транзакция на каждый проход мыши по строкам. Наведение лучше мгновенно.
3. Сворачивание сайдбара — `Timer` 120 Гц меняет толщину `NSSplitView` (`MainWindow.swift:391`): каждый кадр — layout SwiftUI и, вероятно, resize терминальных surface. Проверить, ресайзится ли libghostty покадрово; если да — фиксировать размер терминала до конца анимации.
4. Сайдбар обёрнут в `AnyView` (`MainWindow.swift:205/233`) — стирание типа, полная пересборка при замене корня.
5. 11 `GeometryReader`, 4 `ForEach(indices, id: \.self)` — мелочь, но в списках (настройки, update, интеграции) ломает идентичность строк.
6. Синхронного `Process.waitUntilExit` в UI нет (только Installer и CLI); чтение каталогов `nonisolated` — хорошо. `EditorIO` (`Data(contentsOf:)`) — проверить, с какого потока.

## 5. Ответы на дополнения владельца

### 5.1 Главное и второстепенное

| Главное (видно всегда, крупно) | Второстепенное (иконка, меню, тултип) |
|---|---|
| список чатов со статусом; текущий чат и ветка в заголовке | «Новый чат» — иконка у заголовка «Чаты» и ⌘N |
| вкладки агентов/терминала, терминал | «История» (⌘Y), «Настройки» — подвал сайдбара |
| «Изменения» с числом файлов | SSH-серверы — секция внизу, скрыта, если нет |
| «ждёт ответа» / «ошибка» — словом и цветом в строке | «работает», «готово», «простой» — только точкой |
| колокольчик со счётчиком | обновление, «не спать» — в заголовке справа, только когда есть |

Правило: в сайдбаре цветом и словом — только то, что требует действия (ждёт, ошибка); всё остальное — нейтрально.

### 5.2 Словарь

| Сейчас | Предлагаю | Почему |
|---|---|---|

| Новая сессия | **Новый чат** | |

Решение владельца: «Чат» или «Задача» (так называется сущность в коде) — доска сделана на «Чат».

### 5.3 Лист «Новый чат» (доска: A — копия выбрана, B — папка проекта)

Порядок: Название → **Где работать** (две карточки-радио: «В папке проекта — сейчас ветка `main`, изменения увидят все чаты проекта» / «В отдельной копии — своя папка и ветка (git worktree), не мешает другим чатам») → только для копии: «Ветка копии `hangar/<имя>` от `origin/main ▾`» и «☑ Подготовить копию: `pnpm install`» → свёрнуто «› Задание для Claude — можно написать потом, во вкладке» → «Отмена» / «Создать чат». Убрать «esc — отмена» (системное поведение), «⌘↩» — в тултип.

Рекомендация: **убрать строку состояния** (−24 pt, минус одна полоса). Минимальная альтернатива: показывать её только в редакторе (язык, LSP, миникарта) — как у WebStorm.

### 5.6 Ветка: показ и переключение

Сейчас: ветка в заголовке только у worktree-чата и из сохранённого при создании `task.branch`; если агент/терминал сделал `git checkout`, UI не узнаёт. FileWatcher уже ловит изменения `HEAD` в git-dir (для статуса) — достаточно читать текущую ветку оттуда.

Предложение:
- Ветка видна **всегда**: в заголовке («acme-web / discount-codes [⎇ feat/discount ▾]») и моно-подписью `text3` в строке каждого чата (вместо слова статуса, если статус не требует действия). Источник — живой `HEAD` папки чата (detached — короткий хеш).
- Клик по ветке — поповер: поиск, локальные ветки (текущая с галочкой; занятая другим чатом-копией — подпись «чат «…»», недоступна), «Новая ветка от <текущей>…».
- Минимально безопасно: `git switch <ветка>` только при чистом дереве; при изменениях — отказ с текстом «Есть незакоммиченные изменения (N файлов). Переключиться можно после коммита или stash. Новая ветка возьмёт изменения с собой.»; `git switch -c` разрешён всегда. Без stash/merge/rebase/pull/push.
- **Решение владельца:** спека §1 «Вне рамок» запрещает git-действия. Запрос владельца это переоткрывает — нужна запись в `decisions.md` («разрешены только switch и switch -c; остальное по-прежнему вне рамок»).

## 7. Два направления

| | **A «Спокойный компактный»** (≈ WebStorm New UI Compact) | **B «macOS-native»** (≈ Xcode / Nova) |
|---|---|---|
| Сетка | 4 pt, строки 24/28 | 4 pt, строки 28 |
| Хром | одна полоса заголовка 38 с названием и веткой | тулбар 52: название чата + проект, ветка-кнопка |
| Сайдбар | строки на всю ширину с малой вставкой, группы по проектам, «Новый чат» иконкой у секции | source list: скругление 6, выделение заливкой акцента, папки проектов, кнопки в подвале |
| Вкладки | плоские, подчёркивание акцентом | «пилюли» с заливкой |
| Инспектор | вкладки как у вкладок терминала | системный сегмент |
| Радиусы | 4 / 8 / 12 | 6 / 10 / 12 |
| Плюсы | максимум терминала, мало декора, один язык вкладок, легко держать единообразие | роднее macOS, привычно пользователям Xcode |
| Минусы | меньше «маковости» | ниже плотность; акцентная заливка выбранного — самое яркое пятно на экране |

**Рекомендация — A** со шрифтами SF Pro / SF Mono. Из B взять только системные поповеры и листы.

## 8. Решения владельца

1. Направление: A (рекомендую) или B.
2. Шрифты: системные SF Pro + SF Mono (рекомендую) или Inter + JetBrains Mono в бандле (+1.2 МБ, OFL).
3. Словарь: «Чат» (как на доске) или «Задача»; «История» вместо «Сессии».
4. Строку состояния убрать (рекомендую) или оставить только в редакторе.
5. Переключение ветки: разрешить `git switch` / `switch -c` при чистом дереве — исключение из «Вне рамок» §1 (запись в `decisions.md`).
6. Подписи инспектора: русские («Файлы / Изменения / Git / Поиск») или английские везде (тогда и «Worktree» и т. п. — единообразно).
7. Темы: оставить три темы, но привести к ролям (левый и правый сайдбары одного цвета).
