# Субагенты агента — спека

Статус: задача владельца от 2026-11-05 (по мотивам сайдбара Orca: субагенты сессии Claude — вложенные строки со статусом); решения HD-136, HD-139, HD-145. Видно, что делает агент-оркестратор — его субагенты Claude (инструмент Agent/Task), — и можно заглянуть в любой, без расхода энергии, пока не смотришь.

## 1. Что это
Под строкой чата в сайдбаре — свёрнутая строка «2 субагента работают»; развёрнутая — по строке на работающего субагента: иконка статуса, его задача («Implement Task 2.2»), сколько идёт. Законченный уходит из сайдбара сразу (HD-145). Клик по субагенту открывает в инспекторе вид «Субагент» только для чтения (немодально, HD-139 — работать рядом можно): задание оркестратора, ход работы (сообщения и вызовы инструментов, обновляются вживую), итог.

Слова: «субагент» / "subagent" (как в статусе чата «работает · 2 субагента»); в коде `Subagent`, `SubagentList`.

## 2. Источники (только документированные, HD-014)
Хуки Claude Code (https://code.claude.com/docs/en/hooks, прочитано 2026-11-05, Claude Code 2.1.318):
- `PreToolUse` с matcher `Task|Agent` (уже был, `subagent-start`): `tool_use_id`, `tool_input.description`, `subagent_type`, `prompt` → строка рождается.
- `SubagentStart` (**новый**, `hangar event subagent-run`): `agent_id`, `agent_type` — у строки появляется id субагента, а значит и его журнал. Описания и промпта в нём нет.
- `PostToolUse` `*` (уже был, `tool`): для инструмента Agent/Task — `tool_use_id`, `tool_response.agentId`, `tool_response.status` (`completed` — закончил; `async_launched` — фоновый, работает дальше).
- `SubagentStop` (уже был, `subagent-stop`): `agent_id`, `last_assistant_message`; `agent_transcript_path` не берётся — путь считается сам (§5).
- `UserPromptSubmit`, `Stop`/`StopFailure`, `SessionStart` — границы хода. `Stop` приходит, когда ход главного агента кончился, даже если фоновый субагент ещё работает; после Esc (прерывание) `Stop` не приходит. Его `background_tasks` — задачи в работе: `id`, `type` (`subagent`, `shell`, …), `status`, `description`; у субагента `id` — его `agent_id` (сверено с журналами Claude Code 2.1.318: `<task-id>` уведомления = `agentId` ответа Agent = имя `agent-<id>.jsonl`). Берутся id идущих записей (`running`/`pending`/`in_progress`/`started` или без статуса), не больше 99 (больше — список не используется), каждый — как id субагента ниже.
- Прерванный субагент `SubagentStop` не присылает (HD-145): его журнал кончается строкой `user` «[Request interrupted by user]».
- Любой хук, сработавший внутри субагента (его инструменты), несёт `agent_id` (и `agent_type`); `hangar event` помечает такое событие `inSubagent` (кроме `SubagentStart`/`SubagentStop`, где `agent_id` — сам субагент). Вне хода главного агента такие события статус чата не меняют (HD-145, §3).

Новый хук добавляется существующим путём HD-095 R1 / HD-111: только недостающие записи Hangar, пользовательские не трогаются, резервная копия, идемпотентно; согласие уже дано включённой интеграцией. Без него (до обновления файла) всё работает, кроме журнала ещё работающего переднего субагента: id приходит только с его концом.

Поля проверяются на границе доверия дважды — в `hangar event` и при разборе строки сокета: id — `[A-Za-z0-9_-]{1,128}` (из них строится имя файла), тип ≤ 64 символов без управляющих, описание — первая строка ≤ 200, промпт и итог ≤ 2000. Поля субагентов есть только у Agent/Task: прочие `PostToolUse` идут как раньше и списков не трогают.

## 3. Состояние (`AgentStatus/Subagents.swift`, только в памяти)
`SubagentList` на лист агента; события без своих часов (время приносит событие):
- **launch** (PreToolUse) — строка `running`, ключ `tool_use_id`, тип по умолчанию `general-purpose`, название — описание или тип.
- **started** (SubagentStart) — id к первой работающей строке без id того же типа (иначе любой). *shortcut:* параллельные запуски одного типа сопоставляются по порядку прихода; ответ инструмента (`returned`) исправляет ошибку обменом id. Повторный SubagentStart того же id (resume) — снова `running`.
- **returned** (PostToolUse Agent) — id из ответа; `async_launched` → фоновый, иначе `done`.
- **stopped** (SubagentStop) — `done` + итог (и у уже `failed`: его стоп разминулся со `Stop`, который его не перечислил); id без строки запоминается (до 16): передний субагент останавливается раньше, чем отвечает инструмент; внутренние агенты Claude (подсказки, `/btw`) так и не находят строки.
- **turnEnd** (Stop/StopFailure) — работающий нефоновый не вернулся: `failed` («прерван»). Есть список `background_tasks` у `Stop` (HD-145) — работающий фоновый с id, которого в нём нет, тоже `failed`: прерван без `SubagentStop`. Нет списка (старый Claude Code, `StopFailure`) или у строки нет id — фоновые не трогаются.
- **turnStart** (UserPromptSubmit) — работающий нефоновый → `failed` (Esc не шлёт `Stop`; *shortcut:* ввод во время хода Claude выполняет после хода, HD-062, — передний субагент промпт не переживает; менять, если `UserPromptSubmit` начнёт приходить посреди хода). Уходят законченные до конца прошлого хода; законченные после (фоновый субагент разбудил Claude) остаются на этот ход. Фоновые не трогаются — их сверяет следующий `Stop`.
- **interrupted** (журнал открытого вида, §5) — последняя прочитанная запись — «[Request interrupted by user…]»: строка `failed`. Только то, что вид и так читает; нового чтения или опроса нет. Повторный SubagentStart (resume) снова делает её `running`.
- **exited** (выход агента) — работающие → `failed`; **reset** (SessionStart startup/clear/resume, перезапуск вкладки) — пусто. compact не сбрасывает.
- Не больше 30 строк: первыми уходят самые старые законченные.

Счётчик субагентов в статусе чата (`activeSubagents`, «работает · 2 субагента») остаётся как был.

**Статус чата — состояние главного агента (HD-145).** `LeafStatus.inTurn` — его ход идёт (промпт или его инструмент … `Stop`/`StopFailure`, выход, перезапуск, `SessionStart`). Инструмент или запуск субагента с пометкой `inSubagent` вне хода состояние не трогает: «готово» остаётся «готово» (непросмотренным, с записью во входящих); запрос разрешения субагента — «ждёт», после ответа (его следующий инструмент) — снова «готово». Внутри хода — как раньше («работает»).

## 4. Сайдбар (`SidebarSubagents.swift`)
- Под строкой чата (проект, «Чаты», подчат — на уровне его отступа + `subChatIndent`): строка 28 — треугольник 12 `text3` в колонке точки, «N субагент работает / субагента работают / субагентов работают» (`secondary`, `text2`; en "N subagent(s) running"). Клик сворачивает/разворачивает; по умолчанию свёрнуто; раскрытие не сохраняется (в памяти).
- Развёрнуто — строки 28 только работающих (HD-145): `StatusDot` `working` (спиннер), название `text1` с обрезкой, в конце время `caption` `text3` — сколько идёт: «<1 мин», «N мин», «N ч M мин». Законченный (готово, ошибка, прерван) уходит из сайдбара сразу; его итог — в виде «Субагент» (там же «готово» — тихая галочка, прерван — `failed`, время — сколько шёл). Тултип и VoiceOver — «название · тип · состояние · время».
- Время пересчитывается только при перерисовке (как «2 мин» у чатов без проекта) — таймера нет, поэтому секунд не показываем.
- В рейке ничего; фильтр «только ждущие» строки чатов не меняет. Перетаскивание учитывает высоту строк субагентов.
- Строк и счётчика нет, пока у чата никто не работает.

## 5. Просмотр (`SubagentViewer.swift`, вид инспектора «Субагент», HD-139)
- **Немодально, в инспекторе.** Клик по строке субагента — вместо содержимого инспектора вид «Субагент»: строка-шапка высотой с сегмент (`barTabs`, нижняя `line`): «Субагент» `secondary` 600 `text1`, справа «×» (`IconButton`, тултип «Закрыть (Esc)»). Ниже прокрутка (поля `rowPaddingH`): название `body` 600 `text0` (переносится), строка состояния — точка, «тип · слово · время» `secondary` `text2`; «Задание» — первое сообщение журнала (иначе промпт из хука); шаги: текст агента `body`, вызов — имя инструмента `mono` 600 + суть ввода (описание / команда / путь / шаблон) в одну строку, результат — `monoSmall` `text3` до 3 строк (ошибка — `failedText`); «Итог» — сообщение `SubagentHandback`, иначе `last_assistant_message` законченного. Выделение текста включено; новые шаги прокручивают вниз.
- Клик выбирает чат субагента (если выбран другой) и показывает скрытый инспектор. Клик по другой строке переключает вид; по той же — ничего.
- **Закрывается:** «×»; Esc — если фокус в инспекторе, ни у чего (`FirstResponderKind.other`) или сразу после клика по строке, пока клавиша не ушла в терминал (терминал и поля свой Esc сохраняют — им прерывают агента); ⌥⌘1/2/3 и другие показы сегмента; выбор другого чата; вкладка агента закрыта. Субагент закончил или его строка ушла из списка (новый ход, сброс) — вид остаётся с последним состоянием, пока его не закроют (HD-145). Скрытие инспектора (⌥⌘I) и «Сессии» вид не закрывают — только приостанавливают.
- Журнал: `<config>/projects/<папка cwd>/<session>/subagents/agent-<id>.jsonl` (сначала папка, которую claude называет по cwd листа, потом любая — id уникальны, как `transcriptChoice`); session — id разговора листа. Формат проверен на файлах Claude Code 2.1.314 (только чтение): строки `user`/`assistant`, `isMeta`, вложения, thinking и служебные записи пропускаются.
- **Энергия:** журнал читается и смотрится только пока вид на экране — открыт, инспектор показан, «Сессии» не поверх, окно видно (не свёрнуто, не закрыто другими; `AppState.syncSubagentPanel` из `InspectorWatch.update`, как остальной инспектор). Тогда FSEvents (`FileWatcher`, папка журнала, задержка 0,3 с) — только события этого файла, дочитываются только дописанные полные строки (`TranscriptReader`, ≤ 8 МБ за раз, ≤ 4000 символов на шаг, ≤ 2000 шагов). Ушёл с экрана — поток FSEvents остановлен; вернулся — дописанное за это время дочитывается один раз (смещение читателя сохраняется), поток снова. Закрыт — нет ничего. Строка получила id или закончилась, пока вид на экране, → поиск журнала ещё раз (событие, не опрос).

## 6. Где работает
- Чаты проекта, чаты без проекта, подчаты — у любой вкладки claude (и в нижнем терминале).
- **Удалённые (ssh)** — строки из хуков есть (через `hangar-remote`, разбор на Mac), журнала нет: в том же виде «Субагент» задание и итог из хуков и строка «Ход работы виден только у чатов на этом Mac.» Сверка по `Stop` и промпту — та же (payload `Stop` разбирается на Mac тем же кодом); по журналу (**interrupted**) — нет, журнала нет. *shortcut:* `hangar-remote` версии 6 не знает `subagent-run` и отбрасывает его — строки сопоставляются по ответу инструмента; добавить при следующем изменении `hangar-remote`. Чтение журнала по ssh по запросу — не делаем, пока не попросят.
- **Codex** — пропускаем: у него нет хуков субагентов.
- CLI/MCP (`tabs subagents`) — не делаем: не просили.
