# HD-089 — 2026-10-27 — `--continue` рядом с известным id сессии не даётся (Pane B22, дополняет #41 и #62).

Было: в (агент, хост, папка) первый лист без id получал `--continue` / `resume --last`, даже если у соседнего листа id из hooks был. `--continue` берёт последний разговор папки, а это почти всегда разговор того соседа (у него hooks работают) — две вкладки оказывались в одном разговоре. Так же ↩ второго листа без id после того, как первый получил id из SessionStart, делал второй «первым без id» и подцеплял разговор первого. Теперь `resumeSet`: лист с валидным id всегда `--resume <id>`; без id продолжает не больше одного листа на ключ, и только если ни у одного листа этого ключа (во всех незаархивированных сессиях) нет id; остальные стартуют заново. Правило одно для старта, разархивации и каждого запуска (`spec(for:)`, #62); разархивация тоже судит по всем живым сессиям, а не по одной своей. id из hooks уже пишутся в лист (`setAgentSessionId` → `scheduleSave`, при выходе `saveNow`), поэтому листов без id при работающих hooks почти нет: это листы, где агент так и не начал сессию, или запущенные до установки hooks. Цена: такой лист теряет `--continue` к своему разговору, если он был; разговор остаётся в «Сессиях» (⌘Y) и открывается оттуда. Отвергнуто: искать «последний свой» разговор по истории (`History`) — на удалённых хостах её нет, а локально это угадывание того же рода.
