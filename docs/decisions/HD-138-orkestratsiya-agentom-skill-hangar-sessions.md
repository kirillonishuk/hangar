# HD-138 — 2026-11-05 — Оркестрация агентом: скилл Hangar, `sessions_note`, `tabs_wait` (решения владельца по разбору Orca; дополняет #111, #128, #131).

(1) **Скилл Hangar** — короткий `SKILL.md` (~2,3 КБ: когда делить работу, `sessions_spawn` в папке родителя / `worktree: true` для параллельных правок, `sessions_wait`, `sessions_note`, `tabs_wait`, `tabs_read` только при нужде; правила — задача самодостаточна, итог коротким, без подчатов для мелочи, в терминал родителя не писать). Лежит в ресурсах приложения; ставится **только** переключателем «Скилл Hangar» в карточках Claude Code и Codex (Настройки → Интеграции, «этот Mac») в `<папка агента>/skills/hangar/SKILL.md` (`$CLAUDE_CONFIG_DIR` / `$CODEX_HOME`, иначе `~/.claude` / `~/.codex`; Codex читает скиллы оттуда же). Ключи `claude_skill` / `codex_skill`, по умолчанию `false`: ни согласие первого запуска, ни миграция его не включают; включение переключателя — и есть согласие (как остальные функции карточки, #111), отдельного листа diff нет — файл новый и целиком наш. Запись — `writeUserFile` (атомарно, отказ при изменении, копия старого в `<state>/backups`); свой файл узнаётся по метке `<!-- hangar-skill vN -->`: при запуске другая версия обновляется (тихо, с копией), выкл. — свой файл удаляется (копия) и пустая папка; чужой `skills/hangar` не трогается никогда (подпись `waiting`). От главного переключателя не зависит (как MCP); на хосты не ставится (MCP только на Mac). (2) **`sessions_note`** (MCP; CLI `hangar sessions note [TEXT…] [--session S]`; метод сокета `tasks.note`): чат — вызывающий (`HANGAR_LEAF_ID`) или явный. Текст — недоверенный: переводы строк и табы → пробел, управляющие символы и невидимые разделители/bidi убираются, пробелы схлопываются, обрезка до 100 символов с «…», пустое — очистка. Хранится в `HangarTask.note` (state.json). Показ (правило «без повторов»): тултип строки сайдбара второй строкой и подзаголовок тулбара «проект · заметка»; конец строки сайдбара (ветка / слово состояния / счётчик подчатов) не занимается — там уже нужная информация, а заметка нужна реже. Также `note` в `sessions_list` и в каждом `SubSessionInfo` `sessions_wait` (родитель видит, где идёт подчат). **Очищается только самим агентом** (пустая заметка); новый ход пользователя её не сбрасывает — оркестратор получает уточнения посреди плана, и сброс стёр бы ещё верную стадию; архив тоже не трогает. (3) **`tabs_wait`** (MCP; CLI `hangar tabs wait --tab T [--for idle|waiting|any] [--next] [--timeout N]`; `tabs.wait`, в `--read-only`): `idle` — ход окончен (`idle`/`done`), `waiting` — агент просит ввод, `any` (по умолчанию) — любое; `failed`, `limit`, выход процесса (`exited`) и закрытие вкладки (`closed`) заканчивают всегда. По событиям: хук листа, изменение его статуса, выход процесса и закрытие вкладки / архив чата (`perform`) будят ждущего сразу, таймер — только дедлайн (энергия). Таймауты как у `sessions_wait` (110 с, Codex 50 с, `still-running` — вызвать снова). Возвращает статус и последнее сообщение агента (Stop / codex notify / вопрос; сбрасывается новым промптом; ≤ 1500 символов). Гонка «отправил и сразу ждёт» (прежнее «готово» вернулось бы сразу) решена параметром `next: true` / `--next`: текущее состояние не считается, ждётся следующий **конец хода** после вызова — счётчик концов хода листа (Stop, codex notify, StopFailure, вопрос) растёт в `handle`, ждущий сравнивает его со значением на старте. Считаются концы, а не начала: Codex сообщает только конец хода; ход, начавшийся и закончившийся между пробуждениями, не теряется. По умолчанию `next` выкл. — поведение прежнее; описание инструмента и скилл велят ставить `next: true` сразу после `tabs_send`. **Отвергнуто:** автоустановка скилла с MCP; заметка в конце строки сайдбара; сброс заметки на новом ходе; опрос статуса в `tabs_wait`.
