# HD-044 — 2026-10-21 — Инспектор (этап 4).

Решения контроллера: без tree-sitter и новых зависимостей на этапе 4 — unified diff с фоном строк `+/-`, заголовками ханков, номерами строк, моно; подсветка синтаксиса отложена (почему: цена зависимости — грамматики, сборка, размер; вернуться по слову пользователя; tree-sitter по-прежнему не подключён — встроенный лексер, HD-053); split-diff нет (HD-023). Git-чтение — в модуле `Git` через `Runner` (этап 6 подменит исполнителя): `status --porcelain=v2 -z`, `changedFiles` (merge-base с базовой веткой / незакоммиченное), `diff` с разбором `-U3`, `listFiles` через `ls-files -c -s -z` (отслеживаемые; режим 120000 — симлинк) + `ls-files -o --exclude-standard -z` (неотслеживаемые). Files: ленивые каталоги, бейджи из status, каталоги первыми; клик — Helix (`Esc` + `:open <path>` + ↩ в существующий editor-лист, иначе новая editor-вкладка). Не-git — только Files (FileManager, без `.git`). Changes: `+N −M`, временная diff-вкладка (курсив, не сохраняется, заменяется, ⌘W), `↑/↓`, `↩` (`:goto N` / `hx path:N`), `⌥B`. Обновление: FSEvents видимой задачи, только при видимом инспекторе и неперекрытом окне, плюс `done` агента и смена задачи. Решения плана:
- `--no-optional-locks` у всех команд инспектора (иначе цикл: `status` пишет index → FSEvents → `status`).
- Debounce = `latency` 0.3 с потока FSEvents, своих таймеров нет. Новое событие во время загрузки того же контекста не отменяет её: ставится флаг «повторить», после завершения — ровно одна повторная загрузка (иначе при непрерывной записи агента загрузка не завершалась бы никогда). Смена задачи, режима `⌥B` или корня — отмена загрузки (`Task.cancel` → `Runner` убивает git).
- События: внутри git-dir обновляют только `index`, `HEAD`, `refs/**`, `packed-refs`, `MERGE_HEAD`; `objects/`, `logs/`, `*.lock`, `FETCH_HEAD` — нет. Создание/удаление/переименование вне git-dir — перечитать и дерево, и статус; изменение содержимого — только статус. События под игнорируемыми путями (сборка, `node_modules`) отбрасываются: набор берётся из одного `status --porcelain=v2 --ignored=matching` на каждую загрузку дерева (целиком игнорируемый каталог — одной записью); правка `.gitignore` или `info/exclude` перечитывает всё.
- Пути — от папки задачи; в Helix уходит абсолютный путь. Проект в подпапке репозитория (`<repo>/apps/web`, этап 6, вместо прежнего «весь репозиторий»): инспектор показывает только подпапку. git идёт с cwd = подпапка: `rev-parse --show-toplevel --show-prefix` (верх + префикс `apps/web/`), `ls-files` (сам ограничен cwd, пути от неё), `diff --relative … -- .`, `status … -- ':(top,literal)apps/web/'` с отрезанием префикса (porcelain-пути всегда от верха), `--ignored=matching -- .`; парсеры, `-z`, `--no-optional-locks` — прежние. Переименование из-за пределов подпапки показывается как добавление. FSEvents — подпапка, git-dir (и refs/`packed-refs`/`info/exclude` общего git-dir) и файлы `.gitignore` предков до верха (их правила действуют и на подпапку; атомарное сохранение такого файла приходит как RootChanged → всё). Worktree-задача такого проекта — та же подпапка внутри worktree (если она там есть; верх репозитория ищется по ближайшему `.git` на диске — `shortcut:`). Удалённые проекты: main-folder — то же сужение автоматически (те же команды с cwd); worktree-задача удалённого проекта — весь worktree. После ревизии в `diff` всегда `--` (файл с именем `HEAD` иначе «ambiguous argument»). `git rm --cached x` — в Changes одна строка (удалён из diff), untracked-дубль из статуса пропускается. Пробы (`rev-parse`, `symbolic-ref`, `defaultBranch`) тоже с `--no-optional-locks`.
- Лимиты: 5 000 записей статуса/изменений, 200 000 путей дерева, ≥ 50 000 путей — без автораскрытия; diff > 20 000 изменённых строк — «слишком большой diff». «Ленивое дерево» — строки строятся только для раскрытых каталогов из индекса одного `ls-files`; `ls-files` повторяется только при создании/удалении/переименовании файлов.
- Untracked-файлы — в Changes обоих режимов, без `+N −M` (счётчики через `--no-index` на каждый файл — лишние процессы; `// shortcut:`), diff открывается (`--no-index /dev/null`).
- Режим «незакоммиченное» — против `HEAD`, без коммитов — против пустого дерева (`git hash-object -t tree /dev/null`). Базовой ветки нет, merge-base не найден или имя начинается с `-` → показ незакоммиченного с пометкой «базовая ветка не найдена».
- Базовая ветка: worktree-задача — её `base`; задача в основной папке — `Project.lastBaseBranch ?? defaultBranch()`.
- `⌥B`, `↑/↓`, `↩` перехватываются только при активной diff-вкладке (фокус не в поле ввода); иначе уходят в терминал (`⌥B` — слово назад в zsh).
- *Заменено HD-081 (Helix убран, открытие — во вкладке Monaco).* Helix: открытие в существующем листе — только если редактор `hx`/`helix` (первое слово команды). Путь в командной строке Helix: `'…'`, если нет `'`; иначе `` `…` ``, если нет `` ` ``; иначе `"…"`, если нет `"`, `%` и `\` (внутри `"…"` Helix читает `\` как экранирование); иначе — новая вкладка (argv квотируется shell'ом); управляющие символы (перевод строки) в пути — тоже новая вкладка. После `Esc` остаток отправляется через 50 мс (одноразово): иначе `Esc :` в одном чтении терминал без kitty-протокола понимает как `Alt-:`. Текст команды — вставкой (bracketed paste) в промпт `:`, буквы не печатаются по одной (проверено на `hx` 25.07: режим вставки, открытый пикер, пути с пробелом, `'`, `` ` ``, `%{}`, `\`, кириллицей). Лист не запущен (вкладка не показывалась) — меняется `openFile`/`openLine` и вкладка активируется; лист завершился — то же + перезапуск. Лист запущен, но ещё ничего не вывел (Helix стартует и может не прочитать клавиши) — то же + перезапуск на новом файле (`// shortcut:` «вывел» = непустой текст экрана, у Ghostty нет колбэка вывода, а в `ghostty.h` нет запроса «активен альтернативный экран» (Helix работает в нём) — проверено; строка «Last login» тоже считается). Два клика в пределах 50 мс — команды обоих уходят в Helix, побеждает последний `:open`. Клавиши в editor-лист неактивной вкладки допустимы: вкладка сначала активируется. Другой редактор (`nvim` …) — всегда новая вкладка (`nvim +N path`).
- `Leaf.openLine: Int?` рядом с `openFile` (восстановление открывает файл на той же строке; старые файлы читаются).
- Бейджи: `?` цветом A, `R` цветом M, `U` цветом D. Строки дерева и списка — системный шрифт 13 (`row`); моно — в diff (12.5) и заголовке diff.
- Diff-вкладка — по одной на задачу, в памяти `AppState`; ⌘1…9 считают только обычные вкладки; активная diff-вкладка не меняет `activeTabId` (после перезапуска — прежняя вкладка).
- FSEvents и загрузка идут и при скрытом инспекторе, пока показана diff-вкладка (та же выбранная задача, окно видно и не перекрыто): diff обновляется вживую. При активной diff-вкладке ⌘D/⌘⇧D и пункты «Разделить» контекстного меню вкладки игнорируются (сплит скрытой вкладки). Выбранная строка diff хранится по id (вид + текст + номер повтора), а не по индексу: переживает вставку строк выше, исчезла (⌥B, правка) — выбор снимается.
- Сегмент и режим `⌥B` — в памяти (не сохраняются); ширина инспектора — `WorkspaceState.inspectorWidth` (220, 180–480).
- Отвергнуто: tree-sitter; libgit2; опрос; отмена на каждое событие; глобальный `⌥B`; печать команды Helix посимвольно; `git add -N` для счётчиков untracked (запись в index); хранение diff-вкладки в модели.
