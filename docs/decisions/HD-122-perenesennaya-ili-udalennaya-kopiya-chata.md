# HD-122 — 2026-10-31 — Перенесённая или удалённая копия чата: проверка по списку worktree, плашка «Обновить путь»; листы открываются с уже известным ответом git (баги владельца; дополняет HD-121).

(1) Копию перенесли (`git worktree move`, его сделал агент), а старая папка осталась внутри проекта — git из неё отвечает как папка проекта: тулбар показывал ветку папки проекта, инспектор — «Нет файлов в git». Теперь путь копии сверяется с `git worktree list --porcelain` проекта (одна команда на проект; при выборе чата, по `done` агента, при возврате в окно): путь — не корень зарегистрированной копии (или помечен `prunable`, папку удалили) → ветку, файлы и изменения чат не показывает (ветка в тулбаре — сохранённая, переключатель ветки не действует). Ветка чата открыта в другой копии → над терминалами строка 28 «Копия перенесена в … · Обновить путь»: путь чата, cwd вкладок и пути открытых файлов переходят в новую папку (идущие терминалы остаются где были; новые вкладки и восстановление — в новой). Не найдена → «Копия не найдена: …», без действия. Папку проекта как новое место не предлагаем. Локальная копия до первой проверки не читается (миллисекунды); удалённая — читается как раньше, пока проверка не ответит (`shortcut`, без ssh перед каждой загрузкой). Чтобы вкладка claude продолжила тот же разговор (слово владельца): по нажатию «Обновить путь» вкладка только запоминает, где записан её разговор (`relinkedFrom`, в состоянии), — claude в ней обычно ещё работает и дописывает старую запись, копия в момент нажатия потеряла бы эти ходы. Копия делается при следующем запуске вкладки, который продолжает разговор (восстановление, перезапуск; запуск без продолжения ничего не пишет и снимает отметку), до выбора «продолжить или начать», вне главного потока — вкладка ждёт со строкой «Переношу разговор в новую папку…» и запускается сама: запись ищется как у claude (`projects/*/<id>.jsonl`, сначала папка старого cwd — так находится и папка проекта по симлинку), копируется в `projects/<новая папка>/<id>.jsonl` (имя — как у claude: всё, кроме латиницы и цифр, → `-`); в копии меняется только верхнеуровневый `cwd`, равный старому пути или первому `cwd` самой записи, остальные строки — байт в байт; папка `<id>/` (субагенты) копируется как есть, права 0600 сохраняются; потом отметка снимается. Копию Hangar помечает рядом (`.<id>.hangar-copy`: размеры оригинала и копии) и обновляет её, пока оригинал растёт, а claude в копию не писал; чужую запись (claude сам создал файл) не трогает никогда. Остатки прерванной копии (`.<id>.jsonl.hangar-tmp-*`) удаляются перед следующей. Имя папки длиннее 200 (claude сокращает его с хешем) — без копии. Это единственная запись Hangar в `~/.claude/projects`: только после явного нажатия, только копия — оригинал не трогается и не удаляется; об этом говорит тултип кнопки («Чат Claude продолжится в новой папке…»). Первая копия не заменяет файл, появившийся за это время (`link`, не `rename`). Не удалось — вкладка, как раньше, начинает новый разговор с пометкой (HD-119). Проект на сервере — без копии (`shortcut`). При восстановлении запись ищется сначала в папке, названной по текущему cwd, затем во всех (`transcriptChoice`, скрипт восстановления на сервере): старый оригинал в другой папке больше не делает разговор «чужим». Пути сравниваются через `realpath` (симлинки и регистр букв на диске: путь, набранный в другом регистре, — та же папка); на сервере путь, не совпавший со списком git, сверяется ещё раз после `pwd -P` там (симлинк — не «перенесена»). Запрос проверки во время идущей — повторяет её один раз после. (2) Лист «Новый чат» показывал «Где работать» и поля копии, пока git не ответил, и убирал их для папки не в git; лист проекта добавлял карточку копий позже. Теперь лист открывается после короткой проверки (`rev-parse` и HEAD папки — миллисекунды, не дольше 400 мс, иначе лист открывается и грузится как раньше; у проекта на сервере — последний определённый ответ сразу, он показывается, но не выключает копию; без ответа — загрузка как раньше; новый — для следующего раза), у папки не в git вместо выбора — «Папка не в git — отдельные копии недоступны» (в настройках проекта — то же, у репозитория без коммитов — «Нужен хотя бы один коммит»). Инспектор помнит, что папка чата не в git, и не мигает сегментами «Изменения · Git» при повторном выборе. **Отвергнуто:** `rev-parse --show-toplevel` из старой папки (папка внутри проекта отвечает проектом), автоматический перенос без нажатия (пользователь должен видеть, куда), показ полей «на время загрузки» (мигание).
