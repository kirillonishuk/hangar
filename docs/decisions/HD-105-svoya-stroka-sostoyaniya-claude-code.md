# HD-105 — 2026-10-29 — Своя строка состояния Claude Code (дополняет HD-012).

`hangar statusline` теперь сам рисует строку Hangar (рендер `renderStatusline` в `Workspace/Statusline.swift`, без сети, конфиг читается при каждом запуске; `rate_limits` по-прежнему уходят в приложение). Выбор в `config.toml`: `statusline = "hangar"` (по умолчанию) | `"user"` — исходная команда из `--then`, как раньше; `statusline_segments = ["model", "context", "5h", "week"]` по умолчанию, по желанию `"branch"`, `"effort"`; неизвестные имена пропускаются, порядок всегда по важности (порядок — с HD-110). Строка: одна, без переноса и ошибок, части без данных опускаются (до первого ответа нет `rate_limits` — нет и лимитов). Модель — `display_name` без «Claude » и «(…)», версия из `model.id`, если в имени её нет («Opus 5.5»); приглушённые метки «1M» (окно ≥ 1 млн), «fast», уровень усилия от `high` (с частью `effort` — всегда). Контекст и 5 ч — подпись + полоса 8 ячеек `━`/`─` + %, у 5 ч — приглушённое время до сброса («47m», «1h47m», «2d3h»); неделя — «wk N%», сброс только от 80 %. Цвета — SGR терминала: подписи и разделитель « │ » приглушены, значения нейтральны, жёлтый от 80 %, красный от 95 % (пороги лимитов Hangar). Цены нет. Язык — язык интерфейса Hangar: ru «контекст», «5ч», «нед», «1ч47м» (≈66 знаков против ≈60 у en — читаемость важнее; `ктх` отвергнуто; с HD-110 — всегда английский). Полоса `━─` — box drawing, Ghostty рисует их сам, ровно в ячейку (`▰▱` в моноширинных шрифтах нет). Настройки → Интеграции → «Строка состояния Claude»: «Hangar — везде» / «Ваша» (недоступна, если своей команды не было), «Пример» — тот же рендер на образце, ANSI → текст и полосы (линии во всю ячейку, как box drawing у Ghostty) в цветах терминала темы, фишки частей, список проектов. **Решение владельца «Hangar — везде» (заменяет вариант «уважать проект»):** (1) проекты со своей `statusLine` в `.claude/settings.json` (Claude предпочитает её пользовательской) — Hangar пишет в `.claude/settings.local.json` того же проекта и каждого worktree его живых сессий (у Claude этот файл главнее) `statusLine` с командой `<cli> statusline --project --then '<команда проекта>'` (остальные ключи объекта, напр. `padding`, копируются). У каждой команды Hangar в проекте есть метка (CLI её игнорирует): `--project` — ключ добавлен в существующий файл, `--project-new` — файл создал Hangar, `--project-wrapped` — своя `statusLine` уже была в local-файле и обёрнута (`--then`). Меняется и снимается только помеченное: написанная руками `hangar statusline --then …` остаётся пользовательской. Снимок `--then` обновляется при каждой синхронизации, если команда проекта изменилась. `<cli>` — CLI из `statusLine` пользовательских настроек Claude этой машины: нет там строки Hangar — ничего не пишется. Выбор «Ваша» снимает ровно добавленное: ключ удаляется (файл, созданный Hangar, — целиком, если в нём больше ничего нет), обёрнутая команда восстанавливается. Строка проекта изменилась или пропала — ключ Hangar следует за ней. Запись атомарная, с отказом, если файл изменился (`writeUserFile` / `remoteFileWriteScript`), и с пропуском файла только для чтения (в Настройках — «Файл только для чтения»); копии — не рядом (в репозитории их можно закоммитить вместе с секретами), а в `<каталог состояния Hangar>/backups/<sha256 пути>/` на Mac и `~/.hangar/backups/<…>/` на сервере, по 5 последних на файл (рядом — файл `source` с путём). Синхронизации идут по одной в порядке вызова (очередь `statuslineQueue`), выбор перечитывается после чтения файлов: быстрое «Hangar → Ваша» не оставляет перекрытие. Когда: запуск, подключение хоста, добавление проекта, новая или восстановленная сессия с worktree, смена выбора в Настройках; снимается — перед удалением проекта из Hangar, архивом или удалением worktree (иначе файл посчитался бы «под угрозой») и перед удалением интеграции Claude (на Mac и на сервере). Отсутствие файла на сервере — по `test -e`, а не по тексту ошибки `cat` (он локализован). Если `git check-ignore` говорит, что `settings.local.json` не игнорируется, файл всё равно пишется, а Настройки показывают предупреждение; список «Проекты» — только для сведения. В тестах синхронизация выключена (`AppState.statuslineSync`, включает лаунчер). (2) SSH: `hangar-remote` версии 5 шлёт payload строки как раньше и ждёт до 0,5 с (`nc` — 1 с) второй строки ответа `line:<текст>` — её рисует Mac тем же рендером и конфигом (`ControlServer(remote:statusline:)`, рендер на очереди сокета, конфиг читается с диска); нет ответа, сокета или выбрано «Ваша» (Mac не присылает `line:`) — выполняется `--then`. Старый скрипт v4 вторую строку игнорирует; v5 ставится автообновлением R7. **Отвергнуто:** уважать строку проекта (вариант 1 до решения владельца); рендер в приложении для локальных вкладок (CLI работает и без приложения); `▰▱`; цена и время «в 14:00».
