# HD-124 — 2026-10-31 — Файлы сервера в «<host> · терминал» (слово владельца; спека `specs/2026-10-31-remote-files-design.md`, макет `remote-files.html`; дополняет #64, меняет его «без мастера» и «без удалённой команды»).

Правый сайдбар простого входа на сервер показывает папку, где сейчас терминал, и принимает файлы («+» и перетаскивание из Finder). (1) **Папка:** Ghostty отдаёт OSC 7 встраивающему (`GHOSTTY_ACTION_PWD` → `TerminalSurfaceView.onPwd`), но только с локальным хостом — `file://<сервер>/…` отбрасывается. Поэтому вкладка запускает `ssh -t … -- <host> '/bin/sh -c <hostShellLoginScript>'` (одна строка без `!` — tcsh/csh): скрипт по `$SHELL` добавляет хук приглашения без установки и правки rc-файлов (zsh — временный ZDOTDIR, удаляется при чтении или сторожем через минуту; bash — экспортированный `PROMPT_COMMAND` и настоящий `bash -l`; fish — `-C`; иной шелл — `exec "$SHELL" -l` без хука, панель показывает домашнюю папку и «Папка терминала неизвестна»). **Никогда не хуже #64** (ревью): перед входом `ssh -G <host>` (≤ 2 с); есть `RemoteCommand` или `ssh -G` не ответил — вход без хука (без ответа — ровно #64); вход с хуком упал кодом 1…127 (не 255, не сигнал — Ctrl-C на пароле) в первые 20 с и до первого OSC 7 (tcsh, rbash, устройства) — лист дальше входит без хука; сразу заново — только если с запуска ничего не вводилось (иначе это мог быть свой `exit`, ↩ за пользователем); второе такое подозрение на хосте за запуск ставит `HostShell.noHook` (state.json, пока жив терминал сервера). Вход с удалённой командой пропускает MOTD и utmp; RHEL `/etc/bashrc` не ставит свой `PROMPT_COMMAND` заголовка. Хук печатает `ESC]7;kitty-shell-cwd://localhost$PWD BEL` (схема берёт путь как есть: пробелы и кириллица проверены вживую) и сохраняет `$?`. Путь — недоверенный (`validRemoteCwd`: абсолютный, ≤ 4096 байт, без управляющих), хранится на лист в памяти и идёт только аргументом команд на сервере. (2) **Соединение:** если у пользователя свой мастер (`ssh -G`: `controlmaster` ≠ false или `controlpath`), вкладка его не перекрывает — без нашего `-S`, панель работает через его `ControlPath` и никогда его не завершает; папка сокетов небезопасна (`SSHPaths.prepare` отказал) — вкладка без `-S` и без панели. Иначе сама вкладка — мастер своего сокета `<state>/ssh/hs-<fnv64(leaf)>` (`-S`, `ControlMaster=auto`, `ControlPersist=no`, без `BatchMode` — пароль и 2FA вводятся во вкладке как прежде; коды 0/255 и ↩ — как в #64). Сокет на лист, не на сервер: иначе закрытие первой вкладки ждало бы сессий второй. Фоновые команды — `sshBaseArgs` + `ProxyCommand=/usr/bin/false`: без живого мастера ssh не входит заново, а сразу отвечает 255 («нет соединения»); сокета нет — ssh не запускается вовсе. Закрытый лист: загрузка отменяется, мастеру — `-O exit`. (3) **Список:** POSIX-скрипт (`<тип><имя>\0`, без `ls`/GNU `find`), до 5000 записей и 1 MiB, папки сверху; обновление — на каждом приглашении (debounce 300 мс), после загрузки и кнопкой, только пока панель на экране и выбрана эта вкладка; без таймеров. Папки раскрываются по запросу. (4) **Загрузка** (по одному, общий прогресс, без scp/sftp-server — нужны `/bin/sh`, для папок `tar`): файл — через stdin ssh во временный `.<имя>.hangar-part` той же папки под `set -C` (подложенная ссылка не открывается), проверка размера, `mv`; новый файл — локальный режим под umask сервера, заменённый — свой прежний режим и владельца; ссылка на папку — конфликт видов, ссылка на файл заменяется сама; имя ≤ 242 байт. Папка — локальный `tar ./<имя>` (без `._`, xattr, ACL; владелец root) → `.<имя>.hangar-part/` → проверка числа файлов → `mv`; «Объединить» — `cp -R` в существующую папку (её режим и время, файлы сервера остаются); ссылки внутри не проходятся: на месте файла ссылка заменяется, на месте папки — конфликт видов; файлы считаются NUL-безопасно. Подсчёт файлов — вне главного потока. Занятое имя проверяется до и после передачи → вопрос «Пропустить · Заменить» (для папки — «Объединить»: совпадающие файлы заменяются, остальное на сервере остаётся; Hangar на сервере ничего не удаляет, кроме своих `.hangar-part`), флажок «Для всех», Esc останавливает пачку. Файл вместо папки и наоборот — ошибка. Отмена — процесс завершается, остаток `.hangar-part` удаляется отдельной командой. Перетаскивание во время загрузки — следующая пачка своего листа. (5) **Инспектор:** сегмент «Файлы · Поиск», заголовок 28 — путь, «Обновить», «Загрузить файлы»; панель следует за вкладкой (сплитом) в фокусе. Поиск — `git grep --no-index` через мастер листа (`shortcut:` без git на сервере — ошибка поиска; результаты не открываются — этап 2). Вопросы владельца: потеря приветствия сервера (MOTD) из-за удалённой команды — принята, без настройки; папка с тем же именем — объединение; несколько вкладок — за фокусом. **Отвергнуто:** установка хука в rc-файлы сервера; общий мастер хоста (#64); опрос папки; `scp`/`sftp` (sftp-server не везде); `file://localhost` с процентным кодированием (`kitty-shell-cwd` проще и принят Ghostty). **Отложено (этап 2):** скачивание в Finder, открытие в редакторе, контекстное меню.
