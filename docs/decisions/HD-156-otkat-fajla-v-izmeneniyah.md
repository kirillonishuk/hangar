# HD-156 — 2026-11-13 — Откат файла в «Изменениях» — исключение из §1 «Вне рамок» (слово владельца; дополняет HD-114)

Слово владельца: «блок оставляем, в изменениях можно файл откатить просто». Переключение ветки с незакоммиченными изменениями по-прежнему отклоняется (HD-114, правило (1) без изменений); вместо stash/commit, которых в приложении нет, — откат ненужных файлов. Подсказка под списком веток теперь: «Переключиться можно без изменений: лишнее откатите в «Изменениях».»

Что разрешено — откат одного файла к HEAD: пункт «Откатить изменения…» в меню строки «Изменений» (последний, `failedText`) и иконка в заголовке diff. Только у файла с незакоммиченными изменениями (в «Вся ветка» закоммиченные правки не откатываются: пункта нет). Остальное (stage, commit, push, stash, reset, откат блоков через git) по-прежнему вне рамок; стрелка Monaco «откатить блок» у diff — правка буфера, сохраняется как обычная правка (тултип иконки на неё указывает).

Как (модуль `Git`, `Git+Revert.swift`, `Git.revertFile`):
- Подтверждение — лист Hangar «Откатить «x»?» с тем, что пропадёт; ⌘↩ — «Откатить».
- Сначала снимок: файл (и старое имя у переименования) копируется `FileManager.copyItem` (ссылка остаётся ссылкой, права сохраняются) в `<state dir>/reverted/<время>-<id>/` с `backup.json`; отсутствующий путь записывается как отсутствующий. Снимки старше 7 дней удаляются при следующем откате (один листинг).
- Путь есть в HEAD (изменён, удалён, staged, конфликт, старое имя переименования) → `git restore --source=HEAD --staged --worktree -- :(literal)<path>`.
- Пути нет в HEAD (неотслеживаемый, новый staged, новое имя переименования) → из индекса `git rm --cached -f -q` (если он там), файл — в Корзину (`FileManager.trashItem`), никогда не удаляется.
- Папка на пути (подмодуль, вложенный checkout) или откатывать нечего → отказ до снимка, с текстом.
- Тост «Откачено: x · Вернуть» (тот же, что у архива, ~5 с). «Вернуть» кладёт байты снимка обратно; то, что лежит на пути (копия из HEAD), уходит в тот же каталог снимка (`replaced-…`), не удаляется. Сразу после отката запоминается отпечаток каждого пути (`lstat`: размер, mtime, inode, режим или «нет файла»); если к «Вернуть» он другой (агент успел записать файл или создать на его месте папку), «Вернуть» отказывает с текстом и путём снимка и ничего не трогает. Ошибка git или Корзины после снимка показывает путь снимка. Перед `git restore` и перед Корзиной путь сверяется с отпечатком, снятым при снимке: если агент записал файл в этом промежутке, откат этого пути отказывает («Файл записали заново, пока шёл откат…») и запись остаётся. Старое имя переименования берётся из `git status` в момент отката, а не из списка (в «Вся ветка» он строится от базы ветки) (против HEAD; старое имя вне подпапки проекта не берётся — путь от корня репозитория был бы чужим файлом); git запускается раннером проекта, так что защита `RevertError.remote` в модуле `Git` действует. Возвращается рабочая папка, не индекс: staged-правка вернётся неиндексированной, новый файл — неотслеживаемым.
- Несохранённый буфер этого файла во вкладке редактора или в diff → отказ «Нельзя откатить «x»»: сначала сохранить или отменить.
- Проект на сервере — пункт неактивен, тултип «На сервере откат недоступен». shortcut: только локально — `Runner` читает stdout как текст (снимок бинарного файла через ssh нужен байтовый канал) и Корзины на сервере нет; менять, когда попросят откат на сервере.

**Почему.** Блок переключения ветки защищает от потери данных, но без способа избавиться от лишних правок оставляет пользователя в тупике; откат одного файла со снимком и «Вернуть» — минимальная безопасная операция, как Discard Changes в VS Code / Xcode. **Отвергнуто:** stash и commit в приложении (это шире рамок §1); `git checkout -- <path>` (не трогает индекс и не умеет «нет в HEAD»); `rm` для неотслеживаемых (необратимо); откат без снимка (нет «Вернуть»).
