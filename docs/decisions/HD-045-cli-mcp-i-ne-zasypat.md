# HD-045 — 2026-10-22 — CLI, MCP и «не засыпать» (этап 5).

Решения контроллера: протокол запрос/ответ поверх NDJSON (версия, лимиты, проверка по методу, та же проверка uid); команды §7 с `--json`; ссылки — UUID, уникальный префикс или имя, неоднозначность — ошибка; разрушительное без `--yes`/`yes: true` — отказ (CLI — код 2; код 2 и у ошибок использования, в том числе `bad-params`/`confirm-required` от сервера, 1 — прочие ошибки); MCP — `hangar mcp`, JSON-RPC 2.0 руками (initialize, tools/list, tools/call, ping), тот же сокет; безопасность: любой локальный процесс пользователя может управлять Hangar и печатать в любой терминал (`tabs send`) и читать экран (`tabs read`, может содержать секреты) — это то же доверие, что у самого терминала, ограничение — uid сокета; `tabs send` в лист, ждущий разрешения, разрешён (так оркестратор отвечает на запрос); «не засыпать» — `PreventUserIdleSystemSleep`, снятие через 2 мин одноразовым таймером. Решения плана:
- Таблица `ControlMethod` — единственный источник параметров: проверка сервера, CLI и JSON Schema MCP. Лишние ключи — `bad-params` (опечатка в `yes` не проходит молча).
- Разрешение ссылок: полный UUID → точное имя (у проекта — и путь) → префикс id ≥ 4 символов без учёта регистра; на любом шаге > 1 совпадения — `ambiguous` со списком id; архивные задачи не находятся. Вкладки — только по id/префиксу (заголовки меняет терминал); `--tab` принимает id вкладки (→ её фокусный лист), id листа или id листа панели TERMINAL задачи (`tasks list` отдаёт его в `drawer`, если шелл панели уже создан; в ответах `tab` = `leaf` = этот id, как его `HANGAR_TAB_ID`; ещё не показанный после запуска шелл стартует скрыто, правила `not-started`/`failed` те же). Отдельного `--drawer --task` нет: меньше грамматики, та же ссылка.
- Задачи и вкладки из CLI/MCP не меняют выбранную задачу, активную вкладку и фокус; их surface запускаются сразу скрытыми (иначе агент с `--prompt` не стартовал бы до показа).
- `tasks create --worktree` — через тот же `NewTaskModel` без листа (fetch, проверка ветки, путь worktree как в UI); ошибка fetch — ошибка команды (кнопки «без fetch» нет); идёт в счёт «создаётся задача» для ⌘Q.
- `projects add <path> --host H` (MCP `host`, этап 6): хост проверяется `validSSHHost` в приложении (иначе `bad-params`), путь — серверный и с хостом не обязан быть абсолютным (`~` и относительный — от домашней папки сервера; CLI не склеивает его с локальным cwd). Тот же путь, что у листа «Удалённый проект»: `RemoteHosts.connect` (с проверкой сервера), `pwd -P` общей функцией `remoteRealPath`, `addRemoteProject`; тот же хост + реальный путь — `added: false`. Ничего не ставится: чего не хватает (причины предупреждения в сайдбаре: `git`/`tmux`, `hangar-remote`, клиент сокета, проброс) — список `warnings` в результате («tmux missing on server; open Hangar → Server to install»). Ошибки — фиксированные строки: «host not connected», «auth failed: run ssh H in Terminal, then retry», «unsupported login shell (csh/tcsh)» (`failed`), «folder not found on server» (`not-found`); после ошибки хост, которым не пользуется ни один проект, отпускается. Таймаут запроса с хостом — 60 с (ConnectTimeout 10 с + проверка до 30 с), как у `tasks create` свой.
- `tabs send`: текст — вставкой (bracketed paste, как HD-044), клавиши — настоящими нажатиями из фиксированного набора `SendKey`; сначала текст, потом клавиши. Невидимая, ещё не запускавшаяся вкладка сначала запускается; пока лист ничего не вывел (агент ещё не включил bracketed paste), ничего не пишется и ответ — `not-started` («tab is starting, retry»): CLI/MCP-вызывающий повторяет запрос позже. Лист, чей запуск не удался или невозможен (нет папки, в том числе при перезапуске — мёртвая surface тогда убирается, вставка в неё невозможна; Ghostty не создал surface), отвечает `failed` («tab could not start») — повтор не поможет. `tabs send` и `tabs read` решают по одному состоянию листа (`LeafState`: не запущен / запускается / работает / завершился / не запустился): `tabs read` тоже запускает ещё не запускавшуюся вкладку и отвечает `not-started` («tab is starting, retry») или `failed`, экран завершившегося листа читается; дальше — последние N строк (по умолчанию 100) без хвостовых пустых, ≤ 512 KiB.
- Строка с `method`, не прошедшая разбор запроса (нет/плохой `id`, `params` не объект, `method` не строка), получает ответ нового формата `{"id":null,"error":{"code":"bad-request",…}}`; прежний `{"ok":false}` — только для строк `event`/`usage`. Текст `tabs send` очищается от ESC и прочих управляющих C0 (кроме \t, \n, \r), чтобы не закрыть bracketed paste досрочно (`Esc`, `ctrl-c` — через `--key`); NUL — `bad-params`. Имя задачи не содержит U+2028/2029 и bidi-символов.
- Вывод CLI/MCP — английский, включая «Hangar is not running» (код `not-running`).
- MCP подключается командами `claude mcp add --scope user hangar -- '<cli>' mcp` и `codex mcp add hangar -- '<cli>' mcp`, которые настройки показывают с кнопкой «Скопировать»; Hangar сам конфиги агентов не правит (их формат и место — дело агента; для Codex не нужен редактор таблиц TOML).
- `Power` — отдельный модуль SwiftPM; имя блокировки меняется `IOPMAssertionSetProperty(kIOPMAssertionNameKey)`, при ошибке — пересоздание. ☕ — своя строка над «Настройками» в обоих режимах (полировка A: так нижняя группа не сдвигается при сворачивании; раньше в развёрнутом виде была кнопкой в строке «Настройки»), неактивный пункт «Не засыпать» в меню «…» удаляется.
- Отвергнуто: правка `~/.claude.json` и `config.toml` для MCP; MCP SDK; HTTP-транспорт; опрос статусов; печать текста посимвольными нажатиями.
