# HD-132 — 2026-11-05 — Удаление worktree не падает молча и видно, пока идёт (слово владельца; дополняет HD-057, HD-059, HD-131; DESIGN.md «Удаление копии»).

Сравнение (worktrunk `wt remove`, workmux, Conductor, Vibe Kanban; `git worktree remove` удаляет файлы по одному — медленно на `node_modules`, падает на locked и на подмодулях): общий быстрый и безопасный приём — переименовать папку рядом (атомарно на той же ФС), `git worktree prune`, удалить в фоне, остатки подчистить позже. Он у нас уже есть с HD-059; дочинено: (1) **locked worktree** — `prune` его пропускал, регистрация оставалась и ломала восстановление (`worktree add`: «missing but locked») и `branch -d`; теперь `worktree unlock` до переименования и в ветке «папки уже нет» (`Git.pruneWorktrees(unlocking:)`). (2) Фоновое `rm -rf` молча падало на папках только для чтения (кэш модулей Go) и `uchg`: теперь `deleteTombstone` при неудаче делает `chmod -R u+w`/`chflags -R nouchg` и пробует снова; удаляет только `*.hangar-removing`; лишнее надгробие, которое не убрать, останавливает перенос (раньше `mv` клал папку внутрь него). (3) **Процессы**: после остановки вкладок (локально) до 3 с ждём, пока процессы уйдут из папки (`lsof -d cwd`), чтобы после проверки никто не дописал; чужие (редактор, shell) только ждём, не убиваем. Удалённые tmux-убийства теперь ждутся для всех чатов группы (раньше только для последнего — `lastKills` перезаписывался). (4) **Ход и ошибки** — `AppState.worktreeRemovals`: строка «Удаление копии «x»…» со спиннером от начала проверки до конца фонового удаления (через 0,4 с), ошибка — там же с причиной, «Повторить» (переноса — с повторной проверкой, если архив не был «всё равно»; новые изменения оставляют папку и говорят «восстановите чат»; фонового удаления — просто ещё раз), «Показать в Finder», «×». Алерт «Не удалось удалить копию» у архива и «Удалить навсегда» заменён этой строкой; CLI/MCP по-прежнему получают ошибку. Надгробия, найденные при запуске/подключении хоста, удаляются так же видимо. (5) **Гонки**: восстановление, «Удалить навсегда» и новый архив той же папки ждут конца переноса (`untilMoved`), поэтому папка никогда не уезжает из-под только что восстановленного чата; восстановление во время проверки по-прежнему отменяет архив — теперь тихо (`ArchiveOutcome.undone`, а не ошибка «session not found»); перед переносом ещё раз проверяется, что в папке не открыт ни один чат. (6) **Кто делит папку** (`worktreeSharers`) — по месту, а не по строке: тот же хост, путь без `.`/`..`/лишних `/`, без учёта регистра; любой проект (один репозиторий добавлен дважды) и чаты «в папке проекта», чья папка — этот worktree. Ошибка в сторону «делит» только оставляет папку. «Удалить навсегда» не удаляет ветку, на которой стоит worktree другого чата проекта (`branchKeepers`: архивный восстановится на неё). Переход между ФС (worktree — точка монтирования) не обрабатывается: `mv` тогда копирует — shortcut, менять, если встретится. Отвергнуто: `git worktree remove --force` (медленно, полупапка при выходе — причина HD-059), убивать чужие процессы в папке, отдельный экран/панель «Удаления».
