# Чаты без проекта — спека

Макет: `docs/superpowers/mockups/free-chats.html` (PNG — `free-chats.png` рядом). Статус: дизайн утверждён владельцем 2026-10-31 по всем пунктам; кода нет. Обязательны: дизайн-система (`specs/2026-10-30-design-system.md`, #112), словарь (#113), имя чата (#116), восстановление разговора (#119), образец модели — терминал сервера (#64).

## 1. Что это
Чат без проекта — обычный чат Hangar (`HangarTask`), не привязанный к проекту: спросить агента о чём-то, что не касается репозитория. Восстановление, статусы агента, уведомления, переименование, закрепление работают как у остальных чатов. Агент — «Агент по умолчанию» из настроек (`HangarConfig.defaultAgent`). Все такие чаты работают в одной служебной папке `<папка состояния>/Chats` — по умолчанию `~/Library/Application Support/Hangar/Chats` (Hangar создаёт её сам, пустую, не git). Поэтому `/resume` внутри claude видит все чаты без проекта, а глобальный `~/.claude` действует как есть: Hangar в этой папке ничего не пишет (ни `.claude/`, ни статус-лайна #105 — у папки нет своего `statusLine`, значит работает пользовательский).

Только этот Mac: у серверов уже есть «<сервер> · терминал» (#64). CLI и MCP чатов без проекта не видят (как и терминалы серверов).

## 2. Модель (`Sources/Workspace`)

Новый файл `FreeChat.swift` по образцу `HostShell.swift`:

```swift
/// A chat with no project: its one task runs in the shared `chatsFolder`; kept out of `projects`.
public struct FreeChat: Codable, Identifiable, Equatable, Sendable {
    public var id: UUID          // == its task's `projectId` (one FreeChat ↔ one task, as HostShell)
    public var lastUsedAt: Date  // the sidebar's order and relative time
}
```

`WorkspaceState`:
- `public var freeChats: [FreeChat]` — ключ `freeChats`, `decodeIfPresent … ?? []` (старые файлы читаются).
- `public var chatsFolder: String = ""` — **не сохраняется** (нет в `CodingKeys`); `AppState` при загрузке ставит `StateStore.directory + "/Chats"`. Так debug-запуски с `HANGAR_STATE_DIR` получают свою папку, а настоящая не трогается. В `==` участвует (это нормально: значение одно на процесс).
- `cwd(for:)`: задача чата без проекта → `chatsFolder`.

Состояние чата — уже существующими полями задачи, новых флагов нет:

| Что | Где |
|---|---|
| открыт (агент запущен или запустится при показе) | `task.archived == false` |
| спит (агент остановлен, в списке тусклый) | `task.archived == true`, `archivedAt` — время закрытия; вкладки и `agentSessionId` листов **сохраняются** |
| имя, «Чат N» до первого запроса | `task.name`, `task.autoNamed` (#116) |
| закреплён / без уведомлений | `task.pinned` / `task.muted` |
| последнее использование | `FreeChat.lastUsedAt` |

Почему спящий = `archived`: перезапуск уже поднимает только незаархивированные задачи (`markRestored(state.tasks.filter { !$0.archived })`), восстановление из архива уже запускает агентов с продолжением своего разговора (#119), а все списки «живых» (входящие, Dock, «не спать») уже пропускают архив. В интерфейсе слово «архив» у чатов без проекта не появляется нигде (§9, конфликт 5).

Мутации в `FreeChat.swift` (расширение `WorkspaceState`), все с юнит-тестами:
- `addFreeChat(name:kind:autoNamed:at:) -> (task: UUID, tab: UUID)` — `FreeChat(lastUsedAt: at)`, задача с `projectId = chat.id`, одна вкладка агента `kind` с `cwd = chatsFolder`, выбрана.
- `freeChat(ofTask:) -> FreeChat?`, `isFreeChatTask(_:)` (как `isHostShellTask`).
- `touchFreeChat(taskId:at:)` — `lastUsedAt = at`.
- `sleepFreeChat(taskId:at:)` — `archived = true`, `archivedAt = at`, `archivedChanges = nil`; был выбран — выбор снимается (как у `archiveTask`, §4.4).
- `wakeFreeChat(taskId:)` — `restoreTask`.
- `removeFreeChat(taskId:)` — убирает `FreeChat` и задачу; был выбран — `selectedTaskId = nil`.
- `freeChatTasks: [HangarTask]` — все задачи чатов без проекта: закреплённые сначала, внутри групп — по `lastUsedAt` по убыванию, при равенстве — по `id`.
- `closeTab`: у чата без проекта закрытие **последней** вкладки не удаляет её, а усыпляет чат (`sleepFreeChat`) — иначе пропал бы `agentSessionId` и продолжать было бы нечего. Не последняя — закрывается как обычно.
- `addTab` / `split` в чате без проекта — как в обычном чате (терминал рядом с агентом разрешён), `cwd` — `chatsFolder`.

«Последнее использование» (`lastUsedAt`) ставится: при создании; при запросе своего агента вкладки — событие `.prompt` claude (тот же путь, что именует «Чат N», `AppState+Agents.swift`, условие `own`) и `.codexNotify` codex. **Не** ставится при выборе, пробуждении и наведении — иначе список прыгал бы от простого клика (правило «ничего не сдвигается»). Источник — состояние, не файлы транскриптов: сайдбар не читает диск.

## 3. Папка `Chats`
- Создаётся (`createDirectory(withIntermediateDirectories: true)`, права по умолчанию) перед каждым запуском листа с `cwd == chatsFolder`, перед показом инспектора чата и перед копированием файла в неё. Удалена пользователем — молча создаётся снова; ошибка создания — обычная ошибка запуска вкладки.
- Hangar её не чистит и не удаляет; «Убрать из списка» её не трогает.
- Папка общая, поэтому общее и то, что агент хранит «на папку»: разрешения «всегда разрешать» claude (`Chats/.claude/settings.local.json`) действуют во всех чатах без проекта, а `/resume` внутри любого из них показывает разговоры всех. Это принято вместе с одной папкой: разделять — значит папка на чат.
- Сборка без этой функции, открыв состояние, теряет `freeChats` при сохранении, но оставляет их задачи. При следующей загрузке задача с неизвестным `projectId`, все агенты которой работали в `chatsFolder`, снова становится чатом без проекта (спящим, если была закрыта); прочие такие задачи не трогаются (`adoptOrphanFreeChats`).
- Первый запуск claude в новой папке может спросить «Do you trust the files in this folder?» — это вопрос claude, Hangar его не отвечает за пользователя (ответ хранится в `~/.claude.json`, файлы пользователя не меняем).
- Проект, чья папка содержит `Chats` (проект в `~` или `~/Library`), не показывает в Истории разговоры из `Chats`: папка `Chats` считается «более глубоким проектом» в `inDeeperProject` (`SessionsModel.swift`).

## 4. Сайдбар (`SidebarView.swift`)

### 4.1 Секция «Чаты»
Порядок секций: **«Чаты»**, «Закреплённые», «Проекты», «Серверы». Заголовок — обычный `SectionHeader` (28, `caption` 600 `text3`, x 20) с «+» (иконка 14 в `control.small`, тултип «Новый чат без проекта — ⌥⌘N»). «+» сразу создаёт чат (§5), без листа.

Строки (сверху вниз):
1. Видимые чаты (≤ 7, `Theme.freeChatsVisible = 7` — счётчик, не размер): закреплённые, затем остальные по `lastUsedAt`. Открытый или выбранный чат виден **всегда**, даже если он восьмой и дальше: его статус нужен на виду (он встаёт на своё место в порядке, лишними уходят нижние спящие).
2. «Все чаты (N)…» — когда в списке есть хоть один чат; N — `freeChats.count` (открытые + спящие). Строка 28, без иконки, текст `body` `text2` на месте имени; клик → История с охватом «Чаты» (§6). Тултип «История — ⌘Y».

Пусто (нет ни одного чата): только заголовок «Чаты» с «+», видимым всегда (как у «Проектов» без проектов). Строк-заглушек и текста нет (§3.19 дизайн-системы).

Фильтр «только ждущие» (⌥⌘F): в секции — только чаты без проекта с вниманием, без «Все чаты (N)…»; таких нет — секция скрыта целиком.

### 4.3 Меню строки (правый клик и «⋯»)
Заголовок меню — имя чата. Пункты:
- открытый: «Переименовать» (F2) · «Закрепить» / «Открепить» · «Без уведомлений» | «Убрать из списка…» (деструктивный, `failedText`);
- спящий: «Переименовать» · «Закрепить» / «Открепить» | «Убрать из списка…».

Нет «Открыть в Finder», «Скопировать путь/порт/ссылку», «В архив»: папка общая и служебная, ссылки CLI на эти чаты не работают (§8).

«Убрать из списка…» → подтверждение (системный `ctx.confirm`): заголовок «Убрать «<имя>» из списка?», текст «Разговор останется у агента — его можно продолжить из Истории (⌘Y).», кнопки «Отмена» / «Убрать». После «Убрать»: открытый чат сначала останавливается (поверхности закрываются, как при усыплении), затем `removeFreeChat`. Транскрипт в `~/.claude` / `~/.codex` не трогается никогда.

### 4.4 Закрыть, проснуться
- Закрыть чат: ⌘W или «×» вкладки на **последней** вкладке, ⇧⌘W («Чат в архив» в палитре) на любой вкладке. Агенты останавливаются (тот же путь, что архив: поверхности закрываются), чат спит, строка остаётся в «Чатах» тусклой, выбор снимается (область — «Выберите чат или создайте новый»). Тоста «Вернуть» нет: строка и так на виду.
- Не последняя вкладка — ⌘W закрывает её как обычно.
- Клик по спящей строке (а также выбор в палитре, «Продолжить» в Истории): `wakeFreeChat` + выбор; агенты запускаются лениво при показе вкладки и продолжают свой разговор по #119 (`--resume <id>` при транскрипте в этой папке; транскрипта нет — `--session-id` того же id; записан в другой папке — новый разговор и строка «откройте из Истории»). `lastUsedAt` не меняется.
- `/resume` внутри claude переключает разговор вкладки — id отслеживают hooks из `--settings` (#119); имя чата не меняется.
- Запуск Hangar поднимает только открытые чаты; спящие остаются спящими.

Спящая плитка: монограмма `text3`, без точки. «+» и «Все чаты (N)…» в рейке нет (новый чат — ⌥⌘N, палитра). Тултип плитки — «Без проекта › <имя>». Пусто — ни разделителя, ни плиток.

### 4.6 Соседи по сайдбару
- «Закреплённые» (`pinnedTasks`) собираются из проектов — закреплённый чат без проекта остаётся наверху «Чатов» и во «Закреплённых» не дублируется (#106).
- Подвал: «Новый чат» (⌘N) по-прежнему создаёт чат **в проекте** (лист). ⌘N при выбранном чате без проекта открывает лист для последнего проекта (`presentNewTask(projectId: nil)`: у чата нет проекта → `projects.last`); проектов нет — «Добавить проект».
- Подсказка под проектом «Все чаты в архиве · История проекта ⌘Y · + Новый чат» — без изменений.
- ⇧⌘[ / ⇧⌘] (`orderedTasks`): сначала **открытые** видимые чаты без проекта в порядке секции, затем как сейчас. Спящие пропускаются (переход не будит).

## 5. Новый чат без проекта
«+» в «Чатах», ⌥⌘N, команда палитры «Новый чат без проекта», вторая кнопка пустого окна (§7):
1. папка `Chats` создаётся при необходимости;
2. `addFreeChat(name: «Чат N», kind: config.defaultAgent, autoNamed: true)` — N наименьший, не занятый **чатом без проекта** с таким именем (спящие считаются; тот же `chatName`, `existing` — имена задач `freeChatTasks`);
3. чат выбран, фокус в терминале агента; первый запрос claude даёт имя по #116 (≤ 40 знаков), у codex остаётся «Чат N» (как у чатов проекта, #116).

Агент не установлен — та же строка, что у обычной вкладки (`Процесс завершён с кодом N. Enter — перезапустить` и подсказка из проверки агента); ничего нового.

## 6. История (⌘Y)
Охват (`SessionsScope`) получает `.chats`. Сегмент в шапке показывается, когда есть удалённые проекты **или** хоть один чат без проекта; порядок: «Все · Чаты · Этот Mac · <серверы>». «Этот Mac» — по-прежнему локальные проекты (без «Чатов»).

Источник: папка `chatsFolder` сканируется тем же `History.local(folder:…)` (claude и codex), отдельно от проектов (`SessionsModel.load`: источник «чаты» до проектов этого Mac; `scan` получает либо проект, либо «чаты»). Разговор относится к чату без проекта по `agentSessionId` его листов:
- открытый чат держит разговор → состояние «открыт», действие «Перейти»;
- спящий чат держит → действие **«Продолжить»** (будит этот чат, §4.4), маркера состояния нет;
- никто не держит (чат убран из списка, `/resume` ушёл на другой, разговор начат в папке руками) → «Продолжить» создаёт **новый** чат без проекта с вкладкой продолжения (`addResumeTab`), имя — `sessionName(title)`, не `autoNamed`;
- спящий чат без разговора (в нём ничего не сказали) — своей строкой (иконка терминала, имя, «Продолжить» — будит).
Меню строки чата из списка — «Убрать из списка…» (тот же поток, §4.3) вместо «Удалить навсегда».

Охват «Все»: группа «Чаты» первой (как секция в сайдбаре), дальше проекты как сейчас (группы по проекту, #107).

Охват «Чаты» («Все чаты (N)…» открывает его сразу, `showSessionsView(scope: .chats)`):
- группы **по дню** последней активности: «Сегодня», «Вчера», «Суббота, 24 октября» (заглавная, §4 дизайн-системы; прошлый год — с годом), внутри — новые сверху; в группе все строки, без «Показать ещё»; сворачиваются по клику, как группы проектов;
- строка как сейчас (`row.large` 32): логотип агента, заголовок, вместо «проект · чат» — имя чата Hangar, если чат в списке (иначе пусто), «N сообщ.», время `mono` 11 (`HH:mm` — день уже в заголовке);
- чипы агентов остаются, чипы состояний («Открытые / В архиве / В истории») скрыты — открытые и спящие и так видны в сайдбаре, а слова «архив» у этих чатов нет;
- поиск — плейсхолдер «Название или текст разговора»; совпадение — по заголовку **или по тексту** разговора (§6.1);
- пусто — «Пока нет чатов без проекта» + кнопка «Новый чат без проекта» (§3.19); ничего не найдено — как сейчас «Ничего не найдено» + «Сбросить фильтры».

### 6.1 Поиск по тексту
Только в охвате «Чаты» (папка одна, локальная, небольшая; в проектах чтение всех транскриптов — дорого, там поиск остаётся по названию, ветке, проекту). Новый метод актора `History`: `matching(query:folder:claudeDir:codexDir:) async -> Set<String>` — id разговоров папки, в чьих сообщениях пользователя и ассистента (текстовые части; не инструменты, не служебные блоки) есть запрос без учёта регистра и диакритики (`localizedStandardContains`). Файл читается построчно целиком, кэша текста нет (память), отмена — между файлами. Вызов — через 250 мс после последнего изменения запроса, новый запрос отменяет прежний; пока идёт — строки по названию уже видны, совпадения по тексту добавляются в конце (без прыжков: список подменяется целиком, как пересканирование).

## 7. Главная область, тулбар, инспектор
- Тулбар: имя чата `body` 600, под ним «Без проекта» `caption` `text2`; кнопки ветки нет (папка не git; `head(of:)` и так nil — плюс явная проверка `isFreeChatTask`, как у терминала сервера).
- Везде, где у чата показывается проект — входящие («Без проекта › Чат 3 · claude»), баннер уведомления, строка палитры, тултип плитки рейки, — для чата без проекта пишется «Без проекта». Один помощник `app.placeName(of: task)`.
- Уведомления: настройки проекта (`ProjectNotifications`) нет → `.all`; «Без уведомлений» у самого чата (`muted`) работает как у всех.
- Инспектор: корень — `chatsFolder` (`InspectorWatch.root(of:)`). Папка не git → сегмент «Файлы · Поиск» (существующая логика `isGit`), «Изменений» и «Git» нет. FSEvents — как у любой видимой папки.
- Перетаскивание файла (из Finder) на список «Файлы» чата без проекта: файл **копируется** в `chatsFolder` (оригинал не трогается; имя занято (в том числе висячей ссылкой) — «имя 2.ext», «имя 3.ext»…; папки копируются целиком; символические ссылки — как есть, `FileManager.copyItem`). После копии в ввод агента активной вкладки (если её фокусный лист — claude или codex) вставляется упоминание файла и пробел, без Enter — «спросить о файле»: так, как его пишет само поле ввода агента — claude `@имя` или `@"имя с пробелами"` (его разбор промпта понимает обе формы), codex — путь, в кавычках при пробелах (так вставляет его всплывающий список `@`); `"` в имени копии заменяется на `'`, иначе кавычки не закрыть. Подсветка цели — рамка `accent` + кольцо .25 вокруг списка (состояние фокуса, §2.8). У чатов проекта перетаскивания нет (не просили).
- Пустое окно без проектов («Добавьте папку проекта, чтобы начать»): кнопки «Добавить проект» (главная) и «Новый чат без проекта» (обычная). Условие «совсем пусто» (`SplitView`): нет проектов, терминалов серверов **и** чатов без проекта.

## 8. Клавиши, палитра, CLI
- `Shortcut.newFreeChat`: ⌥⌘N — `([.command, .option], 45, "N")` (keyCode 45, работает в русской раскладке); в `allCases` и `paletteCommands` сразу после `.newTask`. Свободна: в таблице клавиш ⌥⌘N нет, Monaco глобальные клавиши Hangar не получает (DESIGN.md).

## 9. Конфликты с принятыми решениями и как решены
1. **§3.3 дизайн-системы** («сверху вниз: Проекты, Серверы, подвал») — добавляется «Чаты» первой секцией. Правка §3.3 в том же PR, что и код.
2. **§3.1** («кнопка ветки — всегда, для любого чата») — у чата без проекта её нет: папка не git (так уже ведут себя не-git проекты и терминал сервера). Уточнение §3.1.
3. **#107 / sessions-v2** («заголовков дней нет, группы по проекту») — в охвате «Чаты» группы по дню (слово владельца); в «Все» и прочих охватах — по проекту, как было. Уточнение §3.17.
4. **#106** («одна информация — в одном месте») и секция «Закреплённые» — закреплённый чат без проекта не дублируется во «Закреплённых».
5. **Глоссарий «в архив»** (= убрать чат из списка) — у чатов без проекта «закрыть» оставляет чат в списке. Решение: в коде спящий = `archived`, в интерфейсе слова «архив» у них нет: нет пункта меню «В архив», нет тоста, в Истории нет маркера «в архиве». ⇧⌘W (его название в палитре — «Чат в архив») для такого чата усыпляет — команда одна на все чаты, переименовывать её ради этого случая не стоит.
6. **#119 и «транскрипта нет»** — утверждённый текст говорил «новый разговор со строкой #119». По #119 строка выводится, только когда разговор записан в другой папке или вкладка не была привязана; нет транскрипта = в чате ничего не сказали → `--session-id` того же id молча. Решение: как в #119, без новой строки (Hangar не отличит «ничего не сказали» от «файл удалён руками»).
7. **#64** (терминал сервера — вне `projects`) — та же модель, но чат без проекта виден в палитре, ⇧⌘[/] и Истории (терминал сервера — нет): это полноценный чат агента, а не ssh-вход.
8. **Энергия (AGENTS.md, «ноль таймеров»)** — относительное время в строках без таймера (§4.2).
9. **Файлы пользователя** — в `~/.claude` / `~/.codex` ничего не пишется и не удаляется; «Убрать из списка» не трогает транскрипт; доверие папке claude спрашивает сам.

Решение для `docs/decisions.md` пишется в PR с кодом — следующим свободным номером на момент merge (сейчас занято до #123, #122 — в ветке `fix/moved-worktree`), со ссылкой на эту спеку.
