# HD-048 — 2026-10-23 — Название задачи, которое уже имя ветки, становится веткой как есть.

В проектах с ветками вида `<type>/JS-XXXXXX` slug (`feat/JS-13333` → `feat-js-13333`) мешал пушить из worktree в ветку того же имени. Теперь «Новая ветка» по умолчанию — само название (обрезанное), если в нём есть `/` (шаблон `<type>/JS-…`; одно слово вроде `Refactor` по-прежнему даёт slug `refactor`), первый компонент — не имя remote (`origin/x` дал бы локальную ветку, неоднозначную с `origin/x`), ни одна ветка (локальная или удалённая без имени remote, без учёта регистра) не является `/`-префиксом названия и название не является `/`-префиксом ветки (`release/1.2` рядом с `release` невозможен: ref — либо файл, либо папка) и оно состоит только из `[A-Za-z0-9._/-]` и проходит правила `git check-ref-format --branch` (нет `..`, пустых компонентов и `//`, `/` по краям, компонентов с `.` в начале или `.lock` в конце, `.` в конце, `-` в начале, не `HEAD`); иначе — slug, как раньше (HD-042). Проверка — чистый Swift (`isBranchName`, на каждое нажатие); финальная проверка перед созданием — по-прежнему `git check-ref-format`. Папка worktree — всегда slug (`…worktrees/feat-js-13333`). Суффикс `-2`, `-3`… — при занятой ветке без учёта регистра (refs на диске macOS регистронезависимы) или занятой папке, так что `feat/js-13333` рядом с `feat/JS-13333` получает `feat/js-13333-2`. То же правило в `tasks.create` CLI/MCP (общий `NewTaskModel`). Кириллица, `!`, `@` и прочее, что git допускает, остаются slug-ом: ветки, неудобные в шелле. Push в Hangar не добавляется (§1). Отвергнуто: вызов git на каждое нажатие; настройка шаблона ветки по проекту.
