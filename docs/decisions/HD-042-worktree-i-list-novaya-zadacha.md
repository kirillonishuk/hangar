# HD-042 — 2026-10-19 — Worktree и лист «Новая задача» (этап 2).

Модуль `Git` поверх `Exec.Runner` (struct с замыканием, не протокол; `ssh` — этап 6). Путь worktree: `<родитель проекта>/<папка проекта>.worktrees/<slug ветки>`, настраивается в настройках проекта («Папка worktree»). Slug: lowercase, транслит кириллицы по таблице (Task 3), пробел и `/` → `-`, схлопывание `-`, пусто → `task`. Новая ветка создаётся с `--no-track` (не тянет upstream базы, `git push` не уйдёт в базовую ветку). Переключатель Worktree запоминается по проекту (`Project.worktreeByDefault`); базовая ветка — `Project.lastBaseBranch`, её же правит «Ветка по умолчанию» в настройках проекта (`nil` = из `origin/HEAD`). «Обновлено N мин назад» — по mtime `FETCH_HEAD` (учитывает и fetch из терминала, ничего не хранит). Fetch — при открытии листа (фоном), по ↻ и перед созданием, если в этом открытии успешного fetch ещё не было; только remote базовой ветки (для локальной базы — `origin`, нет remote — пропуск). Архив worktree не трогает (заменено HD-057: архив удаляет worktree, ветка остаётся). «Удалить навсегда» — галочка «Также удалить worktree и ветку» (выкл.); грязный worktree или файлы вне git (ignored: `.env`, локальные БД; в окне до 5 имён) — второе подтверждение, `--force` только после него; ветка — `branch -d` (не слита — сообщение, ветка остаётся). «Удалить из Hangar» worktree не трогает. Не-git проект — строк worktree нет. Почему: решения контроллера плана этапа 2. Исключение из «только `-d`»: уборка после неудавшегося `worktree add` делает `branch -D` лишь для ветки, которую только что создали. Отвергнуто: протокол `GitRunner`, моки вывода git, `-D` при удалении задачи, удаление worktree при архивации, опрос fetch.
