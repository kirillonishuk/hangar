# HD-169 — 2026-11-18 — Отдельная копия на существующей ветке: локальной или только на remote (просьба владельца; расширяет HD-042, HD-005, HD-153).

Владельцу часто надо доделать ветку коллеги, которая есть только на remote (`origin/JS-14914`). «Новый чат» умел только новую ветку от базы, а имя существующей отклонял («ветка уже существует», HD-042): приходилось делать свою ветку и потом просить агента пушить в чужую.

Теперь «Ветка копии» в «Новом чате» может назвать существующую ветку, и копия встаёт на неё саму:
- **Как выбрать.** Справа от поля ▾ (и ↓ в поле) — то же меню веток, что у базы (remote, затем локальные; поиск, ↑/↓, ↩), с поиском, заполненным набранным. Выбор кладёт в поле имя локальной ветки (`origin/x` → `x`, если это та же ветка). Набрать имя руками — то же самое. Отдельного переключателя «новая / существующая» нет: режим следует из имени.
- **Как понимается имя** (`classifyCopyBranch`, модуль Git): `origin/x` — ветка remote, а если есть локальная `x` — она; голое `x` — локальная ветка, иначе ветка remote с этим именем (сначала `origin`); иначе — новая.
- **git по случаям.** Новая — как раньше, `git worktree add --no-track -b x <путь> <база>` (HD-042). Локальная, нигде не открытая, — `git worktree add <путь> x` (как восстановление из архива, HD-057). Только на remote — `git worktree add --track -b x <путь> origin/x` (явно, не DWIM; как `git switch --track` у переключателя, HD-114): `git push`/`git pull` агента идут в `origin/x`. Hangar сам ничего не пушит и не тянет (спека §1).
- **Ветка открыта в другой папке** (папка проекта или другая копия, по `git worktree list`; перед созданием список перечитывается) — ошибка под полем теми же словами, что у переключателя: «Ветка «x» открыта в чате «…»…» или «…в другой папке: <путь>»; git не вызывается, «Создать чат» неактивна.
- **Строка под полем.** Для существующей ветки «от `база` ▾» заменяется на «существующая ветка · `origin/x`» (локальная — «существующая локальная ветка»), ↻ остаётся; высота строки та же (HD-153, без сдвигов). База скрыта, но остаётся базой чата для «вся ветка» и ahead/behind.
- **Всё прочее без изменений:** fetch перед созданием (HD-005; ветка свежая), место копии (HD-121), копирование игнорируемых файлов и команда подготовки (HD-058, HD-127), архив удаляет копию и оставляет ветку (HD-057), восстановление. CLI/MCP `sessions create` по-прежнему делает новую ветку из названия: предложенное имя обходит занятые.

**Ограничение:** ветка на другом remote, чем база, отдельно не fetch-ится (fetch — remote базы). **Отвергнуто:** переключатель «новая / существующая ветка» — лишний контрол, режим и так виден по имени; меню веток на каждое нажатие клавиши — меню забирает фокус у поля (как в HD-164).
