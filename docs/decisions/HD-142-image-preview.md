# HD-142 — 2026-11-05 — Картинки в diff и редакторе вместо «Бинарный файл»

Бинарный файл, который читает ImageIO (png, jpeg, gif, webp, heic, tiff, bmp, ico — решает заголовок файла, не расширение), показывается картинкой. Diff: добавлен — новая, удалён — старая, изменён — обе с подписями «Было» / «Стало» и размером в пикселях; старая сторона — `git cat-file blob <база>:<путь>` (та же база, что у текстового diff; у коммита — его родитель), новая — рабочий файл или файл коммита. Редактор (открытие из дерева, ⌘P): картинка поверх сообщения Monaco, с размером в пикселях и файла, только просмотр. Чтение и декодирование — вне главного потока, в копию не больше 4096 px по длинной стороне (`CGImageSourceCreateThumbnailAtIndex`; подпись — настоящий размер), байты файла после декодирования не хранятся; больше 50 МБ — прежнее сообщение. Файл переписан на диске — картинка обновляется (diff — при каждой перезагрузке diff по размеру и mtime файла; редактор — тем же FSEvents-наблюдателем, что и текст). Вписывается в панель, не крупнее своего размера, фон `bg0` (без шахматки).

**Почему.** Пользователь открывал изменённые макеты (`*.png`) и видел только «Бинарный файл»; картинки — частый артефакт агентов (рендеры макетов, скриншоты). Системный ImageIO уже умеет все нужные растровые форматы — новой зависимости нет; в отличие от `NSImage(data:)` он декодирует сразу и в уменьшенную копию (две 50-МБ картинки «Было/Стало» не держат сотни МБ растра) и узнаёт не-картинку по заголовку, не читая весь файл.

**Ограничение (shortcut).** Только локальные проекты: `Runner` и `EditorIO.remote` отдают stdout строкой UTF-8, байты картинки на сервере теряются; для проекта на сервере остаётся «Бинарный файл». Менять, когда понадобится — дать раннеру байтовый канал. PDF не показывается (ImageIO его не читает), svg — текст и открывается как текст.

**Отвергнуто:** показ картинки внутри Monaco (data-URL в странице) — гонять до 50 МБ base64 через мост ради просмотра; шахматка под прозрачным — не просили; выбор по расширению — не ловит heic без расширения и ошибается на битых файлах; `NSImage(data:)` — ленивое декодирование на главном потоке при первой отрисовке и полный растр в памяти.
