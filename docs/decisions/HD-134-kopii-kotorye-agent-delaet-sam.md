# HD-134 — 2026-11-05 — Копии, которые агент делает сам: Hangar идёт за агентом и только предлагает (слово владельца после случая в проекте пользователя; дополняет HD-122, HD-058, HD-121).

Агент по правилу проекта («в общей папке — создай worktree и `EnterWorktree`») сделал `git worktree add .claude/worktrees/aut-1076` из чата «в папке проекта» и работал там, а Hangar показывал ветку, изменения и файлы папки проекта; в другом чате агент сделал `git branch -m`, и восстановление из архива падало с «ветки нет». Это законный способ работы — Hangar к нему приспосабливается и **никогда сам** не меняет файлы проекта, `.gitignore`, `.git/info/exclude`, хуки, скиллы и не переносит/удаляет копии; всё — только по нажатию. (1) **За агентом.** `cwd` из хуков Claude (SessionStart, UserPromptSubmit, Stop и др.) и из `notify` Codex (`agent-turn-complete` несёт `cwd`) — граница доверия: только абсолютный путь ≤ 4096 байт без управляющих символов; берётся только от агента самой вкладки (его хуки с pid или события его разговора; вложенный `claude -p` не в счёт). Новый cwd — один `git worktree list` проекта (как проверки HD-122, без опросов); cwd внутри **другой** зарегистрированной копии того же репозитория (её корень или подпапка; самая глубокая копия; не папка проекта и не `prunable`) — над терминалами строка «Агент работает в копии <путь> (ветка X) · Сделать чатом этой копии · Скрыть». Подпапка своей копии/папки, папка проекта, путь вне репозитория — без строки. «Сделать чатом этой копии» — чат становится чатом копии по механике «Обновить путь» (HD-122): режим worktree с путём и веткой копии (база — своя у чата копии, иначе база проекта / ветка папки проекта), cwd вкладок и пути файлов переходят, у вкладок claude запоминается `relinkedFrom` — разговор копируется при следующем запуске, восстановление после перезапуска стартует в копии; файлы и git не трогаются, идущие терминалы остаются. Копия без ветки (detached) — кнопка неактивна с причиной. «Скрыть» — для этого чата и этой копии до выхода (`shortcut`: после перезапуска агент стартует в папке чата). (2) **Ветка — из git.** При каждой проверке HD-122 у копии на месте ветка чата сверяется со списком git; другая (агент сделал `branch -m` / `checkout -b`, или ветку переключили в Hangar) — записывается. При архиве ветка берётся у git перед удалением папки; при восстановлении копия, оставшаяся зарегистрированной, ищется по пути, а не по старому имени ветки. (3) **Копия внутри проекта, не скрытая от git** (`git check-ignore`, одна команда при изменении списка): в настройках проекта строка «Копии внутри проекта не скрыты от git — попадают в git add -A, поиск и форматтеры: …», под ней точная строка для `.git/info/exclude` и кнопка «Скрыть от git локально» (в меню «Копии без чата» — пункт с подтверждением, где строки показаны). Строка — родительская папка копии от корня (`/.claude/worktrees/`, чтобы следующая копия агента тоже не всплыла), у копии в корне — сама папка; дописывается один раз, файл без конечного перевода строки не склеивается. Сохранить папку копий внутри проекта HD-121 и так не даёт — отдельной проверки при сохранении нет. Дерево файлов не показывает вложенные копии того же репозитория (git отдаёт их одной строкой `dir/` — раньше это был «файл» без содержимого), поиск rg их пропускает (`--glob=!<путь>`; git grep пропускает сам): это отдельные checkouts, у них свой чат. (4) **Копии без чата.** Под раскрытым проектом, если есть зарегистрированные копии, которых нет ни у одного чата (открытого или в архиве), — строка «Копии без чата · N» (как «Архив · N», HD-125, иконка ветки); клик — меню: у каждой копии путь и ветка, «Открыть чатом» (новый чат в режиме копии, без git-команд и без подготовки HD-058) и «Удалить копию…» (подтверждение, затем проверки архива — незакоммиченное и ignored-файлы — и общее удаление HD-059, HD-132 — с ходом и «Повторить»; ветка остаётся; `locked` (заблокировал агент) — неактивно). Список берётся при первом показе проекта и при проверках HD-122 (выбор чата, `done` агента, возврат в окно). **Отвергнуто:** правка `.gitignore`/`info/exclude`/скиллов или перенос копий автоматически (владелец: не менять, как работают проекты и агенты); опрос `cwd` процессов (энергия; хуки уже приходят); блокирующий лист вместо строки; показывать вложенные копии в дереве как папки (это другой checkout со своей веткой — путает).
