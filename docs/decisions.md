# Журнал решений

Каждое решение — отдельный файл `docs/decisions/HD-NNN-<slug>.md` (HD = Hangar Decision; не путать с PR/issue `#N`). Ссылка на решение — `HD-NNN`.

Формат: дата — решение. **Почему.** **Отвергнуто.** Решённое не переоткрывается без новой информации; новое решение — новая запись (старую пометить «заменено HD-NNN»).

Как добавить решение:
- Новый файл `docs/decisions/HD-NNN-<slug>.md`: NNN — следующий свободный номер (3 цифры), slug — 1–5 слов латиницей через `-`. Первая строка — `# HD-NNN — <дата> — <заголовок>`, дальше текст решения. Больше ничего не правится: общего списка нет.
- Номер брать по `origin/main` прямо перед push: `git fetch && git ls-tree --name-only origin/main docs/decisions/ | grep -o 'HD-[0-9]*' | sort | tail -1`. Занят — взять следующий и переименовать свой файл (и ссылки на него). Чужие номера и файлы не менять (поправка к чужому решению — новое решение со ссылкой).
- Проверка: `scripts/check-decisions.sh` (в CI).

Список решений — `docs/decisions/` (по номеру). Сводка «номер — дата — заголовок — путь»: `scripts/decisions-index.sh` (печатает, в репозиторий не коммитится).
