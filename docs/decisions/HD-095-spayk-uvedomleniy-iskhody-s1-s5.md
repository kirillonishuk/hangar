Источники — [hooks](https://code.claude.com/docs/en/hooks), [permissions](https://code.claude.com/docs/en/permissions), [mcp](https://code.claude.com/docs/en/mcp), [interactive-mode](https://code.claude.com/docs/en/interactive-mode), прочитаны 2026-10-27; настоящий `claude` не запускали. **S1 = A (владелец: добавить хук `PermissionRequest` и `StopFailure` по всем ошибкам).** Факты: у `Notification` только `message`, `title`, `notification_type` (`permission_prompt`, `idle_prompt`, `elicitation_dialog`, `elicitation_url_dialog`, …), инструмента нет; `PermissionRequest` получает `tool_name`, `tool_input` (у Bash `command`, `description`), `permission_mode`, `permission_suggestions`, для MCP — `mcp_server`, без `tool_use_id`; срабатывает, когда Claude Code собирается спросить разрешение или иначе молча отказал бы (фон без диалога), и не срабатывает на сетевой запрос песочницы (для него — `permission_prompt`); `PermissionDenied` — только отказ классификатора auto-режима; `Stop` — текст в `last_assistant_message`; `StopFailure` — `error` (`rate_limit`, `overloaded`, `authentication_failed`, `oauth_org_not_allowed`, `account_on_hold`, `billing_error`, `invalid_request`, `model_not_found`, `server_error`, `max_output_tokens`, `cloud_credential_error`, `unknown`), опциональные `error_details` и `last_assistant_message` (там строка ошибки API, не ответ Claude). Это меняет `claudeHooks`; вместо переустановки из Настроек с diff (HD-015) интеграция Claude обновляется автоматически и только добавлением (ruling R1, задача 2b): добавляются лишь недостающие хуки Hangar, пользовательские не трогаются и не меняются, перед записью — резервная копия с отметкой времени, идемпотентно; если интеграцию не ставили — ничего, свежая установка по-прежнему через согласие в Настройках; локально и на каждом удалённом хосте, где она стоит. Цена ошибки — запись в `~/.claude` без диалога на каждое изменение; владелец это разрешил. **S2 = `[.enter]`** (`[SendKey.enter]`): диалог показывает «Yes» первым, в подвале «Esc — отмена, Tab — комментарий»; документация не называет клавишу ответа и подсвеченный по умолчанию пункт явно — проверить владельцу вживую. Цифру через `sendText` не используем (вставка, не нажатие). **S3 = T-no:** документация Apple для entitlement `com.apple.developer.usernotifications.time-sensitive` без JS не читается (страница 404/пустая), поэтому проверено опытом в `/tmp` (не Hangar): пустой бинарник в `.app`, подпись `codesign -s -` с этим entitlement — `codesign -d --entitlements -` его показывает, но процесс убит (код 137, `open` — «Launchd job spawn failed», 163); тот же `.app` без entitlement запускается.
