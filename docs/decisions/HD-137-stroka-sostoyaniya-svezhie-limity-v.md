# HD-137 — 2026-11-05 — Строка состояния: свежие лимиты в каждом чате и только внутри Hangar (слово владельца; дополняет HD-012, HD-043, HD-105, HD-111).

(1) **Свежие лимиты.** `rate_limits` у каждой сессии Claude — из её последнего ответа, поэтому чат в простое показывал старые 5 ч (7 % при 13 % в соседнем). Теперь сокет приложения держит снимок лимитов Claude (`UsageSnapshot`, один на основной сокет и сокеты всех хостов) и сливает в него каждый тик: на окно новее то, у кого сброс позже больше чем на 90 с (иначе это одно окно с дрожанием `resets_at`), в одном окне — больший процент (в окне расход только растёт); окно снимка с прошедшим сбросом выбрасывается. Ответ на `usage` — `{"ok":true,"windows":[…]}` со слитыми окнами; `hangar statusline` (строка Hangar) ждёт его до 0,3 с и рисует новейшее из ответа и stdin; приложения нет или не ответило — свои `rate_limits` из stdin, как раньше. Пустой `usage` (чат до первого ответа) только спрашивает и в приложение не идёт — такой чат тоже показывает лимиты. В приложение (`UsageBoard`) уходят слитые окна, поэтому тик простаивающего чата больше не понижает лимиты в сайдбаре. SSH: Mac рисует `line:` тем же слитым снимком — протокол `hangar-remote` не меняется. Обновляется строка по-прежнему только когда Claude сам её перезапускает (сообщения в этом чате): периодического `refreshInterval` нет (отвергнуто владельцем ради энергии). shortcut: после смены аккаунта окна старого с более поздним сбросом побеждают до своего сброса. (2) **Только внутри Hangar.** `statusLine` в `~/.claude/settings.json` пользовательский, поэтому строка Hangar была и в обычном Terminal/iTerm. Теперь без терминала Hangar (`HANGAR_TAB_ID` и `HANGAR_LEAF_ID` — UUID, `HANGAR_SOCKET` задан; их ставит Hangar локально и в tmux на хосте) `hangar statusline` ведёт себя как без Hangar: исходная команда из `--then` с теми же байтами stdin, её вывод и код выхода, без `--then` — ничего; лимиты никуда не шлются (раньше слались в сокет по умолчанию). `hangar-remote` 7: то же условие для `statusline` в обычной ssh-сессии. Хуки (`hangar event`, `hangar-remote event`) вне Hangar уже молчали — без id вкладки событие не строится, stdin не читается, сокет не трогается, исходный `notify` Codex выполняется; не менялись. Настройки пользователя не меняются. **Отвергнуто:** новый метод запроса лимитов у приложения (лишний переход на главный поток и строка в MCP; ответ на уже отправляемый `usage` бесплатен); `refreshInterval`; правка `settings.json`, чтобы строка была только в Hangar.
