# HD-057 — 2026-10-24 — Архив удаляет worktree, ветка остаётся (меняет «Архив worktree не трогает» из #42 и «worktree остаётся» в §7).

По слову пользователя. Задача без worktree — просто в архив, как раньше. С worktree (`AppState.archiveRemovingWorktree`): сначала вкладки задачи останавливаются — задача уходит в архив (это закрывает surface; удалённые tmux-сессии убиваются `killSessions`, и их завершение ждётся), чтобы агент ничего не дописал во время проверки; хост не подключён — отказ сразу, ничего не останавливая. Затем проверка папки той же функцией, что у «Удалить навсегда» (`checkWorktree` в `TaskDeletion.swift`: `test -d` через `Runner` проекта, `status --porcelain`, `--ignored`). Ignored-элемент не в риске, если это переустанавливаемая папка (`node_modules`, `.venv`, `vendor/bundle`, `.turbo`, `dist`) или обычный файл, совпадающий (`cmp -s` на машине проекта: размер и содержимое) с тем же путём в основной папке — копия от настройки worktree (#58); иначе без подтверждения нельзя было бы заархивировать ни одну задачу. Грязный worktree или оставшиеся ignored-файлы (до 5 имён; сначала те, которых нет в основной папке, потом изменённые) — подтверждение «Архивировать всё равно»; отказ (и ошибка проверки) разархивирует задачу обратно, её вкладки перезапускаются лениво, как после перезапуска приложения. Подтверждено — дальше `git worktree remove` (`--force` только после подтверждения), папки уже нет — `worktree prune`. Ветку не трогаем. Ошибка проверки (хост не подключён: `host … is not connected`, git) — отказ, задача не в архиве; ошибка `worktree remove` после архивации — задача в архиве, папка на месте, сообщение. CLI `tasks archive --yes [--force]`, MCP `force: true`: при риске потери — `confirm_required` с перечнем, без изменений; ответ `worktreeRemoved`; таймаут CLI 120 с. «Восстановить» и «Отменить» в тосте (`restoreFromArchive`): папки нет → `git worktree prune` + `git worktree add <путь> <ветка>` (без `-b`), затем задача разархивируется и вкладки открываются как при старте; папка есть (заархивирована до этого решения) — просто разархивировать. Ветки нет (`rev-parse --verify` = 1) — подтверждение «Восстановить без worktree»: задача становится main-folder (`WorkspaceState.detachWorktree`, `cwd` листов из worktree переносится в папку проекта; id сессий агентов стираются, и листы стартуют заново, без `--continue` / `resume --last`, чтобы не подхватить разговор другой задачи в папке проекта). Почему: архив должен освобождать диск, а работа сохраняется в ветке. Отвергнуто: хранить флаг «worktree удалён» в модели (достаточно «папки нет»), удалять ветку при архивации, вторая копия проверок потери данных.
