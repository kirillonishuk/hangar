Интеграции v2: подключить один раз — дальше Hangar сам

Группы по функциям, а не по машинам. Каждая включённая функция действует везде: на этом Mac и на каждом ssh-хосте, включая новые. Согласие — один лист при первом запуске агента. Дальше всё обновляется молча, с копией файла, не трогая чужие хуки. MCP-сервер Hangar регистрируется сам, при запуске. Окно настроек — 970×600 по умолчанию.

Не знают, что надо ставить в Настройках

Лист «Подключить Hangar к Claude Code?» появляется сам при первом запуске Claude или Codex в Hangar.

После обновления — переустанавливать

При запуске и подключении хоста Hangar сам обновляет свои записи, в том числе путь после переноса приложения.

MCP я не должен ставить сам

Никаких «Скопировать»: запись hangar в Claude и Codex создаётся и чинится при запуске. Выключить можно переключателем.

Окно узкое

970×600 по умолчанию, минимум 760×480. Старый запомненный размер один раз сбрасывается.

Всё включено

Главный переключатель — в заголовке агента. Подпись строки — функция, под ней — что она даёт. «Где установлено» — одна строка внизу карточки, без настроек по машинам. У MCP пометка «этот Mac»: на хостах сокет Hangar принимает только статусы (#47).

Строка состояния — как в #105: «Hangar — везде» / «Ваша», образец, фишки частей. Ручка ⋮⋮ слева у фишки (подсказка «Перетащите, чтобы поменять порядок» — в тултипе) — место для параллельного PR (перестановка фишек, текст строки только по-английски). Если тот PR войдёт раньше, слот уже готов. Если позже — до него фишки без ручки.

Первый запуск: один лист

Появляется перед первым запуском Claude Code в Hangar: хуки должны быть в файле до старта агента, иначе первая сессия идёт без статусов. Вкладка ждёт ответа. Оба ответа запускают агента, и лист больше не появляется. Слева внизу — «Что изменится»: раскрывает точный diff (правило AGENTS.md о согласии на правку файлов пользователя).

Подключить — пишет выбранное на этом Mac и на подключённых хостах. Отключённые хосты получат то же при подключении. Не сейчас — ничего не пишет (MCP остаётся: он не спрашивает), выбор потом в Настройках. Для Codex — тот же лист с двумя строками.

«Что изменится» раскрыто. Diff по файлам: ~/.claude/settings.json на Mac (и на хостах — тот же вид, файл на хосте). Свёрнутые участки — как в нынешнем листе согласия. Без раскрытия лист остаётся коротким.

Новый хост, первое подключение. Без переключателей: выбор общий для всех машин. Лист только перечисляет, что попадёт на хост, и спрашивает «да / не здесь». «Не на этом хосте» запоминается (integration_hosts_skipped). Вернуть можно из строки «Где установлено».

Состояния

Часть выключена. «Лимиты» выкл. — строка Hangar остаётся, но не шлёт rate_limits в приложение (флаг читается при каждом запуске, файл не меняется). MCP Codex выкл. — запись [mcp_servers.hangar] удалена и больше не добавляется. Главный переключатель агента выкл. — строки приглушены (.38), записи Hangar сняты везде, отключённые хосты — при подключении.

Хост без связи и новый хост. gpu-box: «нет связи», применится при подключении. lab-01: подключён, но согласия ещё не было — «Подключить…» открывает лист хоста. Под курсором devbox — тултип про тихое обновление: когда, что и где копия. На экране отметки нет (#96: только лог), только в тултипе.

Агент не найден. Codex не найден в PATH логин-шелла: вместо карточки одна строка, без переключателя. Подключится сам при первом запуске Codex в Hangar (тот же лист). На хосте без codex строка «Где установлено» у Codex — «codex нет».

Ошибка записи. settings.json с ошибкой JSON: файл не тронут. Красная плашка у функции, причина, «Показать в Finder» и «Повторить». Посторонняя запись hangar в MCP (не наша команда): не трогаем, пишем «занято другой записью».

Что убирается

  • Строки «Claude Code / Codex» с плашкой и кнопками «Установить… / Обновить… / Удалить» и лист diff из Настроек: их заменили переключатели функций. Diff живёт в «Что изменится» первого листа.
  • Секция «MCP» с командами claude mcp add … / codex mcp add … и «Скопировать» (mcpAddCommands).
  • Строки интеграций в листе «Сервер» (установка и удаление на хосте). Остаются инструменты (git, tmux, claude…) и hangar-remote.
  • Ограничение «перенос Hangar.app ломает хуки до переустановки» (#43): при запуске точные записи Hangar переводятся на новый путь.
  • Отдельная секция «Строка состояния Claude»: теперь это строка внутри карточки Claude Code.
