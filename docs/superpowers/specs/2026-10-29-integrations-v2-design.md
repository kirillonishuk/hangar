# Интеграции v2: подключить один раз, дальше Hangar сам

Макет: `docs/superpowers/mockups/integrations-v2.html` (рендер кадра: `?only=<id>`). Статус: реализовано (решение #111). Отличия от текста ниже: окно настроек осталось 970×600 / мин. 680×440 (#109); MCP не зависит от главного переключателя агента; хуки Codex отложены.

## Зачем
Слова владельца (2026-10-29):
- пользователи не знают, что интеграции надо ставить в Настройках;
- после обновления их приходится ставить заново;
- MCP «как будто я не должен ставить сам, она вместе с апкой включается»;
- окно настроек узкое (снимок ≈ 970×600 pt).

Решение: функции группируются по агенту, а не по машине. Каждая включённая функция действует везде. Согласие даётся один раз, в листе при первом запуске агента. Обновления идут молча. MCP регистрируется сам.

## Поведение

### Страница «Интеграции»
Две карточки, по одной на агента. В заголовке карточки — главный переключатель. Строки:

| Claude Code | Codex |
|---|---|
| Статусы и уведомления (хуки) | Статусы и уведомления (`notify`) |
| Лимиты (`rate_limits` из статус-лайны → приложение) | — у Codex нет источника лимитов для Hangar |
| Строка состояния: «Hangar — везде» / «Ваша», образец, фишки частей (#105) | — у Codex нет своей команды строки, только встроенные пункты `tui.status_line` |
| MCP-сервер Hangar, пометка «этот Mac» | MCP-сервер Hangar, пометка «этот Mac» |

Внизу каждой карточки — строка «Где установлено»: `Этот Mac ✓  devbox ✓  gpu-box ● нет связи  lab-01 ● Подключить…`. Настроек по машинам нет. Тултип элемента:
- когда было последнее тихое обновление и где лежит копия;
- «применится при подключении» (хост без связи);
- «codex нет» (на хосте нет codex).

Фишки строки состояния оставляют место (ручка ⋮⋮) под параллельный PR: перестановка перетаскиванием и текст строки только по-английски. Образец и фишки занимают всю ширину карточки (DESIGN.md, #105).

Поведение строк:
- **Главный переключатель выкл.** — строки приглушены (.38). Записи Hangar этого агента снимаются на Mac и на подключённых хостах; хосты без связи — при подключении. Выбор строк запоминается.
- **«Лимиты» выкл.** — файлы не меняются. `hangar statusline` читает конфиг при каждом запуске (#105) и просто не отправляет `rate_limits`. Обёртка `statusLine` снимается, только если одновременно выбрана «Ваша» и «Лимиты» выключены.

### Первый запуск: один лист
Лист «Подключить Hangar к Claude Code?» (620, SheetKit) открывается при первом запуске листа claude, если `claude_integration` ещё нет в конфиге. Codex — так же, свой лист с двумя строками.

- **Содержимое.** Четыре переключателя (все включены) и строка «Куда»: этот Mac, подключённые хосты, отключённые («при подключении»).
- **Футер.** Ссылка «Что изменится» раскрывает точный diff по файлам — это согласие из AGENTS.md. Кнопки «Не сейчас» и «Подключить».
- **Агент ждёт ответа.** Вкладка ждёт: хуки должны оказаться в файле до старта агента, иначе первая сессия идёт без статусов. Любой ответ запускает агента.
- **«Не сейчас».** Пишет `claude_integration = false` и не меняет ничего в файлах. MCP при этом остаётся (см. ниже). Включить потом можно в Настройках.

### Новый хост
При первом подключении хоста, которого нет ни в `integration_hosts`, ни в `integration_hosts_skipped`, Hangar показывает лист «Подключить Hangar на <host>?».
- Переключателей нет: выбор общий для всех машин. Лист только перечисляет, что попадёт на хост: функции по агентам и `hangar-remote`.
- Кнопки «Не на этом хосте» и «Подключить».
- Хост, который был отключён при первом согласии, тоже проходит через этот лист.
- **Миграция.** Хост, где интеграция Hangar уже стоит (v0.7), молча попадает в `integration_hosts`.

### Тихие обновления (расширяет #96)
Когда: при запуске (на этом Mac) и при каждом подключении хоста. Порядок: `hangar-remote` (R7) → хуки → статус-лайна → синхронизация строк проектов (#105).

Работают только с собственными записями Hangar по правилу владения #96: команда ровно `<cli> event <kind>` (три слова). Новое по сравнению с #96:
- **Перенос пути.** Владение больше не требует `w[0] == cli`. Запись Hangar с другим путём к `…/Contents/Helpers/hangar` (приложение перенесли или обновили не на месте) переводится на текущий путь. Статус-лайна (`'<cli>' statusline [--then …]`) и `notify` Codex — так же. Это снимает «Известное ограничение» из #43.
- **Две копии Hangar.app.** Копия вне `/Applications` не перехватывает записи, если путь в них ведёт в существующий `/Applications/Hangar.app`. Иначе две копии перетягивали бы записи при каждом запуске.
- **Выключенная функция.** Её записи снимаются тем же путём (копия, атомарная запись, отказ при изменении файла).
- **Видимость.** На экране ничего не показывается: изменения идут в лог и в тултип «Где установлено».

Все записи идут через нынешние `writeUserFile` / `remoteFileWriteScript`: копия рядом с файлом, атомарная запись, отказ, если файл изменился после чтения. Чужие обработчики, matcher, изменённый пользователем, и составные команды не трогаются (#96).

### MCP
Регистрируется автоматически, без вопроса (слово владельца), только на этом Mac.

**Когда:** при запуске и при возврате в Настройки. Повторная проверка — только чтение файла.

**Порядок:**
1. Прочитать (только чтение) user-scope запись `hangar`:
   - Claude: `<CLAUDE_CONFIG_DIR или ~>/.claude.json`, ключ `mcpServers.hangar`;
   - Codex: `$CODEX_HOME/config.toml`, таблица `[mcp_servers.hangar]`.
2. **Записи нет** и `<agent>_mcp != false` → добавить.
3. **Запись наша, но путь другой** → перерегистрировать. «Наша» значит: `command` оканчивается на `/Contents/Helpers/hangar`, `args == ["mcp"]`, `env` пуст.
4. **Запись чужая** (другая команда) → не трогать. В строке показать «имя «hangar» занято другой записью».
5. **Переключатель выкл.** → удалить, только если запись наша. Записать `<agent>_mcp = false`; после этого Hangar запись не добавляет.

**Чем писать: CLI агента, а не правкой файлов.** Проверено в изолированном `HOME=/tmp/…` (настоящие файлы не тронуты):
- `claude mcp add --scope user hangar -- <cli> mcp` пишет в `~/.claude.json`: `"mcpServers": {"hangar": {"type":"stdio","command":"<cli>","args":["mcp"],"env":{}}}`. Копию кладёт в `~/.claude/backups/.claude.json.backup.<ms>`. При заданном `CLAUDE_CONFIG_DIR` пишет в `$CLAUDE_CONFIG_DIR/.claude.json`.
- Повторный `add` (и `add-json`) с тем же именем завершается кодом 1 («already exists»). Поэтому смена пути = `claude mcp remove --scope user hangar`, затем `add`.
- `claude mcp get` запускает сервер для проверки связи. Hangar его не вызывает, а читает файл сам.
- `codex mcp add hangar -- <cli> mcp` — upsert (`servers.insert`). Пишет через `ConfigEditsBuilder` (toml_edit, атомарно), остальные таблицы и комментарии сохраняются. `codex mcp remove hangar` удаляет запись.

**Почему CLI:**
1. `~/.claude.json` — горячий файл (≈140 КБ), его переписывает каждый запущенный Claude: счётчики, кэши, проекты. Сторонняя правка гонится с живыми сессиями. Писатель этого файла — сам Claude.
2. Для `[mcp_servers.<name>]` нужен редактор TOML-таблиц. #45 его отверг, а `TOMLScanner` понимает только ключи корня.
3. Если CLI агента нет в PATH логин-шелла (Hangar ищет его так же, как сейчас codex — `resolveCodex`), то и агента в Hangar не запустить. Значит, и MCP не нужен: строка показывает «claude/codex не найден», ничего не пишется.

Цена — ≈0,4 с на процесс, и только когда нужна запись. Проверка в обычном случае — чтение файла.

**Хосты: MCP не регистрируется.** Сокет хоста намеренно принимает только `hook`/`statusline` (#47): MCP с сервера позволил бы взломанному серверу печатать в локальные терминалы (`tabs send`). Отсюда пометка «этот Mac» и отсутствие хостов у MCP в «Где установлено». (Открытый вопрос 1.)

### Окно настроек
- `Theme.settingsSize` 760×560 → **970×600**, `settingsMinSize` 680×440 → **760×480**.
- Имя автосохранения рамки `HangarSettings` → `HangarSettings2`: запомненный старый размер один раз сбрасывается на новый.
- Страница «Интеграции» при 970×600 помещается без прокрутки (проверено в макете). На минимуме прокручивается.

## Данные: ключи `config.toml` Hangar (голые, как #43)
```
claude_integration = true      # нет ключа → спросить при первом запуске claude; false → «Не сейчас»/выкл.
claude_hooks = true            # «Статусы и уведомления»
claude_limits = true           # «Лимиты» (читает `hangar statusline` при каждом запуске)
claude_mcp = true              # нет ключа = true; false → запись hangar удалена и не добавляется
statusline = "hangar"          # как #105
statusline_segments = [...]    # как #105 (порядок — параллельный PR)
codex_integration = true
codex_notify = true
codex_mcp = true
integration_hosts = ["devbox", "gpu-box"]   # согласие на хост дано
integration_hosts_skipped = ["lab-01"]      # «Не на этом хосте»
```
Миграция с v0.7 при первом запуске:
- хуки Hangar на Mac есть → `claude_integration = true`, `claude_hooks = true`, `claude_limits = true`;
- `notify` Hangar есть → `codex_integration = true`;
- MCP — по факту наличия записи; если её нет, MCP добавляется (поведение «включён с приложением»).

## Ошибки
| Случай | Что делает Hangar |
|---|---|
| JSON/TOML не разбирается, файл только для чтения, файл изменился | Файл не тронут. Плашка «ошибка» у функции, причина в подписи, кнопки «Показать в Finder» и «Повторить». В «Где установлено» — красная точка у машины |
| Хост без связи | «нет связи». Применится при подключении (тем же путём, что #96) |
| Агента нет на машине | Mac: карточка свёрнута в одну строку «не найден». Хост: «codex нет» |
| Чужая запись `hangar` в MCP | Не трогать, показать причину |
| Запись `hangar` в project/local scope (`.mcp.json`, `projects[...].mcpServers`) | Не трогать. Если она перекрывает user scope — это выбор пользователя |
| CLI вернул ошибку | Лог, строка MCP «ошибка» с текстом stderr (последняя строка) в тултипе. Повтор — при следующем запуске |
| Приложение из DMG или транслоцировано (`installBlocked`) | Ничего не пишется. Подпись «Переместите Hangar в Программы» |
| DEBUG без собранного `Helpers/hangar` | Ничего не пишется (как сейчас) |

## Что убирается
- Строки «Claude Code / Codex» с плашкой и «Установить… / Обновить… / Удалить», `IntegrationSheet` в Настройках. Diff переезжает в «Что изменится» листа первого запуска.
- Секция MCP со «Скопировать» и `mcpAddCommands`. Запись в #45 «Hangar сам конфиги агентов не правит» заменяется: правит через CLI агента, только свою запись.
- Строки интеграций в листе «Сервер» (`ServerCheckModel.review/confirmPlan/applyIntegration` для интеграций). Инструменты и `hangar-remote` остаются.
- Отдельная секция «Строка состояния Claude» — она становится строкой карточки Claude Code.
- Ограничение #43 «перенос Hangar.app ломает хуки до переустановки».

## Тесты
- `claudeUpgrade` / retarget:
  - хуки и статус-лайна со старым путём `…/Helpers/hangar` → новый путь; чужие и составные команды не тронуты;
  - копия вне `/Applications` не перехватывает записи существующей копии из `/Applications`;
  - повторный запуск ничего не меняет.
- Снятие функции: выкл. хуков снимает только точные записи Hangar; выкл. «Лимиты» при «Hangar» не меняет файл; «Ваша» + выкл. «Лимиты» восстанавливает исходную `statusLine`.
- Разбор MCP-записи: наша / чужая / с другим путём / отсутствует — в `~/.claude.json` (с `CLAUDE_CONFIG_DIR`) и `config.toml` (`[mcp_servers.hangar]`, inline-таблица).
- План MCP → argv: `remove` + `add` для Claude, один `add` для Codex. Ничего, если `*_mcp = false` или запись чужая. Тест на поддельном runner, без настоящих CLI.
- Конфиг: разбор и запись новых ключей, миграция v0.7 (есть хуки → `claude_integration = true`).
- Лист первого запуска: показывается один раз; «Не сейчас» пишет `false` и запускает агента; вкладка ждёт ответа.
- Хост: новый → лист; `integration_hosts_skipped` → без листа и без записи; v0.7 с установленной интеграцией → молча в `integration_hosts`.
- Живая проверка (hangar-test): DEBUG с поддельными `HOME`/`CLAUDE_CONFIG_DIR`/`CODEX_HOME` и поддельным ssh — страница при 970×600 и на минимуме, ru/en, Navy/Dark+.
