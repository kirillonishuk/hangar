# HD-070 — 2026-10-24 — ⌘V с картинкой в буфере шлёт ⌃V (как VS Code).

По слову пользователя: Claude Code и Codex берут картинку из системного буфера по ⌃V (байт 0x16), а текстовая вставка картинки ничего полезного не шлёт. ⌘V (по keyCode 9, любая раскладка) в любом терминальном листе — claude, codex, shell (claude бывает запущен вручную в shell-вкладке), нижний TERMINAL — при буфере только с картинкой (`public.png` / `public.tiff` или file URL на файл-картинку) и без простого текста шлёт ⌃V через тот же путь `sendKey`, что `tabs send --key ctrl-c`; иначе обычная вставка. Текст + картинка — текст. Исключение — Helix (лист `editor`): там ⌃V — команда. Цена: в голом zsh ⌃V начинает quoted-insert (безвредно, следующая клавиша вставится буквально) вместо пустой вставки. Решение — `pasteAction` в `ImagePaste.swift`, хук `TerminalSurfaceView.onPaste` (⌘V, меню «Вставить»). ⌃V в русской раскладке уже уходит как 0x16 (Ghostty берёт физическую клавишу, когда символ не ASCII; проверено вживую с кодовой точкой «м»). Копия файла из Finder кладёт и имя текстом — вставляется экранированный путь, как раньше. Перетаскивание файла из Finder в терминал пока не поддерживается (нет drop-приёмника у surface). Отвергнуто: только для листов claude/codex (claude в shell-вкладке не получал картинку).
