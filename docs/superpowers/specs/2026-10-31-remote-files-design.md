# Файлы сервера в терминале «<сервер> · терминал» — дизайн

Статус: утверждено владельцем 31.10, реализовано (решение #124). Макет — `docs/superpowers/mockups/remote-files.html` (рендер — `remote-files.png`). Дополняет #64 (простое подключение), опирается на #47 (транспорт, `shellQuote`, пути мастера), #71, #91 (Поиск), дизайн-систему #112.

## 1. Что просит владелец
Когда просто зашёл на сервер (`WorkspaceState.hostShells`, без проекта), правый сайдбар показывает папку, где сейчас терминал, с её файлами; файлы можно положить туда кнопкой «+» или перетащив из Finder.

## 2. Что есть в коде сейчас
- Вкладка «<host> · терминал» — `sshShellSpec` (`Sources/Exec/RemoteLaunch.swift`): `/bin/sh -c 'TERM=xterm-256color ssh -t -o ServerAliveInterval=15 -o ServerAliveCountMax=4 -- <host>; …OSC 133 C/D…'`. Без мастера (`ControlMaster` не задан — #64 сознательно отказался от общего мастера с `BatchMode`, чтобы работали пароль и 2FA), без удалённой команды: сервер запускает логин-шелл.
- Инспектор у псевдозадачи пуст: `InspectorWatch.update` берёт корень через `app.project(...)`, у `hostShells` проекта нет → `stop()`.
- GhosttyKit отдаёт встраивающему `GHOSTTY_ACTION_PWD` (`ghostty_action_pwd_s.pwd`) после OSC 7, но `GhosttyApp.handleAction` его не обрабатывает (`default: return false`).
- **Главное ограничение:** Ghostty принимает OSC 7, только если хост в URL локальный (`stream_handler.zig reportPwd` → `hostname.isLocal`: `localhost` или имя этого Mac). Обычный OSC 7 сервера (`file://vultr/...`, его же шлют vte.sh, интеграции Ghostty/kitty на сервере) молча отбрасывается. Поэтому хук обязан слать `kitty-shell-cwd://localhost<путь>` — схема `kitty-shell-cwd` берёт путь как есть (`raw_path`), процентного кодирования в шелле не нужно.
- Удалённые проекты (#47) уже умеют: мастер `-S <cp>`, `sshBaseArgs`, `remoteShellArgs` (аргументы — словами в кавычках, код — только `/bin/sh`), запись файла через stdin ssh (`remoteFileWriteScript`: временный файл + `mv`), удалённый Поиск через `git grep` (#91). Это и переиспользуется.

## 3. Механизм

### 3.1 Текущая папка терминала (OSC 7 через хук без установки)
- Перед входом Hangar читает конфиг пользователя для хоста: `ssh -G <host>` (без соединения, синхронно, не дольше 2 с — `shortcut:`). Удалённая команда (одна строка без `!`: tcsh/csh не принимают перевод строки в кавычках и раскрывают `!` даже в них) идёт через `remoteShellArgs`: `/bin/sh -c '<скрипт>'` смотрит `$SHELL` и делает `exec`:
  - **zsh** — временная папка (`mktemp -d`, 0700) с `.zshenv`: возвращает исходный `ZDOTDIR`, подключает `.zshenv` пользователя, добавляет `precmd`-хук через `add-zsh-hook`, удаляет временную папку; затем `exec zsh -l` с этим `ZDOTDIR` (тот же приём, что у интеграции Ghostty, #71). Если `/etc/zshenv` сам задаёт `ZDOTDIR`, наш `.zshenv` не читается: хука нет, временную папку через минуту удаляет фоновый сторож, переменные `HANGAR_*` остаются в окружении сессии (безвредно).
  - **bash** — экспортированный `PROMPT_COMMAND` с хуком и `exec bash -l`: настоящий логин-шелл (`logout`, `.bash_logout`); rc пользователя, который дописывает `PROMPT_COMMAND`, хук сохраняет, а который перезаписывает — теряет (папка тогда «неизвестна»).
  - **fish** — без файлов: `exec fish -l -C 'function __hangar_cwd --on-event fish_prompt; …; end'` (`-C` выполняется после конфигов пользователя).
  - Иное (sh, dash, ksh, csh) — `exec "$SHELL" -l` без хука: панель говорит «Папка терминала неизвестна» и показывает домашнюю папку.
  - **Без хука** вход идёт как раньше (#64): если в конфиге хоста есть `RemoteCommand` (ssh отказал бы — две команды), если `ssh -G` не ответил, если хост помечен «без хука». Пометка ставится сама: вход с хуком закончился кодом ≠ 0 и ≠ 255 (255 — ssh: пароль, связь) до первого OSC 7 — tcsh, rbash (`/` запрещён), сетевые устройства; вкладка сразу входит заново без хука. Пометка хранится в `HostShell.noHook` (state.json) пока жив терминал сервера; закрыли и открыли снова — хук пробуется заново.
- Хук печатает `ESC ] 7 ; kitty-shell-cwd://localhost$PWD BEL` на каждом приглашении. Ничего не ставится и не правится на сервере; временный файл живёт до чтения шеллом.
- Ghostty → `GHOSTTY_ACTION_PWD` → новое событие `TerminalSurfaceView.Event.pwd(String)` → `AppState` хранит «последнюю папку» на лист вкладки (только для листов `hostShells`, в памяти, не в `state.json`). Значение недоверенное: только абсолютный путь, без управляющих символов, ≤ 4096 байт, иначе отброшено; используется только как аргумент удалённых команд (никогда как локальный путь).
- Панель показывает папку **листа в фокусе** у этой псевдозадачи (вкладка/сплит), см. вопрос 3.
- Вложенные `ssh`, `sudo -s`, `docker exec`, `su`: их шеллы хука не имеют (их OSC 7 с чужим хостом Ghostty отбрасывает), поэтому панель держит папку последнего приглашения нашего шелла. Заголовок всегда показывает этот путь — пользователь видит, куда лягут файлы. Признака «сейчас внутри вложенного» нет и не изобретаем (OSC 133 с сервера сломал бы код выхода вкладки, #26).
- Папку сообщает сам вывод в терминале: программа на сервере может напечатать OSC 7 и сменить цель панели — поэтому цель всегда видна в заголовке пути, а загрузка идёт в показанную папку.
- Побочное: если сервер не задаёт заголовок окна, Ghostty делает заголовком вкладки путь (как в Ghostty.app). Открытие относительной ссылки кликом в такой вкладке будет искать файл на Mac — не чиним (редкий случай).

### 3.2 Соединение без второго входа
- Сама вкладка становится мастером: `-S <state>/ssh/hs-<fnv64(leafId)> -o ControlMaster=auto -o ControlPersist=no` (путь и запасной `/tmp/hangar-<uid>/` — как у `SSHPaths`, ограничение 104 байта). Пароль и 2FA по-прежнему вводятся во вкладке: мастер — интерактивный ssh, `BatchMode` у него нет. Это не «общий мастер хоста», отвергнутый в #64.
- Сокет **на лист**, не на сервер: с общим сокетом вторая вкладка стала бы клиентом первой, и закрытие первой висло бы до конца второй.
- Фоновые команды (список, загрузка, поиск) — `ssh` + `sshBaseArgs(controlPath:)` (`ControlMaster=no`, `BatchMode=yes`) + `ProxyCommand=/usr/bin/false`: только через живой мастер — без него ssh не пытается войти напрямую, а сразу отвечает 255; файла сокета нет — ssh не запускается. Итог — «нет соединения», без нового входа.
- Свой мастер пользователя важнее: если `ssh -G` показывает `controlmaster` ≠ `false` или заданный `controlpath`, вкладка идёт без нашего `-S` (его общий мастер и 2FA один раз остаются), а панель работает через **его** `ControlPath` (тот же `BatchMode` + `ProxyCommand=false`) и никогда не завершает этот мастер (`-O exit` только для своего). `~/.ssh/config` не правится.
- Папка сокетов небезопасна (чужая или симлинк `/tmp/hangar-<uid>`, `SSHPaths.prepare` отказал) — вкладка входит без `-S` и без хука, панели нет: чужой сокет мог бы выдать себя за мастер.
- Закрытие вкладки: мастер ждёт конца мультиплексных сессий, поэтому Hangar сначала завершает свои фоновые процессы этого листа (загрузки отменяются).

### 3.3 Список файлов
- Одна команда через мастер: POSIX-скрипт (одна строка) `cd -- "$1"` и обход `.* *` (без `.`/`..`) с выводом `тип\tимя\0` (тип: папка / файл / ссылка на папку / ссылка). Без `ls`-разбора и без GNU `find`. Предел 5000 записей и 1 MiB вывода («Показаны первые 5000»); строгий разбор (как вывод проверки сервера, #47).
- Вид — как «Файлы» (§3.7 дизайн-системы): строки 24, папки сверху, затем файлы, по имени; скрытые файлы показываются. Папка раскрывается шевроном (её список — по запросу, та же команда); дерево ниже текущей папки не грузится заранее.
- Когда обновлять: событие PWD (каждое приглашение — значит, после каждой команды: `rm`, `mv`, `git pull` видны сразу), повтор того же пути — с debounce 300 мс; после загрузки; кнопка «Обновить». Только пока инспектор виден и выбрана эта псевдозадача — иначе событие лишь запоминает путь. Ни таймеров, ни опроса.
- Клик по файлу ничего не открывает (этап 2); контекстное меню — нет на этом этапе.

### 3.4 Загрузка на сервер
- «+» в заголовке панели → `NSOpenPanel` (файлы и папки, несколько). Перетаскивание из Finder: на список — в текущую папку; на строку папки — в неё (строка подсвечивается, §5). Цель всегда видна: путь в заголовке или подсвеченная папка.
- Файл: `ssh … /bin/sh -c '<скрипт>' sh <папка> <имя> <режим> <заменить> <размер>`, stdin — файл. Скрипт пишет во временный `.<имя>.hangar-part` в той же папке под `set -C` (подложенная в общей папке ссылка с этим именем не открывается), сверяет размер и делает `mv`: обрыв не оставляет полуфайла под настоящим именем. Новый файл — локальный режим под `umask` сервера (не шире); заменённый — сохраняет свой режим и, где можно, владельца (`.env` 0600 остаётся 0600). Ссылка на папку под этим именем — конфликт видов; ссылка на файл заменяется сама (цель не трогается). Без «заменить» `mv` не выполняется, если имя появилось за это время (код 10 → снова вопрос). Имя длиннее 242 байт (чтобы `.<имя>.hangar-part` влез в NAME_MAX) — понятная ошибка.
- Папка: локально `tar -c ./<имя>` (имя с `-` не станет ключом; `COPYFILE_DISABLE=1`, без `._`, xattr, ACL) → stdin ssh → на сервере `tar -x` во временную `.<имя>.hangar-part/`, проверка числа файлов, затем `mv`. «Объединить» — `cp -R .<имя>.hangar-part/<имя>/. <имя>/`: совпадающие файлы перезаписываются на месте (режим остаётся), существующие папки не меняют режим и время, ничего не удаляется. Подсчёт файлов папки — не на главном потоке. Нужны только `/bin/sh` и `tar` на сервере.
- Прогресс: байты, переданные в stdin ssh, из суммы размеров (для tar — по содержимому, ограничено 100 %). Очередь по одному, общий прогресс «N из M». Отмена — завершить процесс, затем отдельной командой удалить `.<имя>.hangar-part`; при обрыве связи сервер сам удаляет его (размер / число файлов не сошлись). Перетаскивание во время загрузки — следующая пачка своего листа (идёт, даже если инспектор перешёл на другой).
- Конфликт имени (по списку перед стартом и повторно в скрипте): поповер у панели «report.pdf уже есть в /var/www/app» с флажком «Для всех» и кнопками «Пропустить» · «Заменить». Для папки — см. вопрос 2.

## 4. Интерфейс (макет `remote-files.html`)
- Инспектор псевдозадачи: сегмент «Файлы · Поиск» (без «Изменений» и Git). Поиск — как #91 через мастер листа: `git grep --no-index` (`shortcut:` нет git на сервере — ошибка поиска; результаты не открываются до этапа 2).
- Под сегментом — заголовок панели 28 (§3.5): иконка папки 12, путь `mono` `text2` (середина сокращается, полный — в тултипе, `~` для домашней), справа иконки 22: «Обновить», «Загрузить файлы — +». «+» — второстепенное действие иконкой (§5 дизайн-системы).
- Состояния: загрузка — `ProgressView` small на месте списка; пустая папка — «Папка пуста. Перетащите сюда файлы» `body` `text2` по центру + кнопка «Загрузить файлы»; перетаскивание — рамка `accent` 1 + заливка `accent` .15 у списка или у строки папки (подпись «Загрузить в /var/www/app» `secondary` внизу списка); загрузка — блок внизу инспектора над краем: строка 28 «Загрузка: 2 из 3» + `mono` 11 «48 %» + «×», полоса `LimitBar` высотой 4 (`limTrack` / `limOk`), строка текущего файла `secondary` `text3`; конфликт — поповер (§3.12) у блока загрузки; нет связи — §3.5.
- Тексты (ru/en в `Localizable.strings`): «Загрузить файлы», «Обновить», «Папка пуста. Перетащите сюда файлы», «Загрузить в %@», «Загрузка: %d из %d», «%@ уже есть в %@», «Для всех», «Пропустить», «Заменить», «Нет соединения с %@», «Войдите во вкладке терминала», «Папка терминала неизвестна», «Нет доступа к %@».

## 5. Вне рамок (этап 2 и позже)
Скачивание перетаскиванием в Finder, открытие файла в редакторе, контекстное меню (переименовать, удалить, скопировать путь), то же для не-git удалённых проектов (`remoteNoGit`), загрузка в проектах с tmux, csh/tcsh, синхронизация.

## 6. Решения владельца (31.10)
1. **Вход через удалённую команду** — принято: приветствие сервера (MOTD) не печатается, настройки нет; шелл без хука входит как раньше.
2. **Папка с тем же именем** — «Объединить»: совпадающие файлы заменяются, остальные остаются; Hangar на сервере ничего не удаляет (кроме своих `.hangar-part`).
3. **Несколько вкладок/сплитов** — панель следует за вкладкой (сплитом) в фокусе.

## 7. Проверено
- Ghostty принимает `kitty-shell-cwd://localhost<путь>` с пробелами и кириллицей (живой запуск DEBUG, фейковый ssh, настоящий zsh); `file://localhost` с кодированием не понадобился.
- Хук на настоящих zsh и bash этого Mac в pty (тест `hookReportsTheFolder`): папка приходит, `PROMPT_COMMAND`/`precmd` пользователя работают, временные файлы удалены.
- Тесты: tcsh как логин-шелл входит с хуком (одна строка), rbash падает своим кодом (→ вход без хука); `RemoteCommand`, свой мастер пользователя, небезопасная папка сокетов — тесты плана и `HostShellUITests`.
- Не проверено вживую: настоящий OpenSSH-мастер с мультиплексированием (на Mac выключен sshd, к серверам владельца не подключаемся) — поведение `-S`/`ControlMaster=auto`/`ProxyCommand=false` сверено `ssh -G` и пробой без сети; fish на сервере.
