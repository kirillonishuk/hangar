# HD-039 — 2026-10-18 — Действия над проектами, задачами и вкладками — один реестр `Action` (Task 6b).

`Sources/HangarUI/Actions.swift`: у каждого действия заголовок, иконка `Icon`, шорткат, `isEnabled(for:)`, `perform`; контекстные меню, `…` на строках и шорткаты (позже ⌘K) берут их оттуда (`Action.list(for:)`). Задача: переименовать (F2 / двойной клик, инлайн), закрепить/открепить, открыть в Finder (`activateFileViewerSelecting`), скопировать путь (абсолютный: worktree или папка проекта), открыть в `external_editor` (пункт скрыт, если ключ пуст), архивировать (`⌘⇧W`). Архивная: восстановить, удалить навсегда (подтверждение). Проект: новая задача, переименовать, настройки проекта (лист 580: название, путь с «Выбрать…», ветка — только показ; несуществующая папка — ошибка в листе), Finder, путь, редактор, удалить из Hangar (подтверждение; папка на диске не трогается — тест). Вкладка: переименовать (`Tab.customTitle` важнее заголовка терминала, старые файлы читаются), сплит вправо/вниз, закрыть. Пустое имя — отказ. Смена пути проекта переносит `cwd` листов задач `.mainFolder`, стоявших в старой папке. Инлайн-поле: ↩ — сохранить, Esc — отмена, потеря фокуса — сохранить, затем фокус возвращается в терминал. Перетаскивание — своим жестом строки (`DragGesture`, без `NSItemProvider`): задача внутри группы проекта (закреплённые не перетаскиваются), проект целиком; место — по центрам строк (`dropIndex`), линия `accent` 2 pt. Шорткаты по keyCode: F2: если последним действием пользователя был клик по строке сайдбара (задача или проект) или вкладке и с тех пор ни одна клавиша не ушла в терминал или поле ввода — переименовывает кликнутое; иначе уходит в терминал/поле, а если фокуса нет — переименовывает выбранную задачу (в рейке недоступно). Клик по строке или вкладке клавиатуру у терминала не забирает (переход на другую задачу/вкладку, как и раньше, фокусирует её терминал); состояние `AppState.lastInteraction` (`.chromeClick(цель)` / `.typing`) только в памяти, без записи в модель на каждую клавишу. `Tab.focusedLeafId` следует за реальным фокусом (клик в панель → `setFocusedLeaf`), поэтому `⌘D` делит панель, в которой фокус; `⌘⇧W`; `⌘B` = `⌘0`; `⌘⌥↑/↓` — предыдущая/следующая задача (`⌘↑/↓` остаются терминалу). «Открыть в …» запускается через `<shell> -l -i -c 'exec <editor> <path>'`, а не `/usr/bin/env`: у приложения из Finder в PATH нет `/usr/local/bin` и `~/.local/bin` (как в #27); ненулевой код — `NSAlert` с последней строкой stderr. Почему: инвентаризация Pane + решения пользователя.
