# HD-041 — 2026-10-19 — Восстановление сессии (Task 7).

Старт: `StateStore.load()` → `.loaded` восстанавливает всё (выбор, вкладки, сплиты, фокус, инспектор, сайдбар, нижнюю панель); все листья из файла, включая лист TERMINAL, запускаются с `restoring: true` (`claude --continue`/`--resume <id>`, `codex resume --last`/`<id>`, редактор с тем же файлом, шелл в том же cwd). Сразу стартуют только surface видимой вкладки, остальные — при первом показе. Нет папки — лист показывает «папка не найдена» без запуска, строка проекта серая. `.recoveredFromCorrupt` и `.unreadable` — `NSAlert` (строки ru/en через `L10n`); при `.unreadable` хранилище только для чтения. Выход: `applicationWillTerminate` → `saveNow`. Подтверждение ⌘Q при работающих агентах — этап 3. Ограничение: без id сессии у вкладки `--continue` / `resume --last` берут последний разговор в cwd, поэтому набор `restoring` считается один раз при старте (`resumeSet`): листья с `agentSessionId` всегда возобновляются, среди claude/codex без id в одном (вид, cwd) продолжается только первый (по порядку задач → вкладок → листьев → панели), остальные стартуют заново; настоящие id по вкладкам — с хуками этапа 3. **Запуск листа агента (обновлено 2026-10-19, финальное ревью):** `LaunchSpec` строится заново при каждом запуске (замороженный spec не переиспользуется) из одной чистой функции `launchMode(for:_:)` (`Sources/Exec/Launch.swift`) по контексту: `.created(prompt)` — новая задача/вкладка, свежий старт, первое сообщение только в этот первый запуск; `.restored(inResumeSet)` — старт из state.json и восстановление задачи из архива (в ту же сессию или позже), правило `resumeSet` как выше; для разархивированной задачи набор считается по её листьям (их surface закрыты архивом), работающие листья других задач слот не занимают; `.relaunch(previous, exitCode)` — ↩: первое сообщение никогда не отправляется повторно; если прошлый запуск был возобновлением (`--continue` / `resume --last` / `--resume <id>`) и завершился с ненулевым кодом — свежий старт (иначе бесконечное «No conversation found to continue»), иначе — возобновление (`--resume <id>`, если id известен, иначе `--continue` / `resume --last`); surface не создался (`exitCode` нет, процесс не запускался) — тот же запуск ещё раз. id сессии используется только при возобновлении: свежий старт после неудачного `--resume <id>` его игнорирует. Шелл и редактор не меняются (шелл в том же cwd, редактор с тем же файлом). Почему: приёмка этапа 1.
