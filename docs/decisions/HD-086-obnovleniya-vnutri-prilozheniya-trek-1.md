# HD-086 — 2026-10-27 — Обновления внутри приложения (трек 1, по слову пользователя; без Sparkle и новых зависимостей).

Новый модуль `Update` (только Foundation/CryptoKit, с тестами): `GET https://api.github.com/repos/kirillonishuk/hangar/releases/latest` через `URLSession` (системный прокси), черновики и pre-release пропускаются, тег — только `^v?\d+\.\d+\.\d+$`, нужны ассеты `Hangar-X.Y.Z.dmg` и `.dmg.sha256`, версия тега сравнивается с `CFBundleShortVersionString`. Адреса ленты, ассетов, страницы релиза и всех редиректов (`willPerformHTTPRedirection`) — только https на `api.github.com`, `github.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`; иное отбрасывается при разборе (сохранённый в `update.json` релиз проверяется так же). Проверка — при каждом запуске и при активации приложения, если с прошлой прошёл ≥ 1 ч, без таймеров; неудачная (нет сети, 403) тоже считается проверкой, следующая при активации — через час (исправлено 2026-10-28, см. HD-099: было «не чаще раза в 24 ч», и запущенная 0.4.0 сутки не видела вышедшую 0.4.1; час — далеко от лимита GitHub 60 запросов/ч без авторизации). Пока обновление загружается, проверяется или подготовлено, проверки не идут (найденный позже релиз не подменит устанавливаемый). `update.json` рядом со `state.json`: время последней проверки, пропущенная версия, найденный релиз (плашка переживает перезапуск между проверками). Настройки → Общие: «Проверять обновления» (`check_updates`, по умолчанию вкл.), «Версия» — текущая версия, итог проверки и «Проверить сейчас» (игнорирует час и снимает пропуск с найденной версии); найденное обновление ставится и отсюда — «Обновить до X.Y.Z» на месте «Проверить сейчас» (HD-099). Есть релиз новее и не пропущен — справа в строке статуса плашка «Доступна X.Y.Z» → лист (SheetKit): заметки релиза (раздел «Install» из workflow убран, заголовки и списки упрощены, inline-Markdown), «Пропустить версию» · «Позже» · «Обновить». «Обновить»: если запущена другая копия с тем же bundle id — отказ с подсказкой в листе; иначе DMG и `.sha256` во временную папку `hangar-update-X.Y.Z-…` под фиксированными именами `Hangar.dmg`/`Hangar.dmg.sha256` с прогрессом, несовпадение суммы — отказ; нет прав на запись в папку бандла (или это не `.app`, App Translocation) — DMG открывается в Finder с подсказкой; иначе `hdiutil attach -nobrowse -readonly`, приложение в образе — настоящая папка (не симлинк), проверка bundle id (как у запущенного), версии (= тег) и `codesign --verify --deep --strict`, затем обычный выход (`NSApp.terminate`: подтверждение при работающих агентах и несохранённых файлах, `saveNow`). В `applicationWillTerminate` после сохранения запускается отсоединённый `sh`-помощник: ждёт выхода нашего pid (до 2 мин), `ditto` в соседний `.Hangar.app.hangar-new.<pid>` (результат должен быть папкой, не симлинком), снимает карантин, `mv` старого в `.hangar-old`, `mv` нового на место (при ошибке старый возвращается), удаляет старый, `hdiutil detach` и удаление временной папки (на любом пути, и при таймауте ожидания), `open` нового; ошибка пишется в `update-error.txt`, и при следующем запуске показывается в листе. Отменённый выход оставляет подготовленное обновление: оно поставится при следующем выходе (кнопка листа — «Перезапустить»). DEBUG: проверки выключены, пока `HANGAR_UPDATE_FEED` не укажет тестовую ленту (file:// годится), перезапуск — прямым запуском исполняемого файла, чтобы сохранить изолированное окружение. Релизы подписаны ad-hoc (без Team ID), поэтому `codesign --verify` проверяет только целостность, а подлинность держится на TLS, аккаунте GitHub и списке разрешённых хостов; sha256 из того же релиза защищает от порчи, не от подмены релиза. С Developer ID можно будет закрепить designated requirement (Team ID) и сверять его у нового приложения. Проверка: юнит-тесты (версии, разбор релиза и выбор ассетов, отказ при несовпадении суммы, скрипт замены на поддельных бандлах в temp: путь с пробелами, кавычками и кириллицей, откат при сбое второго `mv`, таймаут ожидания с уборкой; строгие теги, список хостов и редиректы, симлинк в образе, `codesign`; машина состояний: «готово» переживает проверки, двойной клик готовит один раз, другая копия, неудачная проверка ждёт час, запуск проверяет всегда, пустая проверка и затем найденный релиз) и живая DEBUG-проверка: копия debug-бандла 0.2.0 в /tmp, лента file:// с DMG 0.3.0 → плашка, лист, «Обновить» → старый процесс вышел, на месте бандл 0.3.0, образ отключён, лишних файлов нет, сессия восстановлена, плашки нет.
