# Hangar — дизайн

Дата: 2026-10-18
Статус: на ревью

## 1. Цель

Нативная замена Pane (Electron) для работы с AI-агентами на macOS.

- Меньше энергопотребления: в простое приложение почти не тратит CPU.
- Проще интерфейс: только то, что используется каждый день.
- Терминал — libghostty (GhosttyKit), рендер и поведение как в Ghostty.

**Критерий успеха:** Pane закрыт, Hangar используется каждый день; в простое (агенты не работают) процесс Hangar держит < 1% CPU и заметно меньше RAM, чем Pane на том же наборе вкладок.

### Что пользователь сказал явно

- Обязательно: несколько вкладок-агентов в сессии, статус агентов, просмотр файлов и git diff (только просмотр), ручная правка кода с LSP.
- Агенты: Claude Code и Codex.
- Правка кода — встроенный редактор Monaco во вкладке «Редактор» (#80, #81); Helix и терминальные редакторы убраны.
- Структура: проект → сессии → вкладки; worktree у сессии — опционально.
- CLI и MCP для управления приложением — сразу, в первой версии.
- После закрытия и повторного открытия восстанавливаются все сессии и вкладки.
- Агент по умолчанию — claude, меняется в настройках.
- Визуальный стиль — «Ghostty-native» (тёмный, плотный), сайдбар на всю высоту, вкладки — внутри области сессии.

### Допущения

- Только macOS 14+, Apple Silicon.
- Тема, шрифт и клавиши терминала берутся из конфига Ghostty пользователя (`~/.config/ghostty/config`).
- Миграции данных из Pane нет.
- Горячие клавиши `⌘…` работают в любой раскладке, включая русскую (сопоставление по keyCode, а не по символу).

### Вне рамок первой версии

Git-действия (stage/commit/push/PR), встроенный браузер, собственный редактор кода (кроме встроенного Monaco по слову пользователя, #80), онбординг, синхронизация, Linux/Windows.

## 2. Архитектура

Swift (AppKit + SwiftUI), один Swift Package с модулями и Xcode-проект приложения. Рядом — CLI-бинарник `hangar`.

| Модуль | Ответственность | Зависит от |
|---|---|---|
| `GhosttyBridge` | Обёртка над C-API GhosttyKit: app/surface lifecycle, ввод, события (title, bell, desktop notification, child exit), чтение текста экрана, пауза рендера. Единственное место, знающее про нестабильный API. | GhosttyKit.xcframework |
| `Workspace` | Модель Project → Task → Tab (+ сплиты), сериализация в JSON, восстановление. Чистая логика. | — |
| `Git` | Вызов `git` CLI: default branch (`origin/HEAD`), список веток, `fetch`, `worktree add/remove`, `status --porcelain=v2`, `diff`. | git |
| `AgentStatus` | Приём событий агентов, свёртка в статус вкладки и сессии. | — |
| `Usage` | Лимиты подписок: приём `rate_limits` от `hangar statusline`, вызов `codex app-server`, свёртка в окна, пороги. | `ControlServer`, `Exec` |
| `Integration` | Правка файлов агентов (`~/.claude/settings.json`, `~/.codex/config.toml`): показ diff, копия, запись, откат (#43). | — |
| `History` | Прошлые разговоры агентов папки (jsonl Claude/Codex, только чтение, голова+хвост, кэш по mtime) — локально и через runner хоста (#74). | `Exec`, `AgentStatus` |
| `Update` | Обновления из GitHub Releases (#86): `releases/latest`, сравнение версий, загрузка DMG и `.sha256`, проверка, `hdiutil attach`, проверка bundle id и версии, скрипт-помощник замены бандла. | `hdiutil`, `ditto` |
| `Power` | Блокировка сна, пока есть вкладки в `working` (число работающих передаёт UI). | IOKit |
| `Exec` | «Где выполнять»: локально (`Process`) или на SSH-хосте (через общий мастер-процесс `ssh -M` без `ControlPersist`, #47). Через него ходят `Git`, `Usage`, запуск вкладок. | ssh |
| `ControlServer` | Unix-сокет, JSON-протокол (запрос/ответ, по строке на сообщение). Обслуживает hooks, CLI и MCP. Этап 3 — типы `event` и `usage`; этап 5 — запросы/ответы (#45). | `Workspace`, `AgentStatus` |
| `UI` | Окно, сайдбар, полоса вкладок, сплиты, инспектор, diff-вкладка, лист новой сессии, настройки. | все выше |
| `hangar` (CLI) | Подкоманды CLI + `hangar mcp` (MCP-сервер со stdio). Ходит в сокет. | протокол `ControlServer` |

Сборка GhosttyKit: скрипт `scripts/build-ghosttykit.sh` клонирует Ghostty на закреплённом коммите и собирает xcframework через Zig. Обновление Ghostty = смена коммита + правки только в `GhosttyBridge`.

Данные: `~/Library/Application Support/Hangar/state.json` (состояние), `update.json` рядом (последняя проверка обновлений, пропущенная версия, найденный релиз), сокет `~/Library/Application Support/Hangar/hangar.sock`, конфиг `~/.config/hangar/config.toml`.

## 3. Модель данных

- **Project**: id, имя, путь к репозиторию, последняя выбранная базовая ветка, worktree по умолчанию (вкл/выкл), папка worktree (необязательно; сюда идут все worktree проекта), список «копировать в worktree» (игнорируемые пути/маски) и команда после создания; без своего списка — по lockfile (pnpm/yarn/bun: `.env*` и т. п., npm: ещё клон `node_modules`); команда install по lockfile только предлагается и выполняется лишь сохранённой в проекте — #58.
- **Task**: id, имя, project id, режим (`main-folder` | `worktree`), путь worktree, ветка, базовая ветка, порядок, архивирована ли.
- **Tab**: id, task id, тип (`claude` | `codex` | `editor` | `shell` | `diff`), заголовок, дерево сплитов (каждый лист — surface со своим типом), `agentSessionId` (для resume), cwd, открытый файл (для editor).
- **Leaf** (панель сплита): id (сохраняется при переносах между вкладками — статусы, `--resume` и «Входящие» идут за панелью), вид (`claude` | `codex` | `shell` | `editor`; `choose` — панель-«выбор», в файл не пишется), своё имя `customTitle` (необязательно). Операции над деревом — слияние вкладки в край панели, перенос и вынос панели — `docs/superpowers/specs/2026-10-28-splits-design.md` (#101).
- Diff-вкладка временная: не сохраняется и не восстанавливается.

## 4. Интерфейс

Дизайн-система: `docs/design/DESIGN.md`. Эталонные макеты: `docs/superpowers/mockups/style-a-v2.html` (основной экран, diff), `new-task-v4.html` (новая сессия), `style-a-screens.html` (уведомление, ранние варианты).

- **Сайдбар** (на всю высоту, светофор над ним): «+ Новая сессия», закреплённые, проекты (сворачиваемые группы) → сессии, архив; у сессии — точка статуса или иконка worktree. Ширина перетаскиванием сохраняется; `⌘0` сворачивает в рейку 44 с монограммами (решения #32, #35).
- **Область сессии**: строка заголовка «Проект · Сессия» по центру и кнопка инспектора справа; ниже — вкладки со статус-точкой и иконкой агента, `+` (меню: Claude, Codex, Редактор, Shell). Сплиты (#101, `docs/superpowers/specs/2026-10-28-splits-design.md`): `⌘D` / `⇧⌘D` — новая панель-«выбор» (Claude, Codex, Терминал, Редактор, «Продолжить»); панель любого вида; у панелей разделённой вкладки — заголовок (иконка, статус, имя, «⇱», «×», меню); вкладка, утянутая на край панели, становится её половиной, заголовок панели — на край другой панели или в строку вкладок; агенты при этом не перезапускаются. Переносы — только внутри сессии.
- **Инспектор** справа (`⌘⌥I` скрыть/показать), сегменты `Files` / `Changes N` / `Git` / `Search` (поиск в файлах, `⇧⌘F`, #91).
  - Files: дерево файлов (с учётом `.gitignore`), бейдж M/A/D. Клик — открыть во вкладке «Редактор» сессии (Monaco, файл добавляется вкладкой файла внутри неё), иначе в новой.
  - Changes: изменённые файлы. Клик — временная diff-вкладка (курсивом); следующий клик заменяет её. По умолчанию diff относительно merge-base с базовой веткой, `⌥B` — только незакоммиченное (при активной diff-вкладке; иначе — клик по подсказке под Changes). `↑/↓` — соседний файл, `Enter` — открыть в Helix на строке. Подсветка синтаксиса отложена (#44).
- **Строка состояния окна** (внизу на всю ширину, DESIGN.md «Строка состояния окна», #75): «Этот Mac» или хост, проект выбранной сессии, ненулевые счётчики агентов проекта (работают — с субагентами, ошибки) и «ждут внимания» — число колокольчика по всем проектам (#96); справа — число панелей активной вкладки и процесс в фокусе. Ветка — в строке заголовка «Проект · Сессия ⎇ ветка».
- **Новая сессия** (`⌘N`): название; карточка настроек: Worktree (переключатель), От ветки (выпадающий список с поиском: сначала remote, по умолчанию из `origin/HEAD`; затем локальные), Новая ветка (из названия: само название, если в нём есть `/` и это допустимое имя ветки вроде `feat/JS-13333`, иначе slug — #48; редактируемая); поле «Первое сообщение для claude». Без worktree строки веток неактивны, внизу — текущая ветка. Перед созданием worktree — `git fetch`; подробности (fetch, валидация `check-ref-format`, ошибка «ветка уже существует», не-git проект — строк worktree нет) — решение #42. После создания worktree в него клонируются игнорируемые файлы из списка проекта (прогресс «Копирую node_modules…» в подвале), строка «После создания: <команда>» с переключателем (предложенная по lockfile — выключена; включил — сохраняется в проект), команда и ошибки копирования — во второй вкладке shell в корне worktree (#58). Настройки проекта: имя, путь, ветка по умолчанию, папка worktree (с подсказкой «сюда создаются все worktree»), «Копировать в worktree», «Команда после создания».
- **Архив** (`⌘⇧W`, меню сессии; #57): сессия без worktree просто уходит в архив. У сессии с worktree вкладки останавливаются (удалённые tmux-сессии убиваются), папка worktree удаляется (атомарный `mv` в `<путь>.hangar-removing`, `git worktree prune`, удаление в фоне; оставшиеся после выхода надгробия убираются при запуске — #59), ветка остаётся. Незакоммиченные изменения или файлы вне git (`.env`) — сначала подтверждение со списком, как при удалении. Удалённый проект — то же на сервере; хост не подключён — отказ, ничего не меняется. «Восстановить» и «Отменить» в тосте заново создают worktree, если по пути нет рабочего worktree (`rev-parse`; неполная папка без `.git` с именем worktree ветки: пустая убирается, с файлами сохраняется как `<путь>.hangar-orphan-<время>`; #59), из ветки (`git worktree add <путь> <ветка>`) и открывают вкладки; ветки нет — ошибка и предложение восстановить сессию в папке проекта.
- **Быстрый переход** как в VS Code: `⌘P` — сессии всех проектов и файлы текущей сессии, `>` в начале запроса — команды из таблицы клавиш; `⇧⌘P` — сразу команды. Нечёткий поиск, группы; `⌘K` остаётся Ghostty (#65).
- **Требуют внимания** (`⌥⌘F`, точка-переключатель в заголовке «Проекты», тултип «Только ждущие — ⌥⌘F»; #67): в сайдбаре только сессии со статусом waiting/failed, по-прежнему под своими проектами (закреплённые — тоже под проектом, секция «Закреплённые» скрыта; свёрнутый проект остаётся свёрнутым); проекты без таких сессий скрыты, пусто — «Никто не ждёт». Перетаскивание выключено. Состояние сохраняется (`attentionOnly` в state.json).
- **Ссылки** `hangar://task/<id>`, `hangar://tab/<id>`, `hangar://project/<id>`, `hangar://sessions/<id проекта>`, `hangar://host/<хост>` (#66, #88): клик выбирает сессию / вкладку (с фокусом терминала) / раскрывает проект / показывает «Сессии» только этого проекта (чип «Проект: … ×», #107) / терминал хоста или сессию его проекта; ничего не запускает и не подключает. id — только полный UUID. Неверная ссылка или её цели нет — тост «Ссылка никуда не ведёт», больше ничего. «Скопировать ссылку» — в контекстном меню проекта, сессии, вкладки и хоста.
- **Клавиши**: `⌘1…8` вкладки, `⌘9` последняя вкладка, `⇧⌘[`/`⇧⌘]` сессии, `⌘N` сессия, `⌘T` вкладка (shell), `⌘W` закрыть фокусную панель (последнюю — с вкладкой; агент работает или ждёт — подтверждение), `⌘D`/`⇧⌘D` сплит, `⌘0` сайдбар, `⌘J` нижний терминал (и ``⌃` ``), `⇧⌘N` проект, `⌥⌘I` инспектор, `⌥⌘1`/`⌥⌘2`/`⌥⌘3` инспектор на Files/Changes/Git, `⇧⌘F` поиск в файлах (`⌥⌘4` — синоним), `⌥⌘R` открыть в Finder, `⌥⌘C` скопировать путь. Полная таблица — DESIGN.md «Тултипы и клавиши».
- **Настройки**: короткий экран + `config.toml` (`default_agent`, команды агентов и их аргументы, внешний редактор `external_editor`, `theme` = `dark-plus`/`graphite`/`navy` (тема приложения, решение #85) (фон терминала — всегда фон темы, #109; прежний `terminal_background` игнорируется), тема редактора `editor_palette` (по умолчанию `theme` — пара темы оформления, #109), уведомления: `notifications` (общий выключатель баннеров), по причинам `notify_permission`/`notify_question`/`notify_done`/`notify_failed` и `limit_notifications`, звуки `sound_<причина>` (`""` — без звука, `"default"`), `notify_when_active`, `allow_from_notification`, `ssh_terminal_bell`, `dock_badge`; `keep_awake` — «не засыпать», §5.2). Уведомления проекта (все / срочные / выкл.) и «Без уведомлений» сессии — в `state.json` (#96).

## 5. Статусы агентов

Статусы: `working`, `waiting`, `done`, `failed`, `idle`.

Каждая surface стартует с env `HANGAR_TAB_ID`, `HANGAR_LEAF_ID` (статус хранится на лист; событие с tab, не владеющим leaf, игнорируется), `HANGAR_SOCKET` и `HANGAR_PORT` — порт сессии (#60: стабильный, из id сессии в 41000–48999, уникальный среди сессий, хранится в модели; локально и на сервере; в меню сессии «Порт: N (копировать)»). `hangar event <kind> [--session <id>]` отправляет событие; без `HANGAR_TAB_ID` молча выходит с кодом 0 (не ломает агентов вне Hangar).

- **Claude Code**: Hangar предлагает (с подтверждением и показом diff) добавить hooks в `~/.claude/settings.json`: `SessionStart` (id сессии), `UserPromptSubmit` → working, `PostToolUse` (matcher `*`) → working, `Notification` → waiting только для `permission_prompt`/`elicitation_dialog` (`idle_prompt` не трогает статус), `Stop` → done, `StopFailure` matcher `rate_limit` → failed + `limitReached`; у каждого `"timeout": 5` (#43). `session_id` из payload hook сохраняется в листе.
- **Codex**: `notify` в `~/.codex/config.toml` → done (+ session id). `waiting` — по bell/OSC-уведомлению от surface. Точность проверяется на практике и дорабатывается.
- **Запасные пути (#43)**: bell/OSC-уведомление → waiting только у листов claude/codex и только если у листа не было hook Claude; гаснет в idle при фокусе листа.
- **Все**: выход процесса с кодом > 0 → failed, иначе idle; перезапуск → idle.
- **Статус сессии** = максимальный из вкладок по приоритету waiting > failed > working > done > idle.
- **Уведомления и «Входящие»** — по причинам (разрешение, вопрос, ошибка, лимит, готово), с кнопками «Разрешить» / «Ответить» под защитой `requestKey`, группировкой по сессии и уборкой; колокольчик «Входящие» в заголовке, ⌥⌘A, число Dock = разрешения + вопросы + ошибки; настройки по причинам, проекту и сессии. Дизайн — `docs/superpowers/specs/2026-10-27-notifications-design.md`, решения — #95 (спайк), #96 (поведение и итог живой проверки).

## 5.1 Лимиты подписок

Макет: `docs/superpowers/mockups/limits.html`.

**UI.** Внизу сайдбара — строка на каждого агента (claude, codex): две полоски (окно 5 ч и неделя) и максимальный процент. Клик или `⌘⇧L` — поповер: план, каждое окно (у Claude — все пришедшие окна, включая отдельные недельные по моделям, если они есть), процент, время сброса, «обновлено N мин назад», кнопка ↻. Пороги: ≥ 80% — жёлтый и «почти лимит», ≥ 95% или исчерпан — красный и «лимит исчерпан». Если лимит агента исчерпан, точки его вкладок тоже красные. Уведомление macOS — один раз при пересечении 80% и при исчерпании окна (выключается в настройках). Строка агента не показывается, если данных нет (агент не установлен, вход по API-ключу).

**Модель.** `UsageWindow { kind: session | weekly | weekly_model(name), usedPercent, resetsAt, updatedAt }`, по агенту — список окон, план и флаг `limitReached`. Окно с прошедшим `resetsAt` сбрасывается в 0% (ожидаем свежие данные). Все поля во входных данных опциональны.

**Claude — только документированные источники:**
- Статус-лайн. Hangar (с согласия, как и hooks) прописывает `statusLine` = `hangar statusline`. Команда читает JSON из stdin, отправляет все окна `rate_limits` — `five_hour`, `seven_day` и недельные по моделям `seven_day_<model>` (`used_percentage`, `resets_at`) — в сокет, затем вызывает исходную статус-лайн пользователя (если была) с тем же stdin и печатает её вывод. Исходная команда хранится в самой команде: `'<cli>' statusline --then '<исходная команда>'`, остальные ключи `statusLine` не трогаются; откат восстанавливает её оттуда. Путь CLI — `Hangar.app/Contents/Helpers/hangar` (#43). Данные приходят только для Pro/Max и только пока в какой-то вкладке работает claude, поэтому показываем возраст данных.
- Исчерпание: hook `StopFailure` с matcher `rate_limit` → `limitReached`.
- Недокументированный OAuth usage endpoint не используем.

**Codex:**
- Основной: `codex app-server` (JSON-RPC по stdio), метод `account/rateLimits/read` → окна `{usedPercent, windowDurationMins, resetsAt}`. Процесс короткоживущий: запускается при открытии поповера, по ↻ и после события «ход закончен» (не чаще раза в минуту), затем завершается. Окна различаем по `windowDurationMins` (300 — сессия, 10080 — неделя), а не по позиции.
- Резервный: последнее событие `token_count` с `rate_limits` в свежем rollout-файле `~/.codex/sessions/**` (форматы ≥ 0.48; если событий нет — источник пропускается).
- Исчерпание: ошибка `UsageLimitExceeded` / текст «You've hit your usage limit» → `limitReached` до `resetsAt`.
- Недокументированный `/wham/usage` не используем.
- Примечание: `notify` в Codex помечен как legacy. Если у установленной версии есть новые hooks (`~/.codex/hooks.json`), статусы и триггер обновления лимитов берём из них, `notify` — запасной путь. Проверяется в спайке.

## 5.2 Не засыпать, пока агенты работают

- Включается переключателем в настройках и иконкой ☕ в строке внизу сайдбара (по умолчанию включено). Иконка подсвечена, когда блокировка активна; тултип — сколько агентов работает.
- Пока есть хотя бы одна вкладка в `working` (локальная или удалённая) — держим `IOPMAssertion` `PreventUserIdleSystemSleep` с фиксированным английским именем «Hangar: 1 agent working» / «Hangar: N agents working» (в паузе после последнего агента — «Hangar: agents finished, keeping awake briefly») (`pmset` не показывает кириллицу, #46). Экран может гаснуть.
- Снятие — через 2 минуты после того, как `working`-вкладок не осталось (чтобы не дёргать между ходами). Таймер снятия — единственный: взводится на переходе «работающих стало 0» при удерживаемой блокировке; в простое без блокировки таймеров нет (#45). Выключение фичи или выход из приложения снимает сразу.
- Работа с закрытой крышкой без внешнего монитора и питания не поддерживается (нужен root, `pmset disablesleep`) — не делаем.

## 6. Сохранение и восстановление

- Состояние пишется на диск при изменениях (debounce 500 мс) и при выходе; запись атомарная (temp + rename).
- При запуске восстанавливаются проекты, сессии, порядок, вкладки, сплиты (пропорции, фокусная панель, имена панелей), активная сессия и вкладка, состояние инспектора. Панель-«выбор» не сохраняется: при записи и чтении убирается, вкладка только из неё исчезает (#101).
- Вкладки:
  - claude → `claude --resume <sessionId>`; без `sessionId` → `claude --continue` в cwd (подтверждено спайком);
  - codex → `codex resume <sessionId>`, если id нет — `codex resume --last` в cwd сессии;
  - без id продолжает не больше одного листа на (агент, хост, папку), и только если ни у одного листа там id нет; остальные стартуют заново (#41, #62, #89);
  - editor → редактор с тем же файлом;
  - shell → новый shell в том же cwd.
- Процессы не переживают выход. `⌘Q` при наличии вкладок в `working` спрашивает подтверждение.
- Повреждённый `state.json` (и висячий симлинк на него) → перенос в `state.json.bak`, старт с пустым состоянием и предупреждение.

## 7. CLI и MCP

`hangar` (протокол — JSON по Unix-сокету):

| Команда | Действие |
|---|---|
| `hangar projects list` / `add <path> [--host H]` | проекты (с `--host` — папка на сервере, #45) |
| `hangar sessions list [--project] [--git]` | сессии со статусами (и лист панели TERMINAL — его id годится как `--tab`); с `--git` (MCP `git: true`) — `changes {added, removed, files}` относительно базы, `dirty`, `ahead`/`behind` базы (#63) |
| `hangar sessions create --project P --name N [--worktree --base B] [--prompt T]` | создать сессию |
| `hangar tabs open --session S --kind claude\|codex\|editor\|shell [--prompt T]` | новая вкладка |
| `hangar tabs send --tab ID [<text>] [--enter] [--key K]… [--wait]` | вставить текст, затем нажать клавиши (`enter`, `escape`, `tab`, `backspace`, `up`, `down`, `left`, `right`, `ctrl-c`, `ctrl-d`, `interrupt`); `--wait` ждёт начала хода claude (решение #62) |
| `hangar tabs read --tab ID [--lines N]` | последние N строк экрана (по умолчанию 100) |
| `hangar sessions archive --session S --yes [--force]` | архивировать; worktree удаляется, ветка остаётся (#57); грязный worktree или ignored-файлы — отказ без `--force` (MCP `force: true`) |
| `hangar sessions restore --session S` | вернуть сессию из архива; worktree создаётся заново из сохранённой ветки (#57); ветки нет — ошибка, без изменений. Не разрушительно, `--yes` не нужен (#63) |
| `hangar doctor [--json]` | только чтение (#61): приложение и сокет, версии CLI/приложения, claude/codex с версиями, hooks в ~/.claude и ~/.codex, ресурсы Ghostty, ssh-хосты проектов (подключён, tmux, hangar-remote), keep-awake, свободное место у папки состояния; строка ok/warn/fail с подсказкой; код 1, если есть fail; MCP `doctor` |
| `hangar ssh <host>` | открыть в приложении вкладку с обычным `ssh -t` на хосте, без проекта (#64; MCP `ssh_open`) |
| `hangar link session\|tab\|project\|host\|sessions <ref>` | напечатать ссылку `hangar://…` с полным id (MCP `links_create`, #66, #88); `host` — имя из SSH HOSTS, `sessions` — вид «Сессии» проекта `<ref>` |
| `hangar event <kind>` | событие от hooks |
| `hangar mcp [--read-only]` | MCP-сервер (stdio) с теми же операциями; `--read-only` — только `projects_list`, `sessions_list`, `tabs_read`, `doctor`, остальные отклоняются (#63) |

Разрушительные операции без `--yes` (в MCP — `yes: true`) отклоняются. Все команды поддерживают `--json`.

- Ссылки (`--project`, `--session`, `--tab`): полный UUID, уникальный префикс id (≥ 4 символов) или имя (вкладки — только id); неоднозначность — ошибка со списком id (#45).
- Коды выхода: 0 — успех; 1 — ошибка приложения, Hangar не запущен, таймаут; 2 — ошибка использования или нет `--yes`. С `--json` результат — JSON в stdout, ошибка — `{"error":{"code","message"}}` в stderr.
- Вывод CLI и MCP — английский (машинный интерфейс, вне `L10n`).
- Сессии (#73): основное имя — `hangar sessions …`, `--session`, MCP `sessions_list|create|archive|restore` и аргумент `session`. Старые `hangar tasks …`, `--task`, `link task`, MCP `tasks_*` и аргумент `task` принимаются молча (в tools/list их нет). Ключи `--json` (`tasks`, `task`), методы сокета `tasks.*` и ссылки `hangar://task/…` не меняются ради совместимости.
- MCP подключается командами `claude mcp add --scope user hangar -- '<cli>' mcp` и `codex mcp add hangar -- '<cli>' mcp`; настройки показывают их с кнопкой «Скопировать», конфиги агентов Hangar не правит.

## 8. Ошибки

- Нет git / не репозиторий → проект без Changes и worktree.
- Ошибка `git fetch`/`worktree add` → лист новой сессии не закрывается, показывает stderr git.
- Нет коммитов → worktree недоступен. Fetch не прошёл → stderr + кнопка «Создать без fetch».
- Hooks не установлены → статусы только по bell/exit, в настройках — предупреждение с кнопкой установки.
- Сокет занят (второй экземпляр) → по успешному `connect` активировать существующий экземпляр (pid собеседника, `LOCAL_PEERPID`), новый процесс выходит; мёртвый сокет удаляется (#43).
- Агент не найден в PATH → вкладка показывает сообщение и команду установки.

## 9. Энергопотребление

- Скрытые вкладки и сессии: рендер поверхностей на паузе (occlusion / API Ghostty).
- Git-статус: FSEvents с `latency` 0.3 с, только для видимой сессии; без таймеров. Событие во время загрузки не отменяет её, а ставит флаг «повторить» — после завершения ровно одна повторная загрузка (#44).
- В простое — ноль периодических таймеров и опросов.
- Проверка: `powermetrics` и Activity Monitor (Energy Impact) против Pane на одном сценарии (3 сессии, 6 вкладок, агенты в простое 10 минут).

## 11.1 SSH-проекты (этап 6)

Архитектура закладывается с этапа 1: все команды идут через `Exec`, проект хранит `location: local | ssh(host, path)`.

- **Локальный диск** (этап 6): у удалённого проекта путь никогда не читается с Mac — git, `lastFetch`, «есть ли папка» при удалении worktree и в настройках проекта идут через `Runner` хоста (`AppState.runner(for:)` / `git(for:)`; без соединения — сразу `notConnected`); подбор имени ветки не проверяет папку worktree (её занятость сообщит `git worktree add`); `~` в путях не раскрывается. Серость проекта и `exists` в `projects list` — по состоянию хоста (`unreachable`), не по диску; `ProjectInfo.host`, человеческий вывод `<host>:<path>`. «Открыть в Finder» и внешний редактор для удалённых выключены, «Скопировать путь» даёт `host:path`. Удаление worktree: проверки (папка, незакоммиченное, ignored-файлы) — на сервере; проверка, которая не ответила, останавливает удаление с ошибкой (не считается «чисто» или «папки нет»). Так же хост без соединения не выглядит как «не репозиторий» (лист «Новая сессия» пишет «Нет соединения с <host>», `tasks.create` — `host <host> is not connected`) или «папка не найдена» (настройки проекта).
- **Добавление проекта**: «+ проект» → «Удалённый» → хост из `~/.ssh/config` (или `user@host`) и путь. Аутентификация — через системный ssh и агент ключей; пароли Hangar не хранит.
- **Простое подключение** (#64): без проекта — «Подключиться к хосту…» (`+` SSH HOSTS, «+ проект») или клик/«Открыть терминал» на строке хоста, CLI `hangar ssh <host>`. Псевдосессия «<host> · терминал» под строкой хоста; её вкладки — обычный `ssh -t <host>` в домашней папке: без мастера, проверки сервера, установки и tmux (закроется при разрыве; ↩ — войти снова). SSH HOSTS сразу показывает хосты из `~/.ssh/config` (с `Include`), перечитывая его при активации приложения; хост без проектов — без состояния.
- **Подключение** (#47): один мастер на хост — дочерний процесс Hangar `ssh -M -T -S <cp> -o ControlPersist=no -o BatchMode=yes`; удалённая сторона печатает `HANGAR-READY <$HOME>` и ждёт на stdin. Готовность — маркер, обрыв — выход процесса (без опроса `-O check`). `ControlPath` в `<state>/ssh/`, при длинном пути — `/tmp/hangar-<uid>/`. Все вкладки, git и служебные команды переиспользуют его; команды идут с PATH логин-шелла, который увидела проверка сервера (там же она нашла `git` и `tmux`). Только системный ssh и конфиг пользователя; пароль и 2FA в фоне не поддерживаются — подсказка выполнить `ssh <host>` в Терминале.
- **Проверка и установка окружения** при каждом подключении (молча, одна команда через мастер) и по кнопке «Проверить сервер»: определяем ОС и пакетный менеджер, проверяем `git`, `tmux`, `claude`, `codex`, скрипт `hangar-remote` и интеграции (hooks, statusline). Показываем список «есть / нет / версия» и план установки с точными командами; устанавливаем только после подтверждения пользователя (sudo — его пароль вводится в терминальной вкладке, Hangar его не видит). Отсутствующий необязательный инструмент (например `codex`) не блокирует работу.
- **Вкладки** (#47): каждый удалённый лист — сессия tmux `hangar-<leafId>` на сервере; surface запускает `ssh -t host tmux new -A -s hangar-<leafId> …`. Агенты переживают обрыв связи и сон Mac. Код выхода 255 — сессия не закончилась (обрыв или detach): лист не `failed` и не закрывается, ↩ и переподключение делают `reattach` к той же сессии; собственный код агента 255 превращается в 254. Код 0 — лист закрывается, как локальный. Закрытие листа/вкладки, архив и удаление сессии убивают сессию, выход из Hangar — нет. Если tmux поставить нельзя — обычный `ssh -t`, восстановление через `claude --resume` / `codex resume`.
- **Статусы и лимиты** (#47): на сервер пробрасывается не основной сокет, а отдельный сокет хоста (`mkdir -p -m 700 ~/.hangar/run && rm -f ~/.hangar/hangar.sock`, затем `ssh -S <cp> -O forward -R <home>/.hangar/hangar.sock:<state>/ssh/r-<id>.sock`; `<home>` — из `HANGAR-READY <$HOME>`, sshd `~` не раскрывает). В сессию передаются `HANGAR_TAB_ID`/`HANGAR_LEAF_ID`/`HANGAR_SOCKET=<home>/.hangar/hangar.sock`. Он принимает только `hook`/`statusline`, одно сообщение на соединение и события только для листов проектов этого хоста. `hangar-remote` — POSIX sh-скрипт (без Swift-бинарника) с тем же argv, что `hangar event` / `hangar statusline`; JSON в sh не разбирается — заголовок + сырые байты, разбор в Swift на Mac. При обрыве события теряются, статусы сохраняются до переподключения.
- **Файлы и diff**: `git ls-files`, `git status --porcelain=v2`, `git diff` через `Exec`; обновление — при показе сессии, когда окно становится key, после `done` агента и после переподключения хоста, если инспектор показывал «нет соединения» и виден (FSEvents удалённо нет; скрытый загрузится при показе), без таймеров. Хост не подключён — одна спокойная строка «Нет соединения с <host>» вместо ошибки git; удалённая папка без git — «дерево файлов недоступно» (без листинга каталога).
- **Worktree** — `git worktree add` на сервере; файлы редактора читаются и пишутся через ssh хоста (#80).
- **Ошибки**: хост недоступен → сессии проекта серые с «переподключиться»; обрыв — автопереподключение с backoff 2, 4, 8, 16, 32, 60… с, не больше 10 попыток, только пока приложение активно или у хоста были `working`-листья; после пробуждения — одна проба с таймаутом 10 с (#47).
