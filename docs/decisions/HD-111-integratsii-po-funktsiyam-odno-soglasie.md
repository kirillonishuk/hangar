# HD-111 — 2026-10-30 — Интеграции по функциям: одно согласие, тихие обновления, MCP с приложением (спека `specs/2026-10-29-integrations-v2-design.md`, макет `integrations-v2.html`; меняет HD-015/HD-043 в части установки, HD-045 в части MCP, HD-096 в части владения).

Слово владельца: функции группируются по агенту, а не по машине, и действуют везде (этот Mac и каждый согласованный ssh-хост; новый — при первом подключении); MCP включается вместе с приложением; согласие — один раз. (1) **Конфиг** (голые ключи, HD-043): `claude_integration` / `codex_integration` (нет ключа — ещё не решено; `false` — «Не сейчас» или выкл.), `claude_hooks`, `claude_limits`, `claude_mcp`, `codex_notify`, `codex_mcp` (по умолчанию `true`), `integration_hosts`, `integration_hosts_skipped`; `statusline` — как HD-105. **Миграция v0.8:** при запуске, если `*_integration` нет, а в файле агента есть записи Hangar (хуки / `notify`), пишется `true` (+ функции) — листа у таких пользователей нет (вкладки агентов, восстановленные до этого чтения, молча ждут его и применения файлов, потом спрашивают заново); хост со старой установкой молча попадает в `integration_hosts`. (2) **Применение** — `claudeApply` / `codexApply` (Integration): желаемое состояние по функциям вместо «установить / обновить»: недостающие хуки дописываются, `claudeHooksRetired` снимаются, выключенная функция снимается, обёртка `statusLine` нужна при `statusline = "hangar"` или «Лимиты» вкл. (иначе исходная строка восстанавливается). Владение (HD-096) расширено: запись Hangar — ровно `<cli> event <kind>` / `<cli> statusline …` / `notify` Hangar, где `<cli>` — текущий helper или путь `…/Contents/Helpers/hangar` копии, которой больше нет (приложение перенесли — запись переводится на текущий путь; снимает ограничение HD-043); helper другой живой копии остаётся её, кроме случая, когда эта копия — `/Applications/Hangar.app` (единственная предпочтительная): так две копии никогда не перетягивают записи. Файл с записями другой копии не меняется вовсе (`IntegrationError.otherCopy`, в «Где установлено» — ошибка с причиной); на хосте — любой `…/hangar-remote`, и без загруженного `hangar-remote` хуки на хост не пишутся (ошибка у хоста). Хуки не зависят от того, найден ли CLI агента. Применение и MCP идут по одному на агента (хост) — запрос во время работы даёт ещё один прогон с актуальным конфигом. Пишется только через `writeUserFile` / `remoteFileWriteScript` (копия, атомарно, отказ при изменении). Когда: запуск (Mac), подключение хоста, переключатель в Настройках; хосту без `hangar-remote` он ставится тем же шагом загрузки, что в «Сервере». «Лимиты» выкл. — приложение не принимает `usage` Claude (вместо правки CLI: тот же результат для Mac и хостов). (3) **MCP — только этот Mac** (HD-047: сокет хоста не принимает команд), через CLI агентов, решение — по чтению их файлов (`claude mcp get` запускает сервер — не вызывается): `mcpServers.hangar` в `$CLAUDE_CONFIG_DIR/.claude.json` или `~/.claude.json`, `[mcp_servers.hangar]` (таблица, inline, dotted) в `config.toml` Codex. Нет записи и `*_mcp` вкл. → `claude mcp add --scope user hangar -- <cli> mcp` / `codex mcp add hangar -- <cli> mcp`; наша со старым путём → Claude `remove` + `add`, Codex `add` (upsert); выкл. → `remove` только нашей; чужая (другая команда, env, args) и запись другой копии — не трогаются. CLI запускаются через логин-шелл (PATH, `CLAUDE_CONFIG_DIR`); исполняемый файл — первое слово команды `[agents]`, только если это сам `claude`/`codex` (обёртка `npx …` / `env …` → ищется просто `claude`), путь из `command -v` (в т. ч. alias на абсолютный путь); CLI нет — пропуск, строка «не найден». MCP не зависит от главного переключателя агента («Не сейчас» его не снимает, как в спеке); у него свой переключатель. DEBUG: ищется только абсолютная команда `[agents]` (фейк), настоящие CLI не запускаются. (4) **Первый запуск:** вкладка claude/codex (или ssh-вкладка нового хоста) при нерешённом ключе не стартует (`LaunchError.awaitingConsent`, полоса «Ждёт ответа…») — лист «Подключить Hangar к …?» (функции, «Куда», «Что изменится» = точный diff, «Не сейчас» / «Подключить»); любой ответ запускает вкладку, «Подключить» — после записи Mac и подключённых хостов. Новый хост — лист «Подключить Hangar на <host>?» без переключателей («Не на этом хосте» / «Подключить»); вкладки хоста ждут решения после подключения (если интеграцию включили уже после подключения хоста, решение запускает сама ждущая вкладка). Ответ «Подключить» отпускает вкладки сразу после записи Mac, хосты применяются в фоне; ответ, который не удалось сохранить, действует до перезапуска (лист не повторяется), ошибка показывается. Без собранного helper (тесты, `swift run`) или из DMG ничего не спрашивается. (5) **Убрано:** строки установки и `IntegrationSheet` в Настройках, команды MCP с «Скопировать» (HD-045 «Hangar сам конфиги агентов не правит» заменено: правит через CLI агента, только свою запись), строки интеграций в листе «Сервер». Окно настроек остаётся 970×600 / мин. 680×440 (HD-109), а не 760×480 из спеки. **Отложено:** хуки Codex (открытый вопрос 2 спеки). **Отвергнуто:** правка `~/.claude.json` напрямую (горячий файл, пишется живыми сессиями); `claude mcp get` для проверки; MCP на хостах; настройки по машинам.
