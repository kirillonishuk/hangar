# HD-154 — 2026-11-13 — Архив спрашивает до остановки вкладок; кэши инструментов не «файлы вне git»; чат после архива (слово владельца; дополняет HD-057, HD-132).

Владелец: «удаляю ворктри — оно пропадает, потом появляется и выскакивает модалка "В копии есть файлы вне git: .claude/.cache/"; хотелось бы историю чатов хранить». (1) **Сначала вопрос.** Было (HD-057): вкладки останавливались и сессия уходила в архив до проверки, а при риске возвращалась обратно — сессия исчезала из сайдбара и появлялась уже с вопросом. Теперь `archiveOne` без `force` сначала проверяет папку (`checkWorktree`, та же функция; оверрайд строки состояния HD-105 на время проверки снимается и возвращается) — при риске `.atRisk`, ничего не остановлено и не заархивировано. Чистая папка — дальше как раньше: остановка, повторная проверка (агент мог дописать в промежутке; тогда, как раньше, сессия возвращается) и удаление. «В архив всё равно» удаляет только то, что было в вопросе: обе проверки (до и после остановки) идут и при `force`, и если появилось новое — копия стала грязной, изменился или добавился незакоммиченный путь (сравнивается отпечаток `Git.dirtyFingerprint`: буквы `git status` и хэш содержимого каждого пути, так что ещё одна правка уже изменённого файла тоже новое) или добавился путь вне git, которого в списке не было, — вопрос задаётся снова, ничего не удалено (`WorktreeCheck.isCovered`; без этого агент, работавший пока открыт диалог, терял бы правки, которых пользователь не видел). CLI `sessions archive` и MCP получают `confirm_required` так же, без перезапуска вкладок; их `--force` / `force: true` соглашается с тем, что найдёт первая проверка этого вызова, а новое после остановки вкладок — снова `confirm_required`. Второй архив той же сессии, пока первый проверяет папку (двойной ⌘⇧W, CLI вместе с UI), отказывает (`inProgress`; CLI — `busy`), а не удаляет папку дважды. То же для «Удалить навсегда» с копией: после «Удалить всё равно» папка проверяется снова, и удаляется, только если сессия всё ещё в архиве (её могли восстановить через CLI/MCP) и в копии не больше, чем было в вопросе; иначе вопрос задаётся снова. (2) **Кэши — не потеря.** К переустанавливаемым (`isReinstallable`: `node_modules`, `.venv`, `.turbo`, `dist`, `vendor/bundle`) добавлены кэши инструментов и мусор Finder по последней компоненте пути: `.cache` (в т.ч. `.claude/.cache` Claude Code), `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.next`, `.build`, `.DS_Store`. `.claude/settings.local.json`, `.claude/worktrees/` и весь `.claude/` одной записью (git сворачивает папку, где игнорируется всё) по-прежнему спрашивают. (3) **Чат не в копии.** Разговор агента лежит у агента (`~/.claude/projects/<папка>/<id>.jsonl`, у Codex — `~/.codex/sessions`), архив его не трогает; запись сессии остаётся в архиве («Сессии», ⌘Y), ветка остаётся (HD-057). «Восстановить» заново создаёт копию из ветки по тому же пути, и вкладка claude продолжает тот же разговор (`--resume <id>`, HD-119) — проверено. Удаляет запись только «Удалить навсегда». Ограничение вне Hangar: Claude Code сам чистит старые транскрипты (`cleanupPeriodDays`, по умолчанию 30 дней). **Отвергнуто:** не прятать сессию до ответа без предварительной проверки (лишняя остановка агента ради вопроса, на который можно ответить, не трогая его); `status --ignored=matching` (разворачивает папки в списки файлов — тысячи аргументов у `ignoredAtRisk`); копировать транскрипт в архив Hangar (он и так вне копии).
