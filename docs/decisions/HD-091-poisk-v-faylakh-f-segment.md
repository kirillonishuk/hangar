# HD-091 — 2026-10-27 — Поиск в файлах ⇧⌘F — сегмент Search инспектора (номер 90 занят треком LSP).

Место: четвёртый сегмент правого сайдбара `Files / Changes N / Git / Search` (у папки без git — `Files / Search`), а не палитра: результаты — постоянный прокручиваемый список, сгруппированный по файлам, по которому кликают много раз подряд, а палитра ⌘P закрывается после выбора и держит одну строку на результат; в инспекторе уже есть корень сессии, контекстное меню файла и «один клик — просмотр, двойной — вкладка» (HD-083). Клавиши: ⇧⌘F (как в VS Code; свободна, ⌥⌘F — «Только ждущие») показывает инспектор на Search и ставит фокус в поле; ⌥⌘4 — тихий синоним (продолжает ⌥⌘1…3), в подсказках только ⇧⌘F. Монитор клавиш стоит перед Ghostty и Monaco, `editorKeyRoute` отдаёт Monaco только ⌘F/⌥⌘F — ⇧⌘F доходит до Hangar из терминала, редактора и diff. Панель: поле запроса (вид поля Git-вкладки) с переключателями `Aa` (регистр), `ab` (слово целиком), `.*` (regex), поля «Включить» / «Исключить» (глобы через запятую, как в .gitignore: без `/` — на любой глубине), строка статуса постоянной высоты («N совпадений в M файлах», «Поиск…», «Ничего не найдено», ошибка; справа движок `rg` / `git grep`), группы файлов (шеврон, иконка, имя, папка, число строк) и строки с подсветкой совпадений как в поиске Git-вкладки (`waiting` 28 %). Клик — `openInEditor(path:line:column:)`, колонка 1-based UTF-16, как у Monaco. Движок (`Sources/Git/TextSearch.swift`, без UI): локально `rg --json` (из PATH логин-шелла один раз за запуск, иначе `/opt/homebrew/bin/rg`, `/usr/local/bin/rg`; `--hidden` без `.git`, .gitignore соблюдается и вне репозитория — `--no-require-git`, как `git grep --no-index --exclude-standard`; строки шире 2000 колонок — превью `--max-columns-preview`), иначе `git grep -n -z -I --column` (`--untracked` в репозитории, `--no-index --exclude-standard` в простой папке; `-i`/`-F`/`-E`/`-w`; глобы — pathspec `:(glob)` / `:(exclude,glob)`; без `--column` на git старше 2.19 — повтор без него). Аргументы — массив для `Process`, запрос — значение `-e` перед `--`, глобы — `--glob=…`: ни запрос, ни глоб не становятся опцией или кодом шелла. Байтовые смещения rg переводятся в UTF-16; у git grep совпадения строки ищутся заново тем же запросом (ICU только по первым 4096 UTF-16 символам строки; не прочитал — строка без подсветки, колонка — от git; `finish` парсера — вне главного актора). Потоково: `streamProcess` отдаёт stdout кусками, парсер собирает строки через границы кусков, переводы строк ищет только в новом куске; строка вывода длиннее 1 МБ пропускается, не буферизуясь, и это сказано строкой «N очень длинных строк пропущено» (вместо немого «Ничего не найдено»). Пределы: 2000 строк всего (процесс останавливается, «Показаны первые 2000 строк…»), 200 строк на файл (группа файла появляется только после проверки общего предела — без пустой последней группы), строка показа — 240 символов вокруг первого совпадения. Новый запрос, переключатель или корень завершает идущий процесс; ввод — debounce 250 мс; уход с вкладки Search, смена сессии и выход из приложения тоже завершают процесс (вернулись — поиск заново); в простое ни таймеров, ни процессов. Корень — корень инспектора (worktree/папка сессии, у проекта в подпапке — подпапка). Удалённый проект: `git grep` на хосте через существующий ssh-мастер (`sshStreamArgs`, PATH логин-шелла из проверки сервера), потоково так же; команда на хосте обёрнута сторожем (`remoteWatchdogArgv`): она идёт в фоне, встроенный `read` на stdin сессии (ssh держит stdin открытым — `holdStdin`) при EOF её убивает, так что отменённый поиск не доживает до следующей записи; выход 1 без совпадений с ошибкой самого шелла в stderr (`sh: …`, `cd: …` — например, `cd` в исчезнувшую папку) — ошибка, а не «Ничего не найдено»; прочий stderr (предупреждение git) — по-прежнему «Ничего не найдено»; rg на сервере не предполагается; хост не подключён — «Нет соединения с <host>». `!glob` в поле «Включить» — исключение для обоих движков (переносится в «Исключить»: у pathspec git нет `!`), лишний `!` в «Исключить» отбрасывается. Попутно: английские формы числа в `L10n.count` — «1 / остальное», а не русские правила («21 results»).
