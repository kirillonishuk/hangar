# Уведомления и «Входящие» — дизайн

Дата: 2026-10-27. Статус: утверждён в разговоре, ждёт ревью спеки.

## Цель

Не пропускать моменты, когда агент ждёт человека. Уведомление сразу говорит, *что* нужно (разрешение, вопрос, готово, ошибка, лимит), клик ведёт ровно в ту вкладку и панель, где ждут — локально и по SSH. Меньше шума: настройки по типам событий, проектам и сессиям, учёт «Не беспокоить».

Критерии успеха:
- По баннеру понятно, что нужно, без открытия окна.
- Клик/«Открыть» выбирает сессию, вкладку и панель агента и даёт ей фокус — для локальных и удалённых проектов.
- Когда агент перестал ждать (ответили, разрешили, открыли вкладку), баннер исчезает из Центра уведомлений.
- Всё ждущее видно в одном месте («Входящие») и обходится клавишей ⌥⌘A.

## Что есть сейчас (кратко)

`Notifier.swift`: баннеры на переходы в `waiting`/`done`, id = leaf, клик → `AppState.reveal`. Состояния из хуков Claude (`Notification`, `Stop`, `StopFailure: rate_limit`, `PostToolUse`…), Codex `notify` → done, колокол/OSC 9/777 → waiting (текст OSC выбрасывается). Удалённые события — через events-only сокет хоста и `ssh -R` (#21, #47). Dock: число ждущих сессий, подпрыгивание. Настройки: `notifications`, `limit_notifications`, `dock_badge`, `keep_awake`.

Пробелы: разрешение и вопрос не различаются; нет кнопок, группировки, уборки доставленных; ошибка и лимит вкладки не уведомляют; лимит не кликается; нет звуков, глушения по проекту/сессии, учёта фокус-режима; отказ в разрешении macOS молчит; простые SSH-терминалы (#64) без статусов.

## Решения

### 1. Модель «Внимание» (модуль `AgentStatus`, без UI)

`AttentionReason`: `permission`, `question`, `done`, `failed`, `limit`.

`AttentionItem`: leafId, taskId, projectId, host (nil — локально), агент, причина, `since`, детали (`tool`, `command` для разрешения; `text` для вопроса/готово/ошибки), `requestKey` — отпечаток конкретного запроса (для защиты кнопок, §2).

Источники:

| Причина | Событие |
|---|---|
| permission | Claude `Notification` с `notification_type = permission_prompt`; инструмент и команда — из полезной нагрузки хука, если есть (формат подтверждает спайк, §5) |
| question | Claude `elicitation_dialog`; колокол и OSC 9/777 у агентов без хуков (Codex и др.) — текст OSC теперь сохраняется |
| done | Claude `Stop`, Codex `notify` (текст последнего ответа, если пришёл) |
| failed | выход агента с кодом ≠ 0, `StopFailure` не по лимиту |
| limit | `StopFailure: rate_limit` на вкладке |

Запись снимается: агент снова работает (`PostToolUse`, `UserPromptSubmit`, `SessionStart`), вкладка видима и в фокусе (как сейчас), вкладка закрыта, сессия в архиве, хост отключён (как `.relaunched` сейчас). Для `done` — также кнопкой «Убрать»/«Очистить» во «Входящих»; иначе `done` живёт до следующей активности агента.

Порядок срочности: permission > question > failed > limit > done; внутри — старше выше.

Существующие `AgentState` (`waiting/done/failed/limit`) остаются; `AttentionReason` уточняет «почему». Точки на вкладках, строки сайдбара, Dock, колокольчик и уведомления строятся из одного списка внимания.

Dock: число = permission + question + failed (раньше — ждущие сессии).

SSH: удалённые события идут теми же хуками через туннель — работают без доработок. Простой SSH-терминал (#64): колокол и OSC 9 → `question`, только при включённой настройке (по умолчанию выкл.).

### 2. Уведомления macOS (`Notifier`)

Заголовок по причине и агенту: «Claude просит разрешение», «Claude спрашивает», «Codex закончил», «Claude: ошибка», «Claude упёрся в лимит». Подзаголовок «Проект › сессия» (+ «· host» у удалённых). Тело: разрешение — `tool: command`; вопрос — текст; готово — начало ответа; обрезка 160 символов.

Категории и действия (`UNNotificationCategory`):

| Причина | Действия |
|---|---|
| permission | Открыть; Разрешить — только если включено в настройках и команда известна |
| question | Открыть; Ответить (`UNTextInputNotificationAction`) |
| done, failed | Открыть |
| limit | Открыть лимиты (окно лимитов ⇧⌘L) |

Клик по баннеру = «Открыть» (`AppState.reveal`, работает для удалённых листов).

Защита «Разрешить»/«Ответить»: перед вводом в терминал проверяется, что у листа *текущий* элемент внимания с тем же `requestKey`. Иначе — только «Открыть», ничего не вводится. «Разрешить» ещё ждёт, пока нет более нового `PermissionRequest`. После ввода запрос считается отвеченным: элемент и баннер уходят, повторное нажатие — только «Открыть» (#96). «Разрешить» отправляет ту же клавишу, что человек (точную — подтверждает спайк). «Ответить» вставляет текст как ввод и Enter. Ввод — через существующий путь отправки текста в лист, если он есть (CLI/MCP); иначе — через `GhosttyBridge`, один путь для обоих действий.

Группировка: `threadIdentifier` = taskId. id уведомления = leafId (новое заменяет старое). Уборка: при снятии элемента — `removeDeliveredNotifications(withIdentifiers: [leafId])`.

Срочность: permission и question — `interruptionLevel = .timeSensitive`, если доступно без платной подписи (спайк). Иначе `.active`, а в Настройках — пояснение.

Звук: свой для каждой причины — системные звуки (`/System/Library/Sounds`) или «без звука».

Подавление: как сейчас — лист видим (окно активно и видимо, лист в активной вкладке выбранной сессии или в раскрытом TERMINAL). Новая настройка «Уведомлять, даже когда Hangar на переднем плане» (по умолчанию вкл. — как сейчас). Если разрешение macOS не выдано — в Настройках «Выключены в macOS» и кнопка «Открыть системные настройки».

### 3. «Входящие», переход, настройки

Колокольчик в заголовке окна справа (рядом с переключателем инспектора; глиф в стиле `icons-v2`). Число = permission + question + failed; цвет — `accent` при permission/question, `failed` если только ошибки; без элементов — приглушённый, без числа.

Список — `NSPopover` в стиле наших меню. Сверху срочное, внутри типа — старше выше. Строка: значок причины, «Проект › сессия», текст, время ожидания («3 мин»), кнопки как в баннере. Секция «Недавно готово» — последние 10 `done`, «Убрать» на строке и «Очистить». Пусто — «Никто не ждёт».

Счётчик ожидающих в нижней строке открывает тот же список. Фильтр ⌥⌘F остаётся.

⌥⌘A (keyCode 0, по коду клавиши) — к следующему элементу внимания по кругу в порядке списка; нет элементов — ничего.

Настройки → Уведомления:
- По причинам: переключатель + звук. По умолчанию: permission и question — вкл., со звуком; done — вкл., без звука; failed и limit — вкл.
- «Разрешать из уведомления» — выкл. по умолчанию, с пояснением риска.
- «Уведомлять, даже когда Hangar впереди», «Число на иконке в Dock», «Сигнал простого SSH-терминала» (выкл.), «Не засыпать» (есть), строка статуса разрешения macOS.

Проект: «Уведомления: все / только разрешения и вопросы / выключены» — в настройках проекта и в меню строки проекта. Заглушённые попадают во «Входящие», но без баннеров и без звука.

Сессия: «Без уведомлений» в меню сессии; в строке сайдбара — маленький перечёркнутый колокольчик.

Хранение: общие — `config.toml`; проект и сессия — `state.json`. Старые ключи `notifications` (общий выключатель баннеров), `limit_notifications` (→ причина limit), `dock_badge` читаются как раньше.

Все строки — через L10n (ru и en), цвета и размеры — из `Theme`, во всех трёх темах.

### 4. Вне рамок

Тихие часы внутри Hangar (закрывает фокус-режим macOS); разделение по агентам; уведомления на телефон/внешние сервисы; разрешение без показа команды; «Разрешить всегда» для инструмента.

## 5. Порядок работ и проверка

1. Спайк (одноразовый): реальная полезная нагрузка `Notification`/`permission_prompt` у Claude (есть ли tool/command), клавиша одобрения запроса, доступность `.timeSensitive` при ad-hoc подписи. Итог — запись в `decisions.md`.
2. Модель внимания + юнит-тесты: источники, снятие, порядок, глушение проект/сессия, `requestKey`.
3. Уведомления: категории, действия с защитой, группировка, уборка, звуки, статус разрешения.
4. «Входящие», ⌥⌘A, настройки, меню проекта/сессии.
5. Живая проверка в DEBUG-сборке с поддельными агентами, включая удалённый проект через поддельный ssh; снимки во всех трёх темах и обоих языках. Ресурсы: одна тяжёлая задача за раз (общий замок), `nice`, не больше одного окна приложения.

Решения записываются в `docs/decisions.md` (новые номера после #93). Выпуск — v0.4.0.
