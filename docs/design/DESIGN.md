# Hangar — дизайн

**Внешний вид (числа, шрифты, цвета, радиусы, высоты, компоненты, тексты) — только из спеки `docs/superpowers/specs/2026-10-30-design-system.md`** (дизайн-система B «macOS-native», решение #112) и скилла `.claude/skills/hangar-design`. Макет-эталон — `docs/superpowers/mockups/design-system-v2.html`. В этом файле — только то, что спека не описывает: поведение, клавиши, тема кода и терминала. Чисел оформления здесь нет; если они понадобились — их место в спеке.

Прежняя версия этого файла (стиль A, до #112) — `git show 587fed8:docs/design/DESIGN.md`: только как справка о поведении экранов, размеры и цвета оттуда не брать.

## Общие правила поведения
- **Курсор — рука на всём кликабельном** (кнопки, строки сайдбара, вкладки и их «×», сегменты, чипы, кнопки листов и настроек). Один модификатор `.pointingHand()` (macOS 15+: `pointerStyle(.link)`); в AppKit — `addCursorRect`. Поля — I-beam, терминал — курсор Ghostty, разделители — курсор изменения размера.
- **Никаких строк литералами**: каждая видимая строка — через `L10n` (`ru` и `en` в `Resources/*.lproj/Localizable.strings`). Литералом — только имена продуктов и команд (Claude, Codex, Shell, Hangar, Monaco) и символы клавиш.
- **Никаких сторонних UI-китов**: системные контролы, перекрашенные под токены.
- **Системных алертов в окне нет**: подтверждения (архив, удаление, выход с работающими агентами, несохранённый diff) и сообщения с одной «OK» — лист подтверждения (`ConfirmSheet`); ↩ — основное действие, Esc — отмена.
- **Пустое и «нет данных»**: элемент не показывается; пустая область — фраза-действие и кнопки (спека §3.19). Ничего не запускается само.
- **Окно настроек** (`⌘,`): изменяемое, размер запоминается; категории — Общие, Оформление, Редактор, Уведомления, Интеграции, Дополнительно. Длинные значения сокращаются в середине, полный текст — в подсказке; ошибка записи — строкой под страницей.
- **Сайдбар свёрнут** (`⌘0`, #32): рейка; маркер (точка/иконка) стоит на одном x в обоих режимах; анимируется только ширина. Монограмма чата: имя делится по `-`, `_`, `.`, пробелу и границе camelCase; 2+ части — две первые буквы, одна — одна буква.
- **Терминал** (#109, #112): фон, текст и курсор — от темы всегда: Hangar кладёт их файлом `overrides` после конфига Ghostty пользователя. Палитра ANSI темы — в `hangar-ghostty-defaults-<pid>.conf` до конфига пользователя, поэтому `palette` / `theme` пользователя побеждают. Шрифт — SF Mono, только если в Ghostty пользователя шрифт не задан. Смена темы перекрашивает открытые терминалы (`ghostty_app_update_config`, #87). Файл конфига Ghostty Hangar не меняет.
- **Интеграции** (#111, макет `integrations-v2.html` — содержание, не размеры): в Настройках две карточки — Claude Code и Codex, у каждой главный переключатель (выкл. — функции и «Где установлено» неактивны; MCP — своим переключателем). Функции: Claude — «Статусы и уведомления», «Лимиты», «Строка состояния», «MCP-сервер Hangar»; Codex — «Статусы и уведомления», «MCP-сервер Hangar». У MCP метка «этот Mac» (почему — в тултипе); его состояние — в подписи: «имя «hangar» занято другой записью» (`waiting`), «зарегистрирован другой копией Hangar» (`text3`), ошибка CLI (`failedText`). Последняя строка — «Где установлено»: машины с состоянием — ✓ (`done`), «нет связи», «codex нет», «не на этом хосте» (`text3`), «Подключить…» (`waiting`; клик — лист хоста), ошибка (`failed`; клик повторяет); тултип — время тихого обновления и копия; машины переносятся, не обрезаются. Агента нет в PATH — карточка в одну строку «не найден» + пояснение. Без собранного .app / из DMG — предупреждение `waiting` над карточками. Кнопок «Установить / Удалить» и листа diff в Настройках нет.
- **Лист «Подключить Hangar к Claude Code?»** — перед первым запуском агента: вопрос и пояснение; флажки функций (все вкл.), «Куда» (Этот Mac, хосты; отключённые — «при подключении»); ссылка «Что изменится» раскрывает diff по файлам; «Не сейчас» (Esc) / «Подключить» (↩). Лист хоста «Подключить Hangar на <host>?» — без переключателей: «Claude Code / Codex / hangar-remote N» с перечнем функций; «Не на этом хосте» / «Подключить». Вкладка агента до ответа — полоса «Ждёт ответа: подключить Hangar?».
- **«Строка состояния» в карточке Claude Code** (#105, #110, #111): «Hangar — везде» / «Ваша» («Ваша» неактивна, если своей команды не было; подсказка — исходная команда); образец — тем же рендером, что `hangar statusline`, на фоне терминала (приглушённое — текст 50 %, жёлтый и красный — ANSI 3 и 1 темы); фишки частей во всю ширину: клик — вкл./выкл., перетаскивание (и выключенных) — фишка идёт за курсором, место вставки — линия `accent`, остальные не сдвигаются до отпускания (вне ряда или Esc — отмена); порядок фишек = порядок частей; узкая карточка — перенос фишек, длинный образец — обрезка с затуханием, окно не раздвигается; фишка — кнопка (Tab, пробел, ←/→), в контекстном меню и VoiceOver — «Левее» / «Правее»; подсказка «Появится, когда интеграция Claude установлена» — отдельной строкой; «Проекты» — только если есть: имя, путь, «своя строка перекрыта», «settings.local.json не в .gitignore» (`waiting`), ошибка (`failedText`).
- **Строка состояния Claude** (#105, #110) — это строка внутри терминала, рисует её `hangar statusline`; всегда по-английски, части в порядке `statusline_segments`, цвета — ANSI 3/1 палитры темы (жёлтый от 80 %, красный от 95 %). К убранной нижней полосе окна не относится.
- **Лимиты**: `limOk` < 80 %, `waiting` ≥ 80 %, `failed` ≥ 95 % или исчерпан. Git: `?` цветом A, `R` цветом M, `U` цветом D.
- **Иконки** — только через `enum Icon` (`Icons.swift`), свои линейные глифы; эталон глифов — `icons-v2.html` (#56), размеры — спека §2.5.
- **Иконка приложения и DMG**: концепт A (#92, `app-icon-v2.html`; исходники `docs/superpowers/mockups/app-icon/`, сборка `scripts/make-icon.sh`); установщик — `scripts/bundle.sh && scripts/make-dmg.sh`.

## Без повторов (#106)
Одна и та же информация на экране — в одном месте. Перед тем как добавить подпись, счётчик или путь, проверь, не видно ли это уже рядом; если видно — не добавляй, а где повтор есть — убери лишний. Примеры: проект — только в тулбаре (и выбранной строкой сайдбара); число изменений — счётчик «Изменения», не «3 файла» в заголовке списка; `+N −M` — строка «Изменений», не заголовок diff; имя вкладки сплита — первая панель, не склейка заголовков панелей; путь — в поле, не ещё раз подсказкой под ним; ошибка агента — точка вкладки, слово в строке сайдбара и колокольчик, но не «ждёт внимания». Подробности, которые нужны редко, — в тултип.

## Тултипы и клавиши
Тултип есть у каждого кликабельного элемента, формат один: «Действие — клавиша» (`L10n.help(title, Shortcut)`), без клавиши — просто действие. Символы клавиш строит `Shortcut.label` из той же таблицы, по которой сопоставляются клавиши (keyCode, любая раскладка); модификаторы в порядке меню macOS ⌃⌥⇧⌘. Литералов «⌘N» в коде нет. Обычная вкладка — «<имя> — ⌘N» для первых девяти.

## Редактор (Monaco, #80) — поведение и тема кода
- Файл — вкладка Hangar (#83), второго ряда вкладок нет. Все файловые вкладки окна делят одну страницу Monaco в WKWebView (модель на вкладку, своё состояние вида и курсор); показанная вкладка получает этот вид, последняя закрытая уносит его (страницы нет). Два редактора в сплите одной вкладки (не больше двух) видны одновременно: у второго — своя страница, она живёт, пока к ней привязан редактор (#101). В заголовке панели редактора справа — статус tsserver (ниже) и переключатель «Миникарта» (по умолчанию выкл., сохраняется). Код — шрифт, размер и высота строки из Настройки → Оформление → Редактор (по умолчанию SF Mono — тот же шрифт, что у терминала, если пользователь не выбрал свой; #108, #112).
- Контекстное меню — своё, не Monaco (без «Command Palette» и команд VS Code, #81): «Перейти к определению F12», «Найти все ссылки ⇧F12», «Переименовать символ F2» | «Форматировать документ ⇧⌥F», «Закомментировать строку ⌘/» | «Вырезать / Копировать / Вставить». Вид — меню Hangar (спека §3.12). Пункт, который редактор сейчас не умеет (нет языкового провайдера, только чтение), — прозрачность `.4`; переход, ссылки — для всех файлов через tsserver (вне TS/JS просто ничего не находят), переименование и форматирование — только TS/JS (#82). ↑↓ ↩ Esc работают при открытом меню. Вырезать/Копировать/Вставить — через команды WebKit (как ⌘X/⌘C/⌘V).
- Тема Monaco (`MonacoTheme` из `EditorTheme`, #108): цвета темы редактора поверх оформления Hangar — виджеты (поиск, подсказки, hover, контекстное меню) на `bg2` с рамкой `line2`, `radius.control`, скроллбары тонкие `line2`. Темы (Настройки → Оформление; по умолчанию — «Как у темы», пара темы оформления, #109): **VS Code Dark Modern** (у Dark+) — свои цвета редактора, от темы оформления не зависят: фон `#1f1f1f`, текст и пунктуация `#cccccc`, номера `#6e7681` / `#cccccc`, курсор `#aeafad`, текущая строка — рамка `#282828`, выделение `#264f78`, направляющие `#404040` / `#707070`; **VS Code Dark+** — синтаксис Dark+, фон `editorBg`, номера `edGutter`/`edGutterActive`, текущая строка `edLine` (заливка), курсор `accent`, выделение `edSel`, направляющие `edIndent`; **Hangar** — приглушённая палитра diff (`Theme.Diff.syntax`), курсивные комментарии, редактор как у Dark+; **Своя** — основа + изменённые цвета. Синтаксис Dark+ / Dark Modern: `const`/`type`/`function` `#569CD6`, `import`/`from`/`return`/`as` `#C586C0`, переменные и свойства `#9CDCFE`, типы и классы `#4EC9B0`, функции `#DCDCAA`, строки `#CE9178`, числа `#B5CEA8`, комментарии `#6A9955`, КОНСТАНТЫ `#4FC1FF`; переменные, типы и функции различает tsserver (семантические токены). Скобки по глубине — `#FFD700` / `#DA70D6` / `#179FFF`, активная пара — направляющая того же цвета. Радужные отступы — тонкая линия 1 px у левого края уровня (rgba 28 %) над едва заметной полосой (2,5 %): жёлтый, зелёный, розовый, бирюзовый, «Подсветка TODO» — плашки радиус 3 в комментариях: FIXME `#d0587e`, TODO `#b38a3c`, HACK `#8a63b8`, XXX `#c14e4e`, белый жирный текст; оба выключаются в настройках. Считаются только для видимых строк.
- Полоса конфликта над текстом (`bar.pane`, `bg2`, точка `waiting`): «Файл изменён на диске — Перезагрузить / Оставить мой». Большой файл (2–5 МБ) — строка «только для чтения»; > 5 МБ, бинарный, отсутствующий — спокойное сообщение вместо текста.
- TS/JS (#82): в заголовке панели редактора, перед «Миникарта», — статус tsserver: точка (`done` готов, `waiting` грузит проект, `text3` нет) + «TS 5.9» / «TS 5.9 · проект…» / «TS» (недоступен: причина — первой строкой тултипа) / «TS остановлен»; тултип — пути tsserver и node; название языка («TypeScript») рядом не повторяется; клик — перезапуск (или повторный поиск TypeScript). Ошибки — маркеры Monaco (`failed` / `waiting`), hover и подсказки — виджеты на `bg2`. Панель ссылок (peek): рамка `line2`, заголовок и список на `bg2`, системный шрифт, выделение `selected`, совпадения `waiting` 25 %.
- Diff — при открытии прокручивается к первому изменению (по центру); без изменений — «Нет изменений». Monaco diff: рядом или одной колонкой (переключатель в заголовке, сохраняется); слева база только для чтения, справа рабочий файл (правится и сохраняется ⌘S; у коммита — только чтение). Строки — фон `diffAdd` / `diffDel`, изменённые символы поверх — `gitA` / `gitD` 12 %; маркер +/− по центру полосы 26 px между номером и кодом.

Подсветка синтаксиса в SwiftUI-diff листа интеграции (#53): keyword `#b79bd9`, string `#a9c48f`, comment `#75819a`, number `#d5a274`, type `#dcc283`; остальное — `text1`; заголовок ханка — `accentText` на нём же 7 %.
