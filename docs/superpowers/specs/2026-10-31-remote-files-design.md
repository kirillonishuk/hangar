# Файлы сервера в терминале «<сервер> · терминал» — дизайн

Статус: черновик, ждёт решения владельца (этап 1 — только дизайн). Макет — `docs/superpowers/mockups/remote-files.html` (рендер — `remote-files.png`). Дополняет #64 (простое подключение), опирается на #47 (транспорт, `shellQuote`, пути мастера), #71, #91 (Поиск), дизайн-систему #112.

## 1. Что просит владелец
Когда просто зашёл на сервер (`WorkspaceState.hostShells`, без проекта), правый сайдбар показывает папку, где сейчас терминал, с её файлами; файлы можно положить туда кнопкой «+» или перетащив из Finder.

## 2. Что есть в коде сейчас
- Вкладка «<host> · терминал» — `sshShellSpec` (`Sources/Exec/RemoteLaunch.swift`): `/bin/sh -c 'TERM=xterm-256color ssh -t -o ServerAliveInterval=15 -o ServerAliveCountMax=4 -- <host>; …OSC 133 C/D…'`. Без мастера (`ControlMaster` не задан — #64 сознательно отказался от общего мастера с `BatchMode`, чтобы работали пароль и 2FA), без удалённой команды: сервер запускает логин-шелл.
- Инспектор у псевдозадачи пуст: `InspectorWatch.update` берёт корень через `app.project(...)`, у `hostShells` проекта нет → `stop()`.
- GhosttyKit отдаёт встраивающему `GHOSTTY_ACTION_PWD` (`ghostty_action_pwd_s.pwd`) после OSC 7, но `GhosttyApp.handleAction` его не обрабатывает (`default: return false`).
- **Главное ограничение:** Ghostty принимает OSC 7, только если хост в URL локальный (`stream_handler.zig reportPwd` → `hostname.isLocal`: `localhost` или имя этого Mac). Обычный OSC 7 сервера (`file://vultr/...`, его же шлют vte.sh, интеграции Ghostty/kitty на сервере) молча отбрасывается. Поэтому хук обязан слать `kitty-shell-cwd://localhost<путь>` — схема `kitty-shell-cwd` берёт путь как есть (`raw_path`), процентного кодирования в шелле не нужно.
- Удалённые проекты (#47) уже умеют: мастер `-S <cp>`, `sshBaseArgs`, `remoteShellArgs` (аргументы — словами в кавычках, код — только `/bin/sh`), запись файла через stdin ssh (`remoteFileWriteScript`: временный файл + `mv`), удалённый Поиск через `git grep` (#91). Это и переиспользуется.

## 3. Механизм

### 3.1 Текущая папка терминала (OSC 7 через хук без установки)
- Команда вкладки становится `ssh -t <ControlMaster-опции §3.2> … -- <host> <удалённая команда>`. Удалённая команда — `remoteShellArgs`: `/bin/sh -c '<скрипт>'`, который смотрит `$SHELL` и делает `exec`:
  - **zsh** — временная папка (`mktemp -d`, 0700) с `.zshenv`: возвращает исходный `ZDOTDIR`, подключает `.zshenv` пользователя, добавляет `precmd`-хук через `add-zsh-hook`, удаляет временную папку; затем `exec zsh -l` с этим `ZDOTDIR` (тот же приём, что у интеграции Ghostty, #71).
  - **bash** — временный rc-файл: повторяет порядок логин-шелла (`/etc/profile`, затем первый из `~/.bash_profile`, `~/.bash_login`, `~/.profile`), удаляет себя, добавляет хук в начало `PROMPT_COMMAND`; `exec bash --rcfile <файл> -i`.
  - **fish** — без файлов: `exec fish -l -C 'function __hangar_cwd --on-event fish_prompt; …; end'` (`-C` выполняется после конфигов пользователя).
  - Иное (sh, dash, ksh, csh) — `exec "$SHELL" -l` без хука: панель говорит «Папка терминала неизвестна» и показывает домашнюю папку.
- Хук печатает `ESC ] 7 ; kitty-shell-cwd://localhost$PWD BEL` на каждом приглашении. Ничего не ставится и не правится на сервере; временный файл живёт до чтения шеллом.
- Ghostty → `GHOSTTY_ACTION_PWD` → новое событие `TerminalSurfaceView.Event.pwd(String)` → `AppState` хранит «последнюю папку» на лист вкладки (только для листов `hostShells`, в памяти, не в `state.json`). Значение недоверенное: только абсолютный путь, без управляющих символов, ≤ 4096 байт, иначе отброшено; используется только как аргумент удалённых команд (никогда как локальный путь).
- Панель показывает папку **листа в фокусе** у этой псевдозадачи (вкладка/сплит), см. вопрос 3.
- Вложенные `ssh`, `sudo -s`, `docker exec`, `su`: их шеллы хука не имеют (их OSC 7 с чужим хостом Ghostty отбрасывает), поэтому панель держит папку последнего приглашения нашего шелла. Заголовок всегда показывает этот путь — пользователь видит, куда лягут файлы. Признака «сейчас внутри вложенного» нет и не изобретаем (OSC 133 с сервера сломал бы код выхода вкладки, #26).
- Побочное: если сервер не задаёт заголовок окна, Ghostty делает заголовком вкладки путь (как в Ghostty.app). Открытие относительной ссылки кликом в такой вкладке будет искать файл на Mac — не чиним (редкий случай).

### 3.2 Соединение без второго входа
- Сама вкладка становится мастером: `-o ControlMaster=auto -o ControlPath=<state>/ssh/hs-<fnv64(leafId)> -o ControlPersist=no` (путь и запасной `/tmp/hangar-<uid>/` — как у `SSHPaths`, ограничение 104 байта). Пароль и 2FA по-прежнему вводятся во вкладке: мастер — интерактивный ssh, `BatchMode` у него нет. Это не «общий мастер хоста», отвергнутый в #64.
- Сокет **на лист**, не на сервер: с общим сокетом вторая вкладка стала бы клиентом первой, и закрытие первой висло бы до конца второй.
- Фоновые команды (список, загрузка, поиск) — `ssh` + `sshBaseArgs(controlPath:)` (`ControlMaster=no`, `BatchMode=yes`): только через живой мастер; нет мастера (ещё вводится пароль, связь оборвалась, вкладка закрыта) — сразу ошибка «нет соединения», без нового входа.
- Опции командной строки перекрывают `~/.ssh/config` пользователя (его `ControlMaster`/`ControlPath` для этих вкладок не действуют); `~/.ssh/config` не правится.
- Закрытие вкладки: мастер ждёт конца мультиплексных сессий, поэтому Hangar сначала завершает свои фоновые процессы этого листа (загрузки отменяются).

### 3.3 Список файлов
- Одна команда через мастер: POSIX-скрипт `cd -- "$1"` и обход `.[!.]* ..?* *` с выводом `тип\tимя\0` (тип: папка / файл / ссылка на папку / ссылка). Без `ls`-разбора и без GNU `find`. Предел 5000 записей и 1 MiB вывода («Показаны первые 5000»); строгий разбор (как вывод проверки сервера, #47).
- Вид — как «Файлы» (§3.7 дизайн-системы): строки 24, папки сверху, затем файлы, по имени; скрытые файлы показываются. Папка раскрывается шевроном (её список — по запросу, та же команда); дерево ниже текущей папки не грузится заранее.
- Когда обновлять: событие PWD (каждое приглашение — значит, после каждой команды: `rm`, `mv`, `git pull` видны сразу), повтор того же пути — с debounce 300 мс; после загрузки; кнопка «Обновить». Только пока инспектор виден и выбрана эта псевдозадача — иначе событие лишь запоминает путь. Ни таймеров, ни опроса.
- Клик по файлу ничего не открывает (этап 2); контекстное меню — нет на этом этапе.

### 3.4 Загрузка на сервер
- «+» в заголовке панели → `NSOpenPanel` (файлы и папки, несколько). Перетаскивание из Finder: на список — в текущую папку; на строку папки — в неё (строка подсвечивается, §5). Цель всегда видна: путь в заголовке или подсвеченная папка.
- Файл: `ssh … /bin/sh -c '<скрипт>' sh <папка> <имя> <режим>`, stdin — файл. Скрипт пишет во временный `.<имя>.hangar-part` в той же папке, `chmod` режим, затем `mv` (как `remoteFileWriteScript`): обрыв не оставляет полуфайла под настоящим именем; без «заменить» `mv` не выполняется, если имя появилось за это время (код 3 → снова вопрос).
- Папка: локально `tar -c` (`COPYFILE_DISABLE=1`, без `._`-файлов) → stdin ssh → на сервере `tar -x` во временную `.<имя>.hangar-part/`, затем `mv` на место. Нужны только `/bin/sh` и `tar` на сервере — ни `scp`, ни `sftp-server` (scp в OpenSSH 9 по умолчанию требует sftp-server).
- Прогресс: байты, переданные в stdin ssh, из суммы размеров (для tar — по содержимому, ограничено 100 %). Очередь по одному, общий прогресс «N из M». Отмена — завершить процесс; временный файл на сервере удаляет следующая команда того же скрипта (`rm -f` старого `.hangar-part` перед записью) — `shortcut:` при обрыве посреди загрузки остаётся скрытый `.hangar-part` до повторной попытки.
- Конфликт имени (по списку перед стартом и повторно в скрипте): поповер у панели «report.pdf уже есть в /var/www/app» с флажком «Для всех» и кнопками «Пропустить» · «Заменить». Для папки — см. вопрос 2.

## 4. Интерфейс (макет `remote-files.html`)
- Инспектор псевдозадачи: сегмент «Файлы · Поиск» (без «Изменений» и Git). Поиск — как #91 через мастер листа: `git grep --no-index` если на сервере есть git, иначе `grep -rnI` (`shortcut:` без глобов «Включить/Исключить» у `grep`).
- Под сегментом — заголовок панели 28 (§3.5): иконка папки 12, путь `mono` `text2` (середина сокращается, полный — в тултипе, `~` для домашней), справа иконки 22: «Обновить», «Загрузить файлы — +». «+» — второстепенное действие иконкой (§5 дизайн-системы).
- Состояния: загрузка — `ProgressView` small на месте списка; пустая папка — «Папка пуста. Перетащите сюда файлы» `body` `text2` по центру + кнопка «Загрузить файлы»; перетаскивание — рамка `accent` 1 + заливка `accent` .15 у списка или у строки папки (подпись «Загрузить в /var/www/app» `secondary` внизу списка); загрузка — блок внизу инспектора над краем: строка 28 «Загрузка: 2 из 3» + `mono` 11 «48 %» + «×», полоса `LimitBar` высотой 4 (`limTrack` / `limOk`), строка текущего файла `secondary` `text3`; конфликт — поповер (§3.12) у блока загрузки; нет связи — §3.5.
- Тексты (ru/en в `Localizable.strings`): «Загрузить файлы», «Обновить», «Папка пуста. Перетащите сюда файлы», «Загрузить в %@», «Загрузка: %d из %d», «%@ уже есть в %@», «Для всех», «Пропустить», «Заменить», «Нет соединения с %@», «Войдите во вкладке терминала», «Папка терминала неизвестна», «Нет доступа к %@».
- Новых токенов нет: высоты 24/28/22, отступы 8/12, полоса 4 — существующая `Theme.Limit.blockBar`.

## 5. Вне рамок (этап 2 и позже)
Скачивание перетаскиванием в Finder, открытие файла в редакторе, контекстное меню (переименовать, удалить, скопировать путь), то же для не-git удалённых проектов (`remoteNoGit`), загрузка в проектах с tmux, csh/tcsh, синхронизация.

## 6. Вопросы владельцу
1. **Вход через удалённую команду.** Чтобы поставить хук без установки, вкладка запускает `ssh host '<скрипт>'` вместо голого `ssh host`. Следствие: sshd не печатает приветствие сервера (MOTD, «Last login») — остальное как было. *Рекомендация:* принять, без настройки; при неизвестном шелле поведение прежнее.
2. **Папка с тем же именем.** «Заменить» для папки — удалить серверную и положить новую или объединить (совпадающие файлы заменяются, остальные остаются)? *Рекомендация:* объединять; кнопка для папки называется «Объединить», серверные файлы Hangar не удаляет никогда.
3. **Несколько вкладок/сплитов терминала сервера в разных папках.** *Рекомендация:* панель следует за вкладкой (сплитом) в фокусе; переключился — панель показывает её папку.
