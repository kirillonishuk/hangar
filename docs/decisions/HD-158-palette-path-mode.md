# HD-158 — 2026-11-13 — ⌘P: любой файл по пути, режимы палитры видны, смена режима не теряет ввод

Дополняет HD-065. По слову пользователя: ⇧⌘P — команды с `>` (можно набрать руками), ⌘P без шифта — открыть файл, «при чём любой на компе, если писать полный путь», и улучшить сам интерфейс.

- **Путь.** Запрос ⌘P, начинающийся с `/`, `~/` или равный `~`, — режим «Путь»: список одной папки (часть до последнего `/`, `~` — домашняя), фильтр по имени после `/` (начало имени без регистра выше, затем нечёткое совпадение; папки раньше файлов; файлы с точкой — только когда имя начинается с `.`), до 50 строк, заголовок — сама папка (`~/…`). ↩ на файле — открывает его во встроенном редакторе (вкладка «Редактор», абсолютный путь; из выбора панели «Редактор» — в эту панель), ↩ или Tab на папке — дописывают её в запрос (`~/` остаётся `~/`), Tab на файле — дописывает имя. Папка читается один раз (`contentsOfDirectory`, без рекурсии, вне главного потока), пока набирается имя в той же папке — повторного чтения нет; нет папки — «Нет такой папки». Устройство, канал (FIFO) или сокет (например, `/dev/zero`) в редакторе не читается (`EditorRead.special`, проверка `stat` со следованием по ссылке): вместо содержимого — пояснение «Это не обычный файл…», иначе чтение не кончалось бы или зависало, в том числе при восстановлении вкладки после перезапуска.
- **Только этот Mac.** Файл по пути открывается в выбранном локальном чате; у чата на сервере (ssh, в том числе «хост · терминал») и без выбранного чата список не строится, вместо него — объяснение. Шорткат: путь на сервере (листинг через ssh) — когда попросят.
- **Режим виден.** Слева от поля — иконка режима (поиск / `>` / папка), справа — подпись «Чаты и файлы» / «Команды» / «Путь» (`caption`, `text3`); внизу строка-подсказка высотой заголовка секции: «> — команды · / или ~ — любой файл по пути», «Сотрите > — чаты и файлы», «↩ — открыть · Tab — дополнить · папка — её содержимое». Пустые состояния по режиму: «Ничего не найдено», «Нет такой команды», «Нет такой папки», объяснение для сервера / без чата. Плейсхолдер — «Найти чат или файл».
- **Смена режима не теряет ввод.** ⌘P ↔ ⇧⌘P в открытой палитре добавляют или убирают только ведущий `>`, набранный текст остаётся (раньше запрос сбрасывался в `>` / пусто).
- **Поле не прыгает.** Плейсхолдер — тем же шрифтом, что и запрос (`title`): пустое и заполненное поле одной высоты, первая буква больше не сдвигает карточку на 3 pt. У моноширинного поля (поиск веток) плейсхолдер по-прежнему прозой (`Theme.Input`).
- **Длинное — с середины.** Имя и папка файла обрезаются посередине, полный путь — во всплывающей подсказке строки.
- **Отладка.** Неактивирующая панель в фоновом приложении забирала клавиатуру у переднего: при `HANGAR_DEBUG_NO_ACTIVATE` палитра только показывается, не становится key. Команда `palette keys <keyCode>:<mods>:<символы> …` шлёт настоящие события клавиш через монитор и поле (проверка ru-раскладки по keyCode).

**Почему.** Пользователь просил разделить ⌘P (файлы) и ⇧⌘P (команды) и открывать любой файл по полному пути; режим по одному символу в поле легко не заметить. **Отвергнуто:** рекурсивный поиск по диску или Spotlight (дорого, не просили); отдельная клавиша для пути (префикс `/` / `~` уже однозначен); `>` по клавише «Ю» в русской раскладке (неявно).
