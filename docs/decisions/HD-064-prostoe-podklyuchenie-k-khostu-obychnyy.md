# HD-064 — 2026-10-24 — Простое подключение к хосту: обычный `ssh -t` без проекта (дополняет #47, §11.1).

*Дополнено #124: вкладка — мастер своего сокета и запускает хук папки (файлы сервера в инспекторе).* По слову пользователя: на хост можно просто зайти, без проекта и установки. «<host> · терминал» — псевдозадача под строкой хоста в SSH HOSTS (`WorkspaceState.hostShells`, вне `projects`: её не видят списки проектов, `tasks list`, ссылки CLI на задачи, ⌘⇧[/]). Её вкладки — только shell (`addTab`/`split` принудительно), каждая — локальный лист с `/bin/sh -c 'TERM=xterm-256color ssh -t -o ServerAliveInterval=15 -o ServerAliveCountMax=4 -- <host>'` в домашней папке сервера: без мастера, проверки сервера, tmux и `hangar-remote`, без `BatchMode` (пароль и 2FA вводятся во вкладке). Код ssh — код вкладки: 0 закрывает, 255 (обрыв, сон Mac) — ↩ входит снова; восстановление после перезапуска — новый вход. Закрытие последней вкладки (или «Закрыть терминал») убирает псевдозадачу; `kill-session` не нужен. SSH HOSTS сразу перечисляет хосты `~/.ssh/config` (с `Include`, `sshConfigHosts`, только чтение) — при запуске и при активации приложения, без опроса и наблюдателя файла; хост без проектов — простая строка без состояния, клик открывает его терминал (или новую вкладку), меню — «Открыть терминал»; у хостов проектов прежняя строка и меню плюс «Открыть терминал». «Подключиться к хосту…» (`+` SSH HOSTS, «+ проект», меню настроек) — поле хоста с выпадающим списком ssh config. CLI `hangar ssh <host>` / MCP `ssh_open` только открывают вкладку в приложении (и показывают её); хост проверяется `validSSHHost` (и при запуске листа — state.json правится руками). Тултип вкладки: «Обычный ssh — закроется при разрыве». Почему: долгая работа — в проектах (tmux, #47); здесь нужен просто вход. Отвергнуто: tmux и проверка сервера для простого входа (по слову пользователя); общий мастер хоста (`BatchMode` запретил бы пароль); псевдопроект в `projects` (пришлось бы фильтровать каждый список проектов).
