# Этап 1 — ручная проверка и хвосты

## Проверить глазами (экран разблокирован)
- Окно: сайдбар 220, светофор, палитра, фон терминала #121826 с цветами Starlight; полупрозрачность 0.95.
- Сайдбар: ⌘0/⌘B — свёрнутый режим без «прыжков»; монограммы; hover/pressed; курсор-рука на всём кликабельном; Reduce Motion.
- Терминал: ввод в русской раскладке и IME; выделение мышью, прокрутка, ⌘C/⌘V; смена Retina-экрана; ⌘T/⌘W/⌘D в русской раскладке при фокусе в терминале.
- Клик в панель A сплита → ⌘D делит A; клик по строке/вкладке → печать идёт в терминал; клик → F2 переименовывает; mc/htop получают F2.
- Контекстные меню, линия вставки при перетаскивании, «Открыть в Finder», «Открыть в <редакторе>».
- Нижняя панель: ⌃` в русской раскладке, клик по полосе, высота, фокус, один shell на задачу в `ps`, exit 0 сворачивает.
- Восстановление: `claude --continue`/`--resume`, `codex resume`, hx с тем же файлом; серый проект с удалённой папкой; фокус после запуска; вид алертов.
- Диалог буфера обмена (OSC 52) на русском; «Разрешить»/«Отмена».
- Замер энергии с живыми агентами рядом с Pane (§9) → `decisions.md` «Замеры».

## Отложено (после этапа 1)
- Restore из архива: слот `--continue` учитывает только листы самой задачи — может подхватить разговор другой живой задачи в той же папке.
- После неудачного `--resume <id>` id не сбрасывается → при следующих падениях resume/fresh чередуются (уйдёт с id из hooks, этап 3).
- Сборка GhosttyKit: патч libtool применяется каждый раз; `macos-arm64` захардкожен (`shortcut:`); проверка символов только после сборки.
- Модель: нет теста на фокус не-последнего листа в дереве из 3; висячий симлинк state.json → `.empty`.
- Конфиг: неизвестные `\x`-экранирования отбрасываются.
- Настройки: повторный ⌘, сбрасывает черновик внешнего редактора; ошибка сохранения при закрытии видна только после повторного открытия.
- Нижняя панель без surface не держит фокус → ⌘W закрывает вкладку; снап кадров посреди анимации.
- Codex: не установлен — проверки `codex resume`, `app-server`, hooks отложены.
