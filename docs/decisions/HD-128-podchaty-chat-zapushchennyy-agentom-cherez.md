# HD-128 — 2026-11-04 — Подчаты: чат, запущенный агентом через MCP, и «полностью закончил» (решения владельца; спека `specs/2026-11-04-sub-sessions-design.md`; дополняет #43, #45, #95, #119, #126).

*Изменено #131: в терминал родителя ничего не печатается (доставки нет), о конце — только уведомление; по умолчанию подчат работает в папке родителя.* Агент чата создаёт подчат `sessions_spawn` (CLI `hangar sessions spawn`): полноценный чат со своим терминалом, родитель — вызывающий чат по `HANGAR_LEAF_ID` из окружения `hangar mcp`/CLI (или явный `parent`). В модели — `HangarTask.parentTaskId` и `subsCollapsed` (`decodeIfPresent`), подчат живёт в проекте родителя (основная папка или worktree) или, у чата без проекта, — новым чатом без проекта (worktree нельзя). Сайдбар: подчаты под родителем с отступом, у родителя треугольник раскрытия, свёрнутый показывает «2 подчата · 1 работает»; в интерфейсе слово «подчат» / "sub-chat" (словарь #113 запрещает «сесси»/"session"), в API — sub-session. **Архив родителя** архивирует его открытые подчаты по обычным правилам #57 (рискованный worktree без подтверждения не удаляется — такой подчат остаётся открытым и встаёт на верхний уровень; `force` передаётся); восстановление родителя подчаты не восстанавливает; сон чата без проекта подчаты не трогает. **«Полностью закончил»** = агент остановился (Stop) и у него нет фоновой работы: основной источник — поле `background_tasks` Stop-хука (число записей `running`/`pending`, поле `background`); запасной — дети pid агента со своей группой процессов (опыт на живом Claude Code: Bash-инструмент, в т. ч. фоновый, — отдельная группа; MCP-серверы и `caffeinate -i -t 300` — в группе claude); плюс экран без «esc to interrupt» и 5 с без хуков (дебаунс: окончание фоновой задачи будит Claude на новый ход со своим Stop, итог срабатывает один раз после последнего тихого состояния). `waiting` → `needs-input` сразу, StopFailure/выход с ошибкой → `error`. Отчёт — один раз за эпизод; новый ход подчата начинает новый эпизод. Codex: `notify` + дебаунс + экран, фоновые процессы не отслеживаются (pid codex неизвестен). **Обратная связь:** `sessions_wait` (CLI `sessions wait`) ждёт без опроса до итога или таймаута (по умолчанию 110 с — Claude Code уводит вызов MCP дольше 2 мин в фон; клиенту `codex-mcp-client` — 50 с, у Codex 60 с на вызов), на таймауте `still-running`; и Hangar сам печатает родителю «[Hangar] sub-session "X" finished (done): … — hangar://task/…», когда его агент не работает, не ждёт, на экране нет «esc to interrupt», 5 с не было клавиш и нет черновика (символы без Enter/⌃C) — к черновику пользователя Hangar не дописывает никогда. Очередь в памяти: после перезапуска недоставленное теряется (`sessions_wait` видит статус). **Дополнение владельца (тот же день):** (1) подчат создаётся и вручную — «Новый подчат…» в меню строки чата и палитре, ⇧⌥⌘N для выбранного чата; лист: задача, агент, где работать (копия — только у локального чата проекта), куда итог; имя — первая строка задачи; (2) доставка на подчат (`HangarTask.subDelivery`, MCP `deliver: parent|notify`, CLI `--notify-only`): в терминал родителя (по умолчанию) или только уведомление пользователю — родителю ноль токенов; (3) итог компактный: `message` ≤ 1500 символов с пометкой « … [truncated; full output: tabs_read]» и `truncated: true`, плюс `tab` для `tabs_read`, ссылка с id; к заданию подчата Hangar дописывает просьбу закончить кратким итогом (что найдено/сделано, ключевые пути/ссылки, < 1500 символов); текст Stop / codex notify на границе доверия хранится до 2000 символов (прочие — 500). Результат: `status`, `id`, `name`, `link`, `agent`, `tab`, `message`, `truncated`.
