# Hangar — дизайн-система

Стиль A «Ghostty-native»: тёмный, плотный, без декора. Значения взяты из CSS эталонных макетов (`docs/superpowers/mockups/style-a-v2.html`, `new-task-v4.html`, `limits.html`). Размеры в макетах — px, в приложении — pt 1:1. Только тёмная тема в v1.

Терминал (цвета, шрифт, размер) берётся из конфига Ghostty пользователя. Хром UI должен с ним гармонировать; по умолчанию — токены ниже. Брать ли `panel` из фона темы Ghostty — открытый вопрос (`decisions.md`).

## Решения пользователя, из которых выросла раскладка
- Сайдбар главный: на всю высоту окна, светофор над ним.
- Вкладки — внутри области задачи, не сверху окна (`style-a-screens.html` с верхними вкладками устарел).
- Слева в полосе вкладок — название задачи и `⎇`.
- Лист новой задачи широкий (≥ 580), подписи в одну строку, настройки — одной карточкой.
- Агент по умолчанию claude; выбора агента в листе нет, другие — через `+` во вкладках.

## Типографика
- UI — системный шрифт (SF Pro). Базовый 12; строки в листе 12.5; поле названия задачи 14; заголовок листа 13.5 semibold; заголовок поповера 13 bold; название задачи в полосе вкладок 12 semibold.
- Вкладки, файлы, терминал-подобный текст 11.5; подписи сегмента 11; мелкое (заголовки проектов, строка состояния, проценты) 10.5; счётчики 10.
- Моно (`JetBrains Mono` → `SF Mono` → Menlo): пути, ветки, имена файлов в diff, номера строк, команды. В терминале — шрифт Ghostty.
- Капс + разрядка `.05–.06em` — только заголовки проектов в сайдбаре и секции выпадающего списка веток (`remote`/`local`). Больше нигде.

## Раскладка
- Окно: радиус 12, без отдельного тулбара. Сайдбар на всю высоту, сверху зона светофора 38.
- Сайдбар: ширина 200 (с блоком лимитов в макете — 230; см. открытые вопросы в `decisions.md`), фон `sidebar`, правая граница `line`.
- Полоса вкладок: высота 38, фон `bg`, нижняя граница `line`.
- Инспектор справа: ширина 220, фон `bg`, левая граница `line`.
- Строка состояния: высота 22, верхняя граница `line`, 10.5 `text3`, промежутки 14: `⎇ ветка` · `+N −M · K файлов` · справа статус агента.
- Сплиты: разделитель 1 pt `line`; у панели заголовок 10.5 `text3` с отступами 5/12.

## Отступы, радиусы, высоты
- Горизонтальный отступ строк сайдбара/инспектора 14; строка задачи 5 сверху/снизу (~26 высота), файла 3 (~22).
- Радиусы: окно/лист/поповер/тост 12, карточка 8, поле 7, кнопка 6–7, сегмент 6–7 (внутренний 4–5), выпадающий список 9, верх вкладки 6.
- Лист: внутренние отступы 18 по бокам; строки карточки 9×12, подпись фиксированной ширины 110.
- Тени: лист `0 24 60 rgba(0,0,0,.55)`, поповер/выпадающий `0 18–22 40–50 rgba(0,0,0,.55–.6)`.

## Компоненты
- **Сайдбар.** Заголовок проекта (капс, 10.5, `text3`, справа `+`). Строка задачи: точка статуса, имя, справа `⎇` (worktree) или счётчик 10 `text3`. Выбранная — `selection`. Внизу: блок лимитов, затем `+ проект` и `⌘K` (11, `text3`, граница сверху).
- **Полоса вкладок.** `Название задачи ⎇`, затем вкладки: 11.5, отступы 6×14, точка статуса, `×` с прозрачностью .4. Активная — фон `panel`, текст `textStrong`. Временная diff-вкладка — курсив, префикс `±`. В конце `+` (меню Claude, Codex, Helix, Shell).
- **Сегмент** (`Files` / `Changes N`): фон `panel`, padding 2, активный — `control` + `textStrong`.
- **Дерево файлов.** Строка 11.5, справа бейдж M/A/D. Стрелки `▾/▸`.
- **Diff.** Заголовок: путь (моно, `textStrong` 500) + `+N −M`. Колонка номеров 34, `text3`, выравнивание вправо. Строка 11.5, межстрочный 1.6. Под списком Changes — подсказка про базовую ветку и `⌥B`.
- **Лист новой задачи** (ширина 580): заголовок «Новая задача» + имя проекта `text3`; поле названия с фокусом; одна карточка строк «подпись → значение» (Worktree — переключатель + подсказка; От ветки — пикер `⎇ origin/main ▾` + «обновлено N мин назад»; Новая ветка — из названия, редактируемая); поле «Первое сообщение для claude (необязательно)…»; футер: слева подсказка (`esc — отмена` / `текущая ветка: main`), справа «Отмена» и «Создать ⌘↩». Без worktree строки веток — прозрачность .38.
- **Переключатель:** 30×18, ручка 14 белая; вкл `primary`, выкл `#444852`.
- **Пикер веток:** поле поиска; секции `remote` (первой, `origin/HEAD` помечен «по умолчанию»), `local`; справа у пункта метка 11 `text3` (возраст, «задача»). Ширина 340.
- **Блок лимитов:** строка на агента: имя (46, 11, `text2`), две полоски 4 (сессия, неделя), максимальный процент (10.5). Наведение — фон `#26282e`. Нет данных — строки нет.
- **Поповер лимитов** (330): план + «обновлено N мин»; на каждое окно — название, бейдж (почти/исчерпан), процент, полоска 6, «сброс через … · время». Разделитель между агентами. Футер: `⌘⇧L` и `↻ обновить`.
- **Уведомление/тост** (290, фон `rgba(50,52,60,.96)`, рамка `controlBorderStrong`): иконка 30, «claude ждёт ответа», `проект › задача`, текст последнего сообщения. В приложении — системное уведомление macOS; тост — только как вид в макете.
- **Кнопки:** обычная `control`/`#363941`, основная `primary` с белым текстом; padding 5×14.

## Состояния
- Выбор — `selection`; фокус поля — рамка `accent` + кольцо; неактивное — прозрачность .38; наведение — чуть светлее фона (`#26282e` на `sidebar`).
- Пустые и «нет данных»: не показывать элемент, а не рисовать пустую рамку.

## Правила
- Нет капса, кроме заголовков проектов в сайдбаре (и секций пикера веток).
- В листах нет переносов подписей: `white-space: nowrap`, лист ≥ 580.
- Настройки в листе — одна карточка строк, а не набор полей с подписями сверху.
- Цвет статуса — только точкой (и ореолом для waiting), не заливкой строки.
- Никаких сторонних UI-китов: системные контролы, перекрашенные под токены.

## Перенос в SwiftUI
Один `enum Theme` (без экземпляров) с вложенными пространствами: `Theme.Color` (токены выше как `Color`/`NSColor`), `Theme.Status` (функция `color(for: AgentState)`), `Theme.Limit` (`color(forPercent:)` с порогами 80/95), `Theme.Font` (`ui`, `uiSmall`, `mono`…), `Theme.Metric` (ширины сайдбара/инспектора, высоты полосы вкладок/строки состояния, радиусы). Пороги 80/95 — константы в одном месте, их же использует логика уведомлений. Литералы цветов и размеров во view запрещены.
