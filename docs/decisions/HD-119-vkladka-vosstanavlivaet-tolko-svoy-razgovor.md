# HD-119 — 2026-10-30 — Вкладка восстанавливает только свой разговор (баг: после перезапуска в чате открылся чужой недавний разговор; меняет #41, #62, #89).

Причина: у владельца hooks Hangar не установлены (интеграция не подключена), id разговора вкладки не было, восстановление шло через `claude --continue`, а он берёт последний разговор папки — другой вкладки, терминала VS Code, `claude -p`; с hooks такой id ещё и закреплялся. Теперь:
- восстановление только по своему id: `--continue`, `codex resume --last` и «слот продолжения» (`resumeSet`) убраны; без id агент стартует заново;
- новый claude-разговор рождается с id: `claude --session-id <uuid>`, id пишется в состояние сразу (без `perform`: запуск может идти из его синка); восстановление решается до запуска по транскрипту `<конфиг claude>/projects/*/<uuid>.jsonl` (id уникальны), его папка — первый `cwd` среди первых строк, разобранный как JSON (экранированные пути сравниваются верно; `cwd` нет — эта папка): записан в этой папке — `--resume`; транскрипта нет (в чате ничего не сказали) — `--session-id` с тем же uuid; записан в другой папке (claude его отсюда не найдёт, и так каждый раз) — новый разговор под новым id и строка «откройте из Истории». На этом Mac выбирает Hangar сам (`transcriptChoice`, конфиг — `CLAUDE_CONFIG_DIR` login-shell, прочитанный при запуске, иначе `~/.claude`): новый id сразу в состоянии, строка — в панели вкладки, claude запускается как обычно в login-shell (alias/функции работают). На сервере выбор в `sh -c` (POSIX и под fish): JSON читает `python3`, если он есть (иначе — эта папка), claude — через `"${SHELL:-/bin/sh}" -l -i -c`, строка печатается в терминал, запасной id сохраняет `SessionStart` агента вкладки. Устаревший `hangar-remote` обновляется при подключении до запуска вкладок хоста; если на хосте всё ещё версия < 6 (без pid), id берётся по-старому — первый `SessionStart` после запуска и переключения, — иначе строка и новый чат повторялись бы при каждом восстановлении. Поэтому выход возобновлённого чата с ошибкой не запускает второй старт, а ↩ после любого выхода claude возобновляет тот же id (свежий старт после провала — только у codex); вкладка, сохранённая без id (до #119), стартует заново со строкой «Прежний разговор не был привязан — откройте его из Истории»;
- каждому claude-листу (локально и на сервере) Hangar при запуске передаёт свои hooks `SessionStart` и `UserPromptSubmit` через `--settings '<json>'` — независимо от интеграции, без записи в файлы пользователя; команда — `h=<hangar | "$HOME/.hangar/bin/hangar-remote">; [ -x "$h" ] && "$h" event <kind> --agent-pid "$PPID"; exit 0` (нет CLI — тихо ничего), JSON собирается `JSONSerialization` и целиком кавычится;
- `--tab-agent --agent-pid` (`$PPID` оболочки hook = процесс claude вкладки) есть только у этих hooks, вложенный `claude -p` их не получает. Сохранённый id меняется только от них (первый pid после запуска — агент вкладки; другой pid — как вложенный, кроме `SessionStart` с `--tab-agent` от /clear, compact, /resume или с id листа: при `CLAUDE_CODE_SHELL_PREFIX` у каждого hook свой pid обёртки, и после /clear id не должен замёрзнуть; `startup` с другим id — никогда: claude передаёт `--settings` своим фоновым сессиям, а те наследуют HANGAR_* вкладки); так ловятся `/resume`, `/clear`, compact, `fork` (раньше `fork` не принимался) и потерянный `SessionStart` (следующий prompt с новым id). Эти события только отслеживают разговор и не меняют статус: статус по-прежнему от установленных hooks, поэтому двойного счёта нет. Без pid (старый `hangar-remote`) — прежнее правило, но сохранённый id не трогается;
- `hangar-remote` 6 передаёт `agentPid`; codex: id только из `notify`, без id — новый разговор.
- Тесты и debug-запуски больше не пишут бэкапы statusline в настоящую папку состояния: сокет, `backups` и обновления у `AppState` по умолчанию лежат рядом с `StateStore.directory`.
