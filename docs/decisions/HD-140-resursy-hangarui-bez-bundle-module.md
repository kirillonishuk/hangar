# HD-140 — 2026-11-05 — Ресурсы HangarUI — только через `L10n.resources`, никогда `Bundle.module` (хотфикс 0.18.x; уточняет HD-038, HD-138).

0.18.0/0.18.1 закрывались при запуске: `AppState.hangarSkillText` (HD-138) читал `HangarSkill.md` через `Bundle.module`, а сгенерированный SwiftPM аксессор ищет `Hangar_HangarUI.bundle` рядом с `.app` и в путях сборщика CI и при неудаче делает `fatalError`; `bundle.sh` кладёт бандл в `Contents/Resources`. Теперь все ресурсы HangarUI ищутся одним `L10n.resources` (Contents/Resources → рядом с бинарём → в DEBUG рядом с тестами); нет файла — `nil`, а не падение. Защита: тест `sourcesNeverUseBundleModule` (в `Sources/` нет `Bundle.module` вне комментариев); `verify-bundle.sh` проверяет `HangarSkill.md` и строки ru/en в `Contents/Resources/Hangar_HangarUI.bundle` и что в бинаре нет аксессора SwiftPM («could not load resource bundle»). **Отвергнуто:** пробный запуск собранного .app в `verify-bundle.sh` — release-сборка игнорирует `HANGAR_STATE_DIR` и тронула бы настоящий `state.json`; класть бандл рядом с `.app` — вне подписанного бандла.
