# HD-058 — 2026-10-24 — Новый worktree сразу запускается: копия игнорируемых файлов и команда настройки.

У проекта `worktreeCopy` (пути/маски; nil = по умолчанию, `[]` = ничего) и `setupCommand` (nil или `""` = без команды; выполняется только сохранённая команда проекта). Умолчания — по lockfile, отслеживаемому в корне репозитория (`WorktreeDefaults`): `pnpm-lock.yaml` → `pnpm install --frozen-lockfile --prefer-offline`; `yarn.lock` → `yarn install --frozen-lockfile` (с `.yarnrc.yml`, berry — `--immutable`); `bun.lockb`/`bun.lock` → `bun install --frozen-lockfile`; у них список `.env*`, `.venv`, `vendor/bundle` без `node_modules` (менеджер ставит его из своего хранилища жёсткими ссылками — быстро и без лишнего места; 1,8 ГБ на worktree не копируем). `package-lock.json` или нет lockfile — список с `node_modules` (клон APFS, места не занимает), без команды. Оба поля правятся в настройках проекта; там для проекта без своих значений список подставляется (только найденное), а команда lockfile — лишь подсказка в пустом поле; сохранение без правки оставляет nil. Команда lockfile только предлагается (изменено 2026-10-24 после ревью: запускать `pnpm install` без согласия, тем более из CLI/MCP, нельзя): лист «Новая задача» показывает строку «После создания: `pnpm install …`» с переключателем — у проекта без сохранённой команды он выключен; включил и создал задачу — команда сохраняется в проект (это и есть согласие) и дальше включена по умолчанию; у сохранённой команды переключатель лишь пропускает её для этой задачи. CLI/MCP `tasks.create` выполняют только сохранённую команду, подсказку — никогда. Строка в листе есть всегда («—» без команды), чтобы чтение lockfile не сдвигало раскладку. После `worktree add` (лист «Новая задача» и CLI/MCP `tasks.create --worktree` — один путь, `NewTaskModel.create`) кандидаты берутся только из `git ls-files --others --ignored --exclude-standard --directory --full-name -- :/` — по всему репозиторию от корня, и для проекта в подпапке (`apps/saas`): копируется лишь то, что git игнорирует и что есть, в то же место от корня worktree (worktree — полный checkout). Маски как в gitignore: без `/` (или с `**/`) — по имени на любой глубине, кроме внутри `node_modules`, `.git`, `dist`, `.turbo`; с `/` — по пути (`apps/*/.env*`). `..`, абсолютные пути и всё вне списка git не копируются; симлинки копируются как есть и не разыменовываются (относительные ссылки pnpm в клоне ведут внутрь клона). Локально `cp -cpR` (клон APFS), при ошибке — `cp -pR`; на сервере через runner хоста `cp -a --reflink=auto`, затем `cp -a`; существующее место назначения пропускается; если путь назначения проходит через симлинк (базовая ветка может отслеживать симлинк-папку, ведущую куда угодно) или его папка после `mkdir -p` вне корня worktree (`pwd -P`) — копия отказывается и попадает в список ошибок. Прогресс — в подвале листа («Копирую node_modules…»). Ошибка копирования не отменяет worktree: строки `hangar: не скопировано …` и команда идут во вторую вкладку shell новой задачи — её cwd корень worktree, где lockfile (запускается сразу, скрыто; вкладка агента остаётся активной и открывается как обычно; после команды остаётся интерактивный shell; при восстановлении не повторяется). `tabs.open` с `prompt` для shell/editor промпт игнорирует (shell выполнил бы его как команду). Почему: пользователь (pnpm + turbo монорепо, вложенные `.env`) хочет, чтобы worktree был готов к запуску без гигабайтных копий. Отвергнуто: симлинки (общие `node_modules` ломаются при правке), копия вне проекта, обход файловой системы своим кодом (git уже знает игнорируемое и не заходит в игнорируемые папки), общая папка worktree в «Настройках» (пока не нужна: папка задаётся у проекта).
