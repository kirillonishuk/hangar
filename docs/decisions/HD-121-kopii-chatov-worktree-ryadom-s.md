# HD-121 — 2026-10-30 — Копии чатов (worktree) — рядом с проектом, не внутри (слово владельца).

Копии внутри проекта (`<проект>/.claude/worktrees/…` с `node_modules`, гигабайты) попадают под слежение файлов редакторов (VS Code) и тормозят их. Hangar сам такую папку не выбирал: по умолчанию всегда было `<родитель>/<папка>.worktrees/<ветка>`, автоопределения `.claude/worktrees` нет; папку внутри проекта пользователь мог ввести в «Где создавать копии» — лист лишь показывал серую подсказку. Теперь: (1) по умолчанию (новый проект и проект без своей папки) — `<родитель>/<папка>.worktrees/`, имена внутри прежние; проект в `/` — `/.worktrees` (рядом некуда). (2) Новую папку внутри проекта лист настроек не сохраняет: ошибка под карточкой «редакторы будут следить за копиями и тормозить» с путём рядом с проектом. «Внутри» — с `~`, симлинками (`realpath` существующей части пути) и без учёта регистра на нечувствительном к регистру томе (APFS по умолчанию); у проекта на сервере — путь как набран, с учётом регистра. (3) Уже сохранённая папка внутри проекта не ломается: копии в ней работают, а в настройках проекта — «Копии лежат внутри проекта — редакторы следят за ними и тормозят» и кнопка «Хранить рядом с проектом»: сразу сбрасывает папку на умолчание, только для новых копий. Существующие копии сами не переносятся и кнопки «Перенести» нет: у переноса (`git worktree move`) живые вкладки, агенты и tmux с cwd в старой папке, сохранённые пути в состоянии и сессиях агентов — небезопасно одним щелчком; вернуться, если владелец попросит.
