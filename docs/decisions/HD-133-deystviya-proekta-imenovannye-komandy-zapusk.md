# HD-133 — 2026-11-05 — Действия проекта: именованные команды, запуск одной кнопкой в папке чата (решение владельца; спека `specs/2026-11-05-project-actions-design.md`; дополняет #45, #58, #60, #127).

Действие — имя + команда + «Перезапускать» (по умолчанию вкл.). Задаются в настройках проекта (`state.json`) и в `.hangar/actions.json` в репозитории (только чтение в UI, свои с тем же именем важнее; битый файл — сообщение, не падение). Запуск: кнопка «▶ X | ⌄» в тулбаре справа от ветки (только когда действия есть: пустое не показывается, §3.19), ⌘R (keyCode 15, свободна), меню чата, палитра «Запустить: X», CLI `hangar actions list|run` / MCP `actions_list`, `actions_run` (список — только чтение; запуск не разрушителен, без `yes`; сессия по умолчанию — вызывающий чат). Выполняется в своей shell-вкладке (`Leaf.action`) тем же путём, что вкладка подготовки копии, с `HANGAR_PORT`; удалённый проект — ssh + tmux как прочие вкладки. Повтор с «Перезапускать»: ⌃C (SIGINT задаче переднего плана через терминал) → как только процесс вышел, новый терминал в той же вкладке; не вышел за 3 с — терминал закрывается (SIGHUP, у сервера — kill tmux-сессии) — это вместо SIGTERM: у Hangar нет pid процесса во вкладке (GhosttyKit его не отдаёт), а закрытие терминала одинаково работает локально и по ssh. Без «Перезапускать» — новая вкладка. Вкладка действия после выхода **не закрывается** (в отличие от #127): полоса «Завершено / Остановлено / Процесс завершён с кодом N · Enter — запустить снова»; ненулевой код — точка `failed`, как у прочих вкладок; ⌃C/SIGHUP/SIGTERM (130/129/143, без кода) и «Остановить» — не ошибка. Работающее действие точки «работает» не получает (dev-сервер не агент: не держит Mac бодрым и не красит чат). После перезапуска приложения вкладки действий возвращаются **без автозапуска** — «Не запущено · Enter — запустить снова» (удалённая подключается к живой tmux-сессии: это не новый запуск). Команда из файла репозитория перед первым запуском и после изменения текста показывает лист подтверждения; одобрение — SHA-256 текста в `approvedActions` проекта; CLI/MCP неодобренную команду не запускают (агент мог сам написать файл). Требования владельца того же дня: действия полностью редактируются (добавить, изменить, удалить, порядок «Выше»/«Ниже»); у действия необязательная рабочая папка относительно папки чата (`apps/cms`), проверяется перед каждым запуском в checkout этого чата; чужое (из файла) можно скрыть — `hiddenActions` проекта, файл не меняется; «+ Добавить действие» предлагает (не добавляет само) скрипты `package.json` корня и пакетов workspace (`pnpm-workspace.yaml` / `workspaces`) через менеджер по `packageManager`/lock-файлу, цели Makefile и рецепты justfile — поиск только при открытии, два запуска `sh` (локально или по ssh), группы по пакету с полем поиска. **Отвергнуто:** автозапуск при восстановлении (неожиданные процессы и порты); точка «работает» для действий; доверять файлу репозитория без вопроса; SIGTERM по pid (нет pid); кнопка ▶ у проекта без действий (пустой элемент); setup/teardown и варианты под платформу в том же файле (отдельная идея); фоновое сканирование репозитория ради подсказок; перетаскивание строк действий.
