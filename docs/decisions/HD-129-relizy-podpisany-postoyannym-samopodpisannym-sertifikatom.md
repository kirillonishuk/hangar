# HD-129 — 2026-11-04 — Релизы подписаны постоянным самоподписанным сертификатом «Hangar Self-Signed», а не ad-hoc (решение владельца; уточняет #86).

Причина: macOS (TCC) привязывает выданные разрешения (запись экрана, файлы и папки и т. д.) к designated requirement подписи; у ad-hoc-подписи он — хеш самого кода (`cdhash`), поэтому после каждого обновления разрешения сбрасывались. Apple Developer Program (Developer ID, нотаризация) не берём — платно и не нужно; самоподписанный сертификат бесплатен и даёт стабильный DR: `identifier "app.hangar.Hangar" and certificate root|leaf = H"<SHA-1 сертификата>"` (codesign формирует его сам, свой DR не задаём). Сертификат: CN «Hangar Self-Signed», SHA-1 `2BC32E9E59D0A3BB47BA27D3E2410F0A86F16768`, до 2046 г., недоверенный (`CSSMERR_TP_NOT_TRUSTED`) — codesign им подписывает, если связка в списке поиска пользователя; `security find-identity -p codesigning` показывает его только без `-v`. Менять сертификат нельзя: новый снова сбросит разрешения у всех. Метки времени нет (`--timestamp=none`: TSA Apple только для её сертификатов). `scripts/bundle.sh` подписывает помощник `hangar` и приложение идентичностью из `HANGAR_SIGN_IDENTITY` (имя или SHA-1, `-` — ad-hoc), иначе «Hangar Self-Signed» из связки, иначе ad-hoc с предупреждением — сборка у участников без сертификата работает. Release: шаг «Import signing certificate» (первым в задаче) берёт секреты `HANGAR_SIGN_P12` (base64 .p12) и `HANGAR_SIGN_P12_PASSWORD`, без них релиз падает (тихий ad-hoc-релиз сбросил бы разрешения всем); .p12 → временная связка в `$RUNNER_TEMP` со случайным паролем, `set-key-partition-list`, связка добавляется в список поиска с сохранением прежних, в конце (`if: always()`) удаляется. `scripts/verify-bundle.sh` с `HANGAR_VERIFY_SIGNED=1` (релиз: бандл и DMG) требует у приложения и помощника `Authority=Hangar Self-Signed` и `certificate root = H"2BC32E9E…"` (сверка SHA-1 закрепляет сертификат); CI на PR (в т. ч. из форков, секретов там нет) подписывает ad-hoc явно (`HANGAR_SIGN_IDENTITY=-`). Не нотаризовано, поэтому первый запуск по-прежнему через «правый клик → Открыть» или `xattr`. Переход: первое обновление с ad-hoc-сборки на подписанную спросит разрешения ещё один, последний раз (DR сменился); дальше разрешения переживают обновления. `codesign --verify` в обновлении (#86) проходит без сертификата в связке (проверено). Не сделано: закрепить DR нового приложения в `Updater.verifySignature` (`-R`) — отдельной задачей. Проверка: одноразовый самоподписанный сертификат «Hangar Self-Signed» во временной связке в /tmp; шаги release.yml извлечены из YAML и запущены как есть: без секретов — код 1 и связки нет; импорт → `HANGAR_SIGN_IDENTITY`=SHA-1, связка первой в списке, прежние на месте; `bundle.sh` с переменной и с автопоиском → `Authority=Hangar Self-Signed`, DR одинаковый в двух сборках; `verify-bundle.sh` подписанный режим — OK, с настоящим SHA-1 — отказ; шаг удаления — связки нет, список поиска совпал с исходным побайтно; подписанный бандл проходит `codesign --verify --deep --strict` и подписанный режим уже без связки; без сертификата `bundle.sh` предупреждает и подписывает ad-hoc, подписанный режим его отвергает.
